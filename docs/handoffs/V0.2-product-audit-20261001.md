**同日接续更新：** 负责人明确将全局 Token 预算及最终免费模型选择留待后续，授权推进其余收尾。P1-B 已按 ADR-019 实现并通过两 Runtime、API、恢复和历史兼容测试；P2 的历史读取文案、历史看板折叠与 MCP 专注回放已落地。最终验证与学习交接见 current-state 顶部及 `docs/learning/V0.2-product-closeout-20261001.md`。以下保留实现前的审查证据；全局 Token 预算、模型入口收口、UI 全矩阵与现场签收仍未完成，不能整版签收。

## 验收判断

V0.2 的主要工程链路已经形成：独立 Handwritten/LangGraph 调度、成对实验、Job 控制、安全点恢复、固定回归、BFCL 改编子集、Trace/动画与兼容历史看板均有实现和测试证据。当前可以开展受控课程演示。

**尚不能按需求 V0.6 完整签收；并非只差现场签字。** 本轮从需求反查源码，发现此前验收矩阵未覆盖的两项预算缺口：FR-08 的跨 Episode 全局 Token 预算，以及 §13.3 的 Episode 总执行时限。另有模型目录/默认选择与本机 Key 实际调用结果不一致，影响真实模型演示。

## 发布前收尾项

### P1-A：补跨 Episode 全局 Token 预算

需求 FR-08 明确列出“全局 Token 预算”。现有 `CreateExperimentRequest.token_budget` 经 `EpisodeService._with_token_budget` 和 `_agent_with_token_budget` 分别覆盖每个 Task/Agent；`run_experiment` 只累计参考金额，没有跨 Episode Token 准入检查。对照页却标为“总 Token 预算（输入 + 输出）”。

本轮离线复现：`provider=fake`、`scenario=success`、`order-status-001`、`repeat_count=2`、`token_budget=200`，Experiment `1c06b074-86c7-4aaa-af40-3251e1280ef8` 完成 2 对/4 Episode，全部成功，累计 **480 tokens**。每个 Episode 为 120 tokens，均低于 200；这证明当前字段是单 Episode 预算，不是整场 200。产物位于本机忽略目录，复现脚本为 `artifacts/diagnostics/audit_v02_global_token_budget.py`。

建议先走 ADR：保留旧字段的单 Episode 含义与历史哈希，增加独立全局预算；明确已完成用量、未完成安全点用量、未知 usage、在途超额和预算耗尽后的部分 Pair/Job 展示。不能只改标签便宣称需求完成，也不能静默把旧字段重释为全局。

验收：低全局预算停止后续 Episode；两种 Runtime 均适用；恢复不把累计用量归零，不重复累计已完成侧；保留部分结果和明确预算原因；旧产物兼容、看板分母不将未运行题算作失败。

### P1-B：补 Episode 总执行时限

需求 §13.3 列出 `Max Execution Time`。`packages/domain/models.py` 的 `Budget` 仍声明“time limits are deliberately deferred”，没有执行时限字段；共同 `EpisodeSession` 记录耗时但没有总时限检查。AIHubMix 单请求 30 秒与 MCP 单读取 5 秒是局部网络超时，不能替代整条 Episode 的运行时限。ADR-002 只将该功能排除在 M0，没有批准长期延期到 V0.2 之外。

建议先走 ADR：确定可配置时限、单调时钟核算、暂停时间是否计入、恢复累计规则、在途请求与实际上游用量边界、终止码及 Trace。实现放在共同 Session/应用编排，不分别复制到两个 Runtime。

验收：使用可控慢 Provider/工具，不访问真实模型；Reference/LangGraph 超时后不启动后续行动，有唯一终止事件与安全产物；恢复不能重置已用运行时间；失败和取消不会被显示成正常完成。

### P1-C：真实模型入口与近期验证结果一致

本机实机页面默认选中 `xiaomi-mimo-v2.6-pro-free`，并默认勾选 12 道原生任务，即 24 Episode。该模型在此前本轮新 Key 测试中两次 429；GLM 5.3 则完成 BFCL/ToolLab 双任务。页面仍显示 2026-09-23 的模型说明。

`EpisodeService._get_live_model_ids` 与 `_require_live_model` 把公共 `/v1/models` 当作 Key 范围；此前无效 Key 也获得该目录的 200，因此“目录可见”不能证明当前 Key 获得调用权限或当前通道可用。配置文件旧默认仍是 MiniMax M2.7；当前公共目录过滤后页面回落为 MiMo，配置与运行时默认不同。新增 Flash 有最小工具调用证据，但尚无项目完整任务验收。

负责人更换免费模型后再收口：统一配置默认与页面默认；区分“候选/目录可见/近期真实验证/本次失败”，验证记录带日期，不自动轮换模型；只对最终选定型号跑有限 BFCL/ToolLab 与 MCP 小样本，表外原厂价格保持未知。默认课程入口可优先提供明确标记的 Fake 小样本，真实批量由操作者选择。

验收：默认入口能完成一次演示；401/429/无通道有准确安全提示；Key 替换或服务重启后不存在旧可用性保证；模型/参考价映射变化按 ADR-017 处理，不猜新型号价格。

### P2：统一现场验收证据与文案

将本轮发现补进整版矩阵；用一个当前状态表承载未完成项，历史记录保留时间标签。部分 9 月 30 日真实产物/截图不在这台机器，不能用不可回读 ID 作现场入口。README、模型说明及课程演示文档存在历史默认/旧 Key 描述，应在模型确定后同步。

本轮浏览器还观察到：历史 GET 读取期间，主运行按钮显示“正在串行执行成对评测…”，附近状态则显示“正在读取历史对照实验”。建议分开历史读取与执行状态，避免操作者误以为正在重新消耗模型额度；其后 404 有明确提示。

完成 UI 规范 §13 的证据清单后，由负责人观看 Fake 恢复对照、Runtime 对照、MCP 动画、失败与恢复、预算停止和导出；同时沿学习文档解释调用链和边界，再记录签收结论与日期。

## 优化潜力（不增加当前版本硬性需求）

1. **首屏任务优先**：当前桌面首屏被介绍、UUID 栏和完整历史看板占据，运行配置和当前实验结论在更下方。将历史看板折叠/移为次级入口，加载结果时先露出本次结论，降低找按钮和结果的成本。
2. **MCP 演示更聚焦画面**：提供现有动画区域的专注查看方式，保留输入、当前工具/返回摘要、最终输出；大段技术 Trace 按需展开。仍以已记录事件为事实，不能把动画扩写成未记录的协议握手或抓包。
3. **配置组更易辨认**：历史筛选存在多个名称近似的配置组；补 Seed/Repeat/预算等可理解摘要与固定配置差异。当前比较键正确隔离，并不等于操作者能够迅速选中要看的组。
4. **真实实验结论更扎实**：最终模型确定后，用有限重复、固定任务覆盖四类能力，给出成功分母和失败分布。不要从单题成功、Fake 回归或一次差值推出某策略/Runtime普遍更优。
5. **新电脑更快复现**：说明固定 BFCL 缓存导入、服务就绪检查和离线演示入口；有需要时设计脱敏演示产物的导出/迁移方式。无需为此提前引入数据库或分布式队列。
