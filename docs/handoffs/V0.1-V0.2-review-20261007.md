# V0.1 / V0.2 需求复核与可视化优化分析

日期：2026-10-07；代码基线：`4581ffb`。依据：唯一需求 `docs/product/requirements.md` V0.6、UI 规范 1.3、Accepted ADR-002/010–024。

本次是需求、源码与当前页面的分析，不是整版签收或新功能授权。没有新真实模型调用；历史真实结果不证明今天的通道可用。业务源码、模型目录、评分和契约未修改。

## 1. 总体判断

系统已具备受控 Agent 实验平台的完整主链路，课程演示基础成立：任务与配置 → 两种 Runtime → 严格工具执行 → 独立评分 → 产物保存 → 回放与对照 → 恢复与回归。

不能称为“完美”或 V0.2 全量完成。最明确的功能缺口仍是跨 Episode 全局 Token 预算；真实模型目录与默认值没有完成最终收口，依赖审计现在存在高危告警；实机辅助功能、第二电脑、远端 CI、课程现场和版本签收仍有待验项。

可视化已有暖色主题、连续切换、结构化过程概览、React Flow、MCP 网络链路、BFCL 调用提议和实时 Episode Trace。下一轮收益主要来自把实验问题、调用参数、证据变化与两侧差异组织在一起。

### 仍需收尾的事项

1. **全局 Token 预算：功能缺口。** 保留旧字段/哈希含义，新全局预算先 ADR；处理完成侧、未完成安全点、未知 usage、恢复累计与部分 Pair。不以改标签替代实现。
2. **最终真实模型入口：运行风险。** 当前默认仍 MiniMax M2.7，说明中已明确新 Key 未包含此型号；GLM 5.3 有 10 月 1 日双任务证据但无今日验证。候选可见、历史成功、本次实际可调用应区分；免费网关不能承诺持续可用。课程入口优先明确 Fake 预设，真实选择由操作者确认。
3. **依赖告警：当前质量缺口。** 10 月 7 日 `npm audit --json` 返回 1 high，间接依赖 source-map-js。官方公告列受影响范围 `<1.2.2`，修复版本 `1.2.2`。先定位父依赖与锁文件内升级，再做类型/构建/单元/audit；不使用 force 进行无关大升级。本次未改依赖，也未证明应用当前路径可被利用。[官方公告](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)
4. **交付实测：证据缺口。** 第二机器安装与缓存导入、真实缩放/系统辅助功能、当前 GitHub CI、课程现场与正式短视频需要可复现记录。
5. **文档准确性：维护项。** §16 仍列 SQLAlchemy/SQLite、Router/Query/Tailwind 等原始技术基线，当前为 JSON 原子产物、原生 URL/fetch/CSS 和 React Flow。ADR-002 先延期数据库，AGENTS 明确不擅自引入数据库；后续应明确当前技术选型与原规划关系，不为凑技术栈增加依赖。项目包版本仍 0.1.0，与阶段号需解释，不表示 V0.2 自动未实现。
6. **性能目标：待证实。** 本次没有找到或运行排除模型等待的单步调度 <100ms 专项测量，不宣称达标或不达标；有正式性能声明时再补最小可重复基准。

## 5. 当前可视化的实际观察

### 已经值得保留

- 历史配置与下次草稿明确分开；历史真实模型 ID 不被当前选择覆盖。
- 单次结果已压缩成四项核心指标，费用/版本展开；失败原因保留，来源区分准确。
- MCP 页确有平台 Client → Streamable HTTP → 独立 Server，并根据保存的调用阶段改变状态；不用再从零制作 MCP 可视化。
- BFCL 页确有函数名、参数和调用提议，未伪装成上游函数计算结果。
- 过程概览已经结构化呈现观察、参数、反馈、环境变化；技术 Trace 保留原始审查能力。
- 390px BFCL 本次抽查没有页面横向溢出；不能据此替代所有模式、真实缩放或辅助功能签收。

### 优化空间

1. **对照结论需要主动寻找。** 当前历史对照页面先显示目录提示、ID/导出/历史，再进入左右配置与聚合面板。聚合面板又先列完整配置，结果卡与成对表在后。读取历史后应优先显示该实验的问题、样本分母、主要结果和差值；完整条件展开，下次草稿折叠但保留入口。
2. **对照配置仍比单次配置密集。** 左窄栏包含轴、Runtime、模型、12 条长任务复选框、预算与最近 UUID。复用已有任务选择与分组方式，显示选中数量/简短摘要，任务选择按需展开；先保留草稿与历史隔离，再缩短页面。
3. **图中可见的是组件，关键数据在别处。** 工具节点主要显示名称和 ID；要理解 query_records 查询了谁、搜索返回哪条文档、为什么重试，还要切概览或打开 JSON。增加当前帧的结构化参数、结果摘要、错误字段与证据差异侧栏，复用概览已有字段映射，不另造评分或业务推理。
4. **三种视图没有共享当前位置。** `App.tsx` 切概览/技术视图主动把 replayIndex 置 0；流程组件的 index 是内部状态，离开后卸载。观众切换视图核对同一错误时容易失去位置。统一锚到 event_id/step；一 Step 有多个阶段时保留阶段事件，不靠数组下标强行对应。
5. **等待模型的状态在动画里不够具体。** `flowFrames` 当前不映射 MODEL_REQUESTED/MODEL_RESPONDED；实时文字只说明接收 Trace，画面可能仍停在观察或上轮返回。将已记录的请求/响应加入阶段，显示“等待模型响应/已返回”；用量与耗时仅取保存字段，不展示隐藏思维或假进度。
6. **画布与控制条占用较长纵向空间。** 普通画布固定 470px；MCP 链路、输入和播放器另占高度，1440×900 下靠页内跳转仍难同时看到完整图、控制和结果。已有专注查看应保留，普通模式根据剩余视口合理压缩高度，并把当前参数/反馈靠近图。不是缩小所有字号。
7. **两侧 Trace 分别打开，差异不好讲。** 本次从成对表进入 Recovery 后转到 Episode 页；另一侧需返回再打开。优先增加同一 Pair 的并列步骤摘要与首次可观察差异入口，而不是第一步就做两套同步动画。
8. **动画阅读节奏容易被误当实际时延。** 1400ms/帧是播放器固定间隔，不是模型/网络耗时。补可见“按阶段播放，非实际耗时”，旁边呈现已保存的 duration。时间戳差值只能命名事件间隔；MCP工具总耗时不能拆成 RTT、握手或网络/服务端时延。
9. **英文原题可继续改善。** 任务选择已有中文说明，本次旧 BFCL 回放仍显示英文 question。可并列中文展示说明与折叠原题；模型输入、评分与历史原文保持原值，缺译文明确降级，不在页面悄悄调用翻译模型。
10. **演示入口缺少明确实验问题。** 目前操作者需要自己选任务和场景。可提供“参数错误如何恢复”“两个 Runtime 同条件执行”“MCP 只读工具跨进程调用”三种预设。预设只填草稿；另设读取已保存案例的只读入口，不能点击预设就自动消费真实模型。

## 6. 可行性与最小实施顺序

下面的成本是相对实现复杂度，不是工期承诺。全部建议仍待选定实施范围；核心契约变化先 ADR。

| 优先级 | 建议 | 复杂度 / 数据来源 | 需要后端变化吗 | 最小验证 |
| --- | --- | --- | --- | --- |
| P0 | 依赖告警、模型默认与演示预设 | 小到中；目录/锁文件/既有表单 | 模型验证记录是否持久化需另定 | audit、构建与单题真实探针；Fake/真实标识 |
| P1 | 历史对照结果优先、草稿收拢 | 小；现有 Experiment/指标 | 否 | GET 不 POST、草稿不被历史覆盖、四视口/键盘 |
| P1 | 当前帧参数/反馈/证据摘要 | 中；已有 Trace、概览映射与快照 | 通常否 | 缺字段、长结果、非法参数、MCP 断线、BFCL 提议 |
| P1 | 共享回放位置与请求/响应阶段 | 中；event_id、step_index、公开事件 | 否 | 切视图回同事件、多调用、失败终止、实时与历史、reduce |
| P1 | Pair 两侧步骤并列与差异定位 | 中；Pair 两个 Episode GET | 否 | 两侧不同步数、缺一侧/旧产物、参数纠错标签来源正确 |
| P2 | 画布/控制区与中文原题层级 | 小；现有 CSS 与展示映射 | 否 | 390/768/1280/1440、200%、长 ID、全屏退出焦点 |
| P2 | 模型/工具耗时与累计 Token 小条图 | 中；已记录 duration/usage | 通常否 | 缺耗时不补零，Fake明确，不用像素长度代替数值 |
| 收尾独立任务 | 全局 Token 与恢复累计 | 中到大；涉及计划、预算、Job、部分 Pair | 是，先 ADR | 低预算、未知 usage、跨进程恢复、不重复累计、旧哈希 |

建议先做“结论优先 + 帧摘要 + 共享位置”这一组小闭环。现有 React Flow、CSS、原生 details、事件映射和 Episode GET 足够支撑，无需新 UI 框架、动画库、数据库或布局引擎。

更完整的双侧同步图、Experiment 逐事件直播、MCP 抓包/协议测量、通用长任务和任意数据集属于后续独立任务。尤其协议级演示必须先采集事实并固定事件契约，不能在现有图上补虚构报文。V0.3 上下文首切片已授权，但本轮不将窗口字节诊断变成新 V0.2 验收项。

## 7. 面向课程的演示组织

一条可讲清楚的路线：**任务目标 → 模型发起工具调用 → 参数校验失败 → Recovery 修正一次 → 获得真实工具证据 → 提交 → 评分器判定 → 成对成功/代价差值**。

随后用只读 MCP 文档例子展示进程边界，再用同条件 Runtime 对照说明框架替换仍经过相同工具与评分链路。预设和保存案例负责稳定呈现；现场真实请求负责证明当前联网闭环，两类来源始终显式区分。

成功演示的检验方式：观众能指出任务、错误发生的步骤、具体修正内容、取得的证据、独立评分及额外 Token/耗时。无需用更多菜单或装饰节点证明技术工作量。
