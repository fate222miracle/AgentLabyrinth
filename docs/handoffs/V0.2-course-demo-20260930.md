现场建议先讲 Fake 恢复对照，再打开 MCP 流程动画，最后展示暂停 Job。流程动画是**已保存 Trace 的回放**；它没有记录 MCP 握手或 `tools/list` 原始报文，也不应被讲成协议抓包。页面中的“实时轨迹”只用于真实正在运行的 Episode，断线时保持未知状态，不虚构进度。真实模型小样本的历史证据见 [整版验收记录](V0.2-acceptance-review-20260930.md)，本次没有新的真实调用；当前模型目录因本机 Key 不可确认而隐藏真实模型。

若需要重新演示暂停/取消，先停止自己启动的普通 API，在仓库根目录运行：

```powershell
uv --cache-dir .uv-cache run python -m scripts.demo_delayed_fake_api --delay-seconds 0.5
```

Web 中选择 Fake、一个任务、每 Seed 多次重复，启动 Job 后立即点“暂停”或“取消”。此脚本仅给 Fake 模型调用增加 0.5 秒等待，以便手动操作；控制仍使用正式 API 逻辑。演示完停止该临时 API，再按 README 启动普通 API；此前暂停、完成和取消状态应保持。不要用该延时数据推断正常运行耗时或真实模型吞吐。

交付脚本已按上述命令实际启动；`GET /api/v1/meta` 为 200，暂停 Job 回读仍为 `paused`。随后已停止脚本并恢复普通 API。
