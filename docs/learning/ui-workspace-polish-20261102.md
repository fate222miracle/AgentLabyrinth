## 问题与实现

实际查看任务库、工作台和实验中心后，确认任务列表描述较长、详情插入整页顶部、准备态固定32rem且重复等待说明、模型目录提示占用只读浏览页面，以及实验看板被ID/恢复工具推后。先向负责人说明诊断，再实施。

- `TaskLibrary.tsx`：紧凑摘要列表，桌面右侧完整任务详情；1023px及以下顺序堆叠，低高度取消sticky。不删减完整目标、交付要求或英文ID；来源、步数和MCP能力取自实际meta，不推导模型能力。两行摘要有可达的完整详情。
- 查看后焦点进入详情标题，关闭后在布局完成的下一帧返回原按钮；切换查询/来源收起旧预览。筛选空态可清除，加载占位与失败明确分开；失败数量显示“目录未载入”，不用0或永久加载冒充未知。所有浏览/筛选/预览零POST，配置入口只填写草稿。
- `App.tsx`与`index.css`：准备舞台取消固定最小高度和两张等待卡，仅保留实际任务目标、尚未开始说明及真实事件到达后的呈现约定。未改运行后实时流、资料与输出。
- 模型目录可用性提示仅在单次/新实验配置及真实Judge视图出现；整个meta读取失败仍全局提示并允许原重读，不能为了简洁隐藏不可用原因。只读历史和任务浏览不再重复提示目录Key权限。
- 实验中心正常状态先看板、后ID查找/历史恢复工具；已有activeJobId时原控制前置。没有删除暂停/取消/恢复、保存进度或原历史入口，未改评分、CSV、预算或历史来源。

设计沿用redesign-existing-projects、design-taste-frontend的app-screen分层与已选方向，保留狐狸/Geist/暖色；ui-ux-pro-max本地焦点查询返回可见焦点及焦点不被遮挡的建议，没有把AAA增强条款称为AA认证。复用现有content-enter动效与减少动效规则，不引入组件库、弹窗系统或独立滚动容器。浏览器目视与测量使用现有CUA和项目回归，不运行技能内另起浏览器的inspect脚本，不声称自动设计评分。
