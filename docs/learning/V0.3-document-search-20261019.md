# V0.3 文档ID检索：源码阅读与交接

范围：[ADR-034](../adr/ADR-034-document-id-search.md)，仅修正已经观察到的检索交互问题。原始需求仍为V0.6，本周整版安排见[周计划](../tasks/V0.3-week-plan-20261019.md)。本地保留，不自动提交GitHub。

## 问题与具体变化

上一轮真实运行搜索`INSPECTION`，返回了引用它的登记/政策，却遗漏验收文档本身：旧工具只匹配标题和正文，该文件的中文标题/正文没有自己的英文ID。这不是额度错误，也不能证明记忆丢失。新规则先对去除首尾空白的查询精确匹配ID（不区分大小写），命中则只返回对应ID/标题；否则继续按整段字面子串匹配标题/正文。不是语义检索，不做组合关键词、翻译或同义扩展。

新结果记录`search_mode`，空搜索额外记录固定建议。建议只解释公开规则，不提供正确答案、私有目标、正文或未读证据。模型已经从成功阅读正文取得的引用可以直接读取；搜索、观察者资料预览均不取得阅读证据。

## 阅读顺序与调用链

1. `apps/api/schemas.py`：新Episode请求1.5 / Experiment请求1.8，仍显式声明single/serial；旧请求1.4/1.7行为保持，默认旧CLI也不自动升级。
2. `apps/api/service.py`：`_with_document_search`只为新文档任务派生`+id-search-v1`与来源元数据；与批次后缀组合为`+id-search-v1.serial-v1`。**Experiment必须先派生任务，再调用`_task_tool_version`选择工具集**，否则计划虽有新标签仍误用旧工具。本轮定向测试已捕获并修复此顺序问题。
3. `packages/environments/tool_lab/environment.py`：ToolSet v1.5.0只升级搜索说明/Schema至1.1.0，read/submit沿v1.4参数与派生答案说明；搜索仍经Registry → Validator → Executor → `search_document_catalog`，query非空、top_k整数1–10，不接受模型自行传协议。
4. `packages/environments/tool_lab/mcp.py`：同一共享函数；新客户端内部附`search_protocol=id-first-literal-v1`，旧客户端不附字段，服务器默认旧literal-v1。未知协议或旧服务器不支持时明确失败，不静默降级。只读HTTP绑定localhost，任务集仍固定，不接任意数据源。
5. `scripts/run_regression.py`：由原请求版本重建相同派生任务/工具版本；旧固定清单保持旧哈希与字面返回，新清单不能混用旧v1.4。
6. `apps/web/src/App.tsx`发新请求；`traceSteps.toolFeedbackFields`只从当时实际成功事件选取匹配方式/建议，`ReadableFields`翻译标签。实时节点/回放/资料区复用现有界面，无新增配置选项。旧记录缺字段就不补字段。

## 状态、恢复与失败

- 搜索仅返回ID/标题，不更改`acquired_evidence`；实际成功`read_document`才取得证据。提交保存的主张仍须独立Evaluator核验，不因填入证据字符串就通过。
- 完整Trace记录真实搜索返回；窗口/记忆仅投影Provider输入，原历史不裁剪。新旧安全点都沿保存ToolSet重建，不能由当前网页草稿或最新版本解释旧实验。
- 只读批次的整批校验、逐工具预算、一次参数纠错、剩余队列恢复不变。新增搜索提示不产生额外模型/工具调用。
- 无匹配是成功返回的空列表，不伪装工具错误；非法参数/协议或MCP断线仍按既有失败边界终止，不改为自动重试。
- BFCL的函数提议评分未改，源任务JSON与目标均不改。新旧搜索版本、不同任务变体不能混为同一配置的趋势或消融结果。
