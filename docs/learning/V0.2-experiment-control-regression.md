## 调用链与状态

Web 启动 Experiment 时 `POST /api/v1/experiments/jobs`，以响应中的 ID 写 `?experiment_job_id=`。API 先原子写 `queued` 状态，再用单进程 semaphore 把并行 Job 限在两个；每个 Job 仍调用原有 `EpisodeService.execute_experiment → run_experiment → run_checkpointed_episode` 串行执行 Baseline/Recovery。`run_experiment` 先写不可变计划，每一侧开始前读取 Job 控制请求。已完成 Episode Artifact 是进度账本。完成后原子写 Experiment Artifact，清除计划，Job 写 `completed`；Web GET 结果并把 URL 换为 `experiment_id`，之后刷新只读。

运行中 `POST /jobs/{id}/pause|cancel` 只记录请求。下一 Episode 边界抛出 `ExperimentJobStopped`：`paused` 保留计划和已完成侧，`cancelled` 也保留它们用于审计但不能隐式恢复。`GET /jobs/resumable` 可在刷新或重启后发现未完成 Job；旧 Experiment 恢复入口拒绝 Job，避免绕过状态。`POST /jobs/{id}/resume` 在原 ID 上重建 Provider/Runtime，并调用原 `run_experiment`；已完成侧直接读 Artifact，未完成 Episode 从安全点恢复，未开始侧继续执行。API 进程意外退出后，持久状态仍是 `running`，当前进程没有活跃任务时 GET 报 `interrupted`；须显式恢复。**暂停/取消不打断进行中的模型请求或工具调用**，请求中途退出仍可能重发上游调用。Job 文件只适合单 API 进程；多 worker 要共享队列与锁。

失败 Episode 重跑走 `POST /episodes/{id}/rerun`：先读取最终 Artifact，只接受 `evaluation.success=false`；Fake 场景从单次输入记录或父 Experiment 产物取得，真实模型按保存的 ModelConfig 当前权限检查；按原 Task/Agent/RunConfig 重建环境与 Runtime，生成新 Episode ID 和版本化 `reruns/{new-id}.json` 来源记录。BFCL 先验证固定来源未变化；旧 Fake 单次产物缺场景来源则拒绝。原产物不会重写，重复重跑也不会被当作 Resume。

固定套件回归由 `scripts/check.ps1` 调 `python -m scripts.run_regression`，依次使用 `benchmarks/regression/course-smoke.json` 与 `course-four-categories.json`。后者固定四类任务各一题，Fake `invalid-then-success` 的基线为 Baseline 1/4、Recovery 4/4；这是工程回归，不是模型能力分数。Manifest 固定请求与基线 Artifact；`preflight` 在模型调用前校验请求、Task 版本、Agent 配置、Prompt/工具/预算和评测协议。当前版本运行一个新的 Experiment，`compare_experiments` 对相同 Task/Seed/Repeat/侧别逐项对齐，成功→失败计退化，失败→成功计改进；Token 附在报告供审阅。不同模型、任务版本或协议拒绝比较；未知费用不会伪装为 0。报告存 `artifacts/regression/regression-reports/{candidate-id}.json`，有退化退出 1，配置不兼容退出 2。

## 实际验证

- 全量质量脚本：194 passed、Ruff、mypy，Fake 固定回归 2 单元、0 退化；Web 构建 194 modules。
- 集成测试：两个并行 Job 在模型闸门上阻塞、第三个保持 queued；pause/cancel 在已完成 Baseline 后生效；pause 恢复的 Baseline 文件字节不变；cancel 不可恢复。重跑测试确认新旧 Episode ID 和来源、成功产物被拒；回归测试注入一个成功→失败并检出。
- 浏览器：单题异步 Fake Experiment `64de7e32-e985-4e09-82e5-6b3f9e40fff2` 完成；12 对 Fake Experiment `349f484c-42e5-49c8-b02d-f1ad7f930f5b` 完成，URL 从 job ID 变为结果 ID；失败侧 `cf1e098c-2a3a-5aae-b3fc-43fc4bde7b81` 经页面按钮重跑为 `e5093c3f-a827-4b8c-a2d5-4bfb9651c5c7`。Fake 运行太快，浏览器未抢在终态前点到暂停；该路径以延时集成测试验收。未调用真实模型。
