# V0.3 真实 Judge 限定一次（2026-10-22）

范围由负责人在 2026-10-22 明确授权：**一个模型、一道已保存 Episode、一次请求**，跑完即止；失败按原样记录，不重试、不换模型、不改 Prompt、不补跑。不是 Judge 质量或一致性的证据。

## 1. 结论

- 真实模型 `coding-minimax-m2.7-free` 对已保存 Episode `3af370c8…`（`order-status-001`，SUCCESS）的 **唯一一次** Judge 请求返回了非严格 JSON 文本，产品代码按既有规则保存为 `status=failed`、`failure_code=INVALID_JUDGE_OUTPUT`，**没有 verdict**。
- 链路本身是真实打通的：`provider=aihubmix`、`model=coding-minimax-m2.7-free`、`prompt_version=episode-review-v1`，响应被真实计费为 prompt **2711** / completion **252** Token（`simulated=false`），费用按目录口径仍为未知（`aihubmix-free-unverified`，`is_known=false`）。
- 源 Episode **未变**：评审前后 `episode_content_hash` 均为 `ee74a953…`；`artifacts/` 下 Episode 603 份、Experiment 55 份数量不变，只新增 1 份评审。
- 严格解析闸门有效：真实模型并未稳定输出裸 JSON（可能带代码围栏或额外说明），这正是一次可复现的失败样本；**不因此宣称 Judge 不可用，也不因此放宽解析或加自动修复**。
- 负责人随后批准 A 方案，追加**唯一一次**诊断请求并留存原始文本，根因已确证为两层：①响应开头带 `<think>…</think>` 推理文本，严格解析在第 1 行第 1 列即失败；②即使切出花括号内 JSON，字段值也不符合契约（`verdict="PASS"` 大写、三个维度为布尔 `true` 而非 `pass|fail|unknown`）。说明 `episode-review-v1` 的 Prompt 未声明枚举取值、也未禁止推理文本，属**协议描述不足**，不是单纯模型能力问题。详见 §5。

4. 一次 `AIHubMixModelProvider.generate(messages, [], config)`：无工具、无重试；`max_tokens=800` 只约束本次输出长度。

## 4. 边界与下一步

1. **不算 Judge 质量证据**：单次失败既不能说明该模型不会评，也不能说明其他模型会评；更不能用它计算准确率、一致性或与确定性评分的吻合度。
2. **不改产品契约**：`POST /api/v1/episode-reviews` 仍按 ADR-039 §9.4 只暴露 Fake Judge；本次没有新增请求版本、没有给网页开放真实 Judge 按钮，避免误点烧额度。
3. **失败原因已由批准的一次诊断请求确证**（见 §5）：`EpisodeReviewArtifact 1.0` 不保存原始响应文本是设计选择；诊断脚本不写评审产物、不改产品代码，只额外消耗一次真实请求。若要做“失败原文自动留存”，须先设计字段与脱敏规则，属新协议，另行确认。
4. 建议的后续选项（均需负责人另行授权）：升 `prompt_version` 到 `episode-review-v2`（写明枚举取值、禁止 `<think>`/围栏/解释性文字，并要求 event_ids 只能取输入中的 UUID）；或换一个模型再试一次；或维持现状，把真实 Judge 留到 V0.3 整版验收之后再谈。

## 5. 根因诊断（A 方案，同一次授权追加）

- 诊断脚本：`artifacts/real-judge-diagnostic-20261022/run_diagnostic.py`；结果：`summary.json`（含原始文本）。
- 请求与首次失败调用**逐字相同**（同一系统提示、同一 `review_input_hash`、`max_tokens=800`），只多保留 `response.action.text`；真实用量 prompt **2711** / completion **299**，费用未知；**不写入评审产物**，`artifacts/reviews` 仍为 1 份。
- 原始响应结构：`<think>…</think>\n\n{…JSON…}`，`raw_chars=882`，首个 `{` 在位置 342、末个 `}` 在 881。
- 第一层失败：`JudgeOutput.model_validate_json(raw)` → `Invalid JSON: expected value at line 1 column 1`，即 `<think>` 文本直接破坏严格 JSON。
- 第二层失败（切出花括号后再解析，仍不通过，4 个错误）：
  - `verdict` 为 `"PASS"`，契约要求小写 `pass | fail | uncertain`；
  - `answer_correctness` / `evidence_support` / `process_safety` 均为布尔 `true`，契约要求 `pass | fail | unknown`；
  - `rationale` 与 `event_ids` 合法，5 个引用 UUID 全部属于该 Episode 的可见事件。
- 结论：**不是解析器太严，也不是模型完全不会评**；是 `episode-review-v1` 没把枚举取值和“禁止推理文本/围栏”写进协议，模型按自己的直觉输出。要提升成功率，正确做法是升级 Prompt 版本（属于 §4 选项），不是放宽 `JudgeOutput`、加自动修复或加自动重试。

## 6. Prompt 升级到 episode-review-v2（2026-10-23，仅协议层）

- 改动只在协议描述：`packages/application/review.py` 新增 `JUDGE_SYSTEM_PROMPT` 常量，逐条写明六个字段、`verdict` 取 `pass|fail|uncertain`、三个维度取 `pass|fail|unknown`、`rationale` 非空且 ≤2000 字符、`event_ids` 只能取输入事件 UUID、只输出一个 JSON 对象、禁止 `<think>`/围栏/前后说明；`prompt_version` 常量升为 `episode-review-v2`。
- **未放宽任何校验**：`JudgeOutput` 字段类型、`model_validate_json` 严格解析、`_validate_event_ids`、无重试、无自动剥离全部保持原样；本次没有发真实模型请求。
- 兼容性：`EpisodeReviewArtifact.prompt_version` 放宽为 `episode-review-v1 | episode-review-v2`，仅为让历史评审（含本文件 §2 的 `9091d602…`）继续只读；`artifacts/reviews` 现有记录未被重写。Web `apiContracts.ts` 同步接受两个版本。
- 自动化：Python **640 passed**（新增 v1 兼容只读用例），Ruff format/check 与 Mypy 115 文件通过；Web typecheck/build、Node 45/45、Edge 66/66 通过。
- **边界**：v2 的成功率未经验证；Fake Judge 只覆盖协议闭环。若要判断 v2 是否真的改善真实模型遵从度，需负责人另行授权**一次**真实请求，且单次结果仍不能作为 Judge 质量或一致性结论。
