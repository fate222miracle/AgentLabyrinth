# V0.2 架构与 UI 复核：源码阅读与实验交接

日期：2026-10-03。唯一需求：`docs/product/requirements.md` V0.6。本轮是对已实现能力的缺陷复核，不替代 V0.2 整版验收；真实模型可用性与全局 Token 预算仍按 current-state 中的延期边界处理。

## 建议阅读顺序

1. `docs/adr/ADR-020-local-browser-origin-boundary.md` → `apps/api/main.py` 的 CORS 与 Origin 中间件 → `tests/unit/test_api_origin.py`。先理解为什么只改响应头无法阻止跨站 POST。
2. `apps/api/service.py` 中 `_get_live_model_ids`、`_require_live_model`、`execute_episode`/恢复/重跑/Experiment 入口 → `tests/unit/test_model_catalog_responsiveness.py`。区分“目录可见”与“真实调用成功”，观察耗时查询如何离开事件循环且共用缓存。
3. `apps/web/src/App.tsx` 的初始 URL/`popstate`、`switchTab`、历史 GET、运行 SSE、恢复与重跑 → `apps/web/src/McpFlowReplay.tsx` 的 `flowFrames`、`FitCanvas` → `apps/web/src/index.css`。最后看 `benchmarks/tool_lab_core/models.json` 与 README 的证据日期。
4. 需要理解底层调用时，继续读 `packages/application/episode.py`、`packages/runtime/handwritten/runtime.py`、`packages/tools/registry.py`、`packages/environments/tool_lab/environment.py`、`packages/evaluation/tool_lab.py` 与 `packages/domain/models.py`；本轮没有改变这些模块的契约。

## 调用链与状态变化

```text
本地 Web / CLI
  → FastAPI Origin 检查（非本地浏览器来源立即 403）
  → Pydantic 请求校验 → EpisodeService
  → 真实模型：固定白名单 ∩ 公共目录可见性 → Provider 的实际 POST 才能验证权限/通道
  → Runtime → Registry/Executor → ToolLab Environment → 独立 Evaluator
  → JSON Artifact / Trace → Web 历史 GET 或 SSE 运行画面 → flowFrames / React Flow
```

- 运行开始：Web 清空旧结果，分配 `historyRequestId`，`liveRun=running`，Trace 事件逐条追加；完成事件给出持久化产物后，`artifact` 替换实时视图，URL 写入 `episode_id`。失败或 SSE 中断不会伪造成功产物。
- 历史读取：先把 URL 改为目标 ID、清空旧产物并显示“读取中”；请求序号只接受当前响应。切换 Tab 写入对应 ID 或空态 `mode=single`；浏览器前进/后退据 URL 恢复视图。
- 恢复/重跑：服务端仍完成已启动的请求与持久化；若用户中途导航，Web 忽略迟到响应、错误和 loading 收尾，不把旧产物覆盖到新页面。Job 的后台轮询独立于 Tab。
- 流程动画：`flowFrames` 从实际事件提取工具节点。实时新增节点后 `FitCanvas` 随节点数重新计算视口；终态除 `SUCCESS` 外的输出卡显示失败样式。动画只读已保存 Trace，不再调用模型。

## 已确认问题、处理与证据

| 触发条件 | 影响与修复 | 验证 |
| --- | --- | --- |
| 任意网页跨站访问本地 API | 旧通配 CORS 配合后端 Key 会暴露本地历史与调用入口；ADR-020 收紧精确本地 Origin，路由前拒绝不可信 GET/POST/预检 | 新增 6 个 Origin 测试；原 API/流式/Job 套件全量通过 |
| 网关公共 `/v1/models` 返回 ID | 无效 Key 也可能看到 ID，旧文案会误导为“Key 可用”；改为“目录可见”，删掉无法通过后端白名单的自定义模型输入，说明真实调用才是证据 | 对比旧新 Key 的已保存探针记录；本轮未向网关发送请求；Web 构建与浏览器 Fake 回归 |
| 多个真实入口首次查询公共目录 | 同步网络等待阻塞 API 事件循环，重复请求并发查询；目录检查移入工作线程并加锁复用缓存 | 两个定向测试模拟慢查询与并发；不触碰真实 Key |
| Tab 切换、浏览器返回或迟到恢复/重跑响应 | 旧 URL/结果可能覆盖当前视图；URL 表示空态与产物态，请求序号丢弃过时的结果 | 浏览器对照/单次切换、刷新与前进后退；延时 Fake 重跑途中的返回抽查；后者未形成自动化长期回归 |
| 新工具节点在实时流中出现 | 画布原只在容器缩放时适配，节点可被裁切；现在节点数变化时重新 fit | 延时 Fake 实机观察 3→4 节点；两阶段节点均在画布内，最终视口重新计算 |
| 非字面 `FAILED` 的终止码 | `TIME_BUDGET_EXCEEDED` 等失败输出卡缺少失败样式；以非 `SUCCESS` 判断 | 历史超时 Episode 浏览器确认失败卡样式 |

## 保留边界与后续

- 本轮没有新真实模型调用；`/v1/models` 仍只是候选筛选，不做实际 POST 探测。最终免费模型名单与 Token 预算等待负责人确定，不能声称 V0.2 整版签收。
- Origin 限制仅保护本地浏览器访问边界，无 Origin 的 CLI 客户端仍允许，API 应继续绑定 loopback；它不是公网鉴权。
- 真实 200% 缩放、Windows 系统减少动效、第二台机器课程演示与负责人现场签收未在本轮完成。延时重跑返回已有浏览器抽查，建议后续补稳定的前端组件级竞态测试。
- 未改核心 Schema、评分口径、数据库或多 worker；未自动提交/推送，`.env` 与 Key 未读出或纳入产物。
