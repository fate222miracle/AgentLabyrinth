# UI第三批：实时执行到最终交付

负责人同意按演示主线优先推进。沿需求V0.6、原实时流/回放和资料来源规则，复用当前工作区，不新增API、依赖、任务协议或模型请求。保留全部先前未提交成果，未提交GitHub。

## 成品行为与源码

- `McpFlowReplay.tsx`保留逐条到达的事件节点及最终节点，完成后不重播；共享`RunDelivery.tsx`在流程前展示实际最终答案、提交引用、原规则结论与Fake/真实来源。完成时交接焦点到交付，不在每个事件更新时抢焦点。BFCL明确展示函数提议及参数，不伪造执行值；无提交、失败和缺失保持明确。
- `EpisodeSummary.tsx`复用同一交付组件，结果分析先交付再资源指标，避免两处答案口径分叉。长答案换行、无固定高度截断；规则未通过仍保留原提交。
- 历史交付标明整次运行结果，与回放游标独立；节点、当前阶段与关联资料继续只看事件前缀，不能把最终答案塞回初始观察。
- 任务目标与模型输入诊断按需展开；调用路径导航单行可滚动、当前项保持可见。桌面有资料时当前行动位于画布上方、资料在右；窄屏依次行动/画布/资料。全屏使用实际容器尺寸容纳当前节点，保留缩放与减少动效。
- `DocumentEvidence.tsx`支持预览其他资料后返回Agent最近关联文档，不发工具请求或修改阅读证据。当前反馈只列已成功返回的文档标识，正文集中在资料区；空正文或失败保留原反馈，不能显示“正文已返回”。
- `App.tsx`传递保存provider，`flowReplay.css`沿既有暖色/狐狸/字体及动效规则，不引入新的页面或装饰系统。UI规范1.16§19与任务卡同步。

## 课堂体验顺序

1. 任务库选择退货审核，或工作台使用课堂快捷配置；先用Fake确认完整演示路径。
2. 展开配置核对任务/模型/Runtime/传输与预算；显式点击开始后观察模型请求、文档读取、当前反馈及右侧依据。仅点资料预览不会调用工具。
3. 完成后停在最终交付，讲答案、引用和规则结论；再看保留的最终节点。需要看成本或耗时时切换结果分析。
4. 历史回放属于保存记录；明确与现场实时过程的区别。模型评审仍为独立显式请求，演示浏览不自动触发。

本批工程验证不代替负责人体验签收，也不证明真实模型效果提升。后续配置与实验差异阅读可继续精修，完整运行数据库列表/后台跨页执行保持原边界。
