# 持久化检查与演进建议

2026-10-28；需求V0.6。本次为只读代码分析和隔离Fake复现，不实施数据库迁移，不改评分或历史文件。

## 已确认的问题与边界

- `EpisodeService.list_episode_reviews`遍历所有评审并先完整读取，再筛选Episode；任意评审损坏可使无关Episode的评审列表失败。独立临时Fake Episode测试：添加无关损坏评审前GET 200，添加后GET 409，原Episode仍可读。不能把损坏记录静默当空列表。
- 可恢复Episode/Experiment/Job发现过程对部分损坏或读取错误直接跳过；空列表不能证明没有损坏的历史。Experiment看板另有skipped_count，但不等于完整的修复清单。
- 单文件临时写入、flush/fsync和replace降低半文件风险；计划、Job、各Episode、最终Experiment和删除检查点是多个独立步骤，不具有跨文件事务。已有恢复校验和故障测试可处理部分中断，不等于所有异常和掉电场景都已验证。
- `read_completed_episode`及实验臂路径原对格式损坏的最终Episode存在借有效安全点恢复并重写的逻辑。隔离测试确认原函数会把损坏结果当缺失；现改为直接停止，保留结果与安全点原字节。历史/Job/进度/预算相关64项通过，Ruff/格式/Linux目标Mypy三文件通过；未验证真实历史是否出现过损坏，也未重跑完整门禁。
- 实验看板扫描解析所有实验后仅返回最近100条；评审查询扫描所有评审并回读每份对应Episode。数据增长的成本可从代码推断，本次没有压测，不给出阈值或性能数字。
- Job注册和恢复活动集属于进程内状态，ADR-016明确仅支持本地单进程，不支持多worker安全调度。更换存储本身不能保证外部工具恰好一次或消除调度竞争。
- 键名过滤不保证自由文本中包含密钥或个人信息时被清理；`artifacts/`被Git忽略但不是备份、加密或访问控制。

## 建议与迁移原则

短期先确认损坏文件恢复覆盖、评审隔离和发现列表可观测性：隔离测试覆盖损坏、缺文件、权限错误、中断、恢复和重复请求；保留证据并避免自动重跑。涉及返回结构的改动先提出具体ADR。

建议为本地单进程实验设计SQLite方案：以一个已批准的权威存储为准，事务保存相关元数据和版本化JSON原文，建立按Episode/Experiment/时间/状态的索引；Trace可用序号约束和原始JSON，避免引入解析重写导致历史变化。是否把所有原文放入数据库、保留JSON文件作导出，需基于实际大小和恢复测试定案，不在本次实施。

迁移需要：只读清点及备份；旧文件源字节哈希、身份/版本/关联校验；坏文件单独报告且不伪造；导入到新库后核对数量、哈希、旧/新回放与指标；故障注入和重复导入测试；显式切换唯一权威数据源并有回滚方案，不将两边独立写入当作可靠同步。验证用户不受影响后再讨论旧文件保留策略，禁止自动删除。

SQLite WAL可以同时读写但同一时刻只有一个写者，也不适合通过网络文件系统跨机器共享；多worker、多机、真正多人使用时另评估PostgreSQL以及独立调度/幂等机制。参考 https://sqlite.org/wal.html 。数据库备份/恢复、权限和真实负载性能需另测。当前不声称数据库能提高Agent正确率或自动解决MCP外部写的幂等。
