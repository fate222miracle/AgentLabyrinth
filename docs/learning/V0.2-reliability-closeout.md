## 恢复调用链与状态

探针父进程启动独立子进程 → Service 真实 Provider → 原运行入口 → 工具完成、消息/预算/Trace/环境同时安全落盘 → `os._exit(75)` → 父进程新建 Service → 原 Resume 入口校验配置/来源 → 继续同一 Session/ID → Evaluator → 原子写终态 → 删除存档。

BFCL 子进程在调用提议已提交的终态安全点退出；恢复仅评测、落盘，不再次请求模型或提议。MCP 通过独立 localhost HTTP 服务读取固定文档，依据 `TOOL_STARTED` Call ID 对应成功事件判断已读完成，恢复只执行后续提交。Experiment 子进程在 Baseline 最终产物已保存、Recovery 安全点已写后退出；父进程恢复原计划，直接复用 Baseline 文件，只继续 Recovery。

Fake Job 集成测试另验证 `running` 状态在进程退出后 GET 显示 `interrupted`，显式 Resume 才变 `queued → running → completed`。本轮修正 API 曾允许 `failed` Resume 的入口：原入口会先改 queued，绕过 Service 的终态拒绝；现在修改状态前返回 409，错误文件不变。取消仍不可恢复，失败 Episode 另走新 ID Rerun。

## 看板调用链与失败路径

`GET /api/v1/experiments → Service 读取持久化 JSON → 校验文件 ID/配置哈希/Pair 数量 → fixed_config 哈希 → DTO 1.1 → Web 兼容组筛选 → 最新两次差值/明细 → GET 历史结果`。

比较键固定模型参数、任务版本、种子/重复、预算、场景/故障、工具/Prompt、环境/评分和对照策略；允许实现版本不同。旧产物缺少来源时仍显示、比较键为空。坏文件、哈希篡改、Pair 数量不符跳过并提示。未知字段写未记录，实际网关费用未知与原厂参考成本分开展示，不追溯补价。

看板请求取消上一次刷新，并忽略已取消响应，防止旧请求覆盖新筛选数据；卸载清理。读失败给重试说明并保留可打开的已有结果。列表至多最近 100 条，当前组每次多显示 8 条。两次差值是排查线索，不是显著性或全局排名。没有新增模型请求、图表库或数据库。

## 接手检查问题

1. 为什么 `failed` Job 不能在写 queued 后再交给 Service 校验？
2. 为什么 BFCL 的一模型一工具恢复成功不等于执行了真实外部函数？
3. 哪些配置变化会把历史实验分到另一组？为什么实现版本可不同？
4. 为什么两个成功率差值不能支持统计显著性结论？
5. 为什么 Checkpoint 账面用量可能低于实际网关用量，原厂参考价不能充当实付账单硬上限？
