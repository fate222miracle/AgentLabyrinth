# V0.2 全局 Token 预算：源码与交接

依据：需求 V0.6 FR-08、Accepted ADR-025。本轮补既有版本缺口，未开启全部 V0.3、提交推送或替负责人签收。

## 1. 交付与含义

API/Web 新增可选 `max_total_tokens`，累计一个冻结 Experiment 的全部侧别、任务、Seed、Repeat 已报告输入与输出。原 `token_budget` 仍是每个 Episode 的限制。

这是 **Episode 边界准入预算**：累计达到阈值，不再启动或恢复未结束的下一 Episode；当前 Episode 可超过阈值。如果超额的是最后一侧，允许保存完整实验，网页明确显示实际累计与超额。不是硬性最大用量、供应商账单或跨 Job 的共享账号预算。

失败的已报告用量照计；请求没有匹配响应或汇总与 Trace 不一致，停止后续准入，不能按零累计。已结束安全点可以零模型调用地发布最终 Artifact，之后下一侧仍受预算限制。

## 2. 阅读顺序与文件职责

1. `docs/adr/ADR-025-experiment-token-budget.md`：规则、版本、限额与无法保证的边界。
2. `apps/api/schemas.py`：请求 1.4 的严格正整数参数；旧请求版本可读，新参数拒绝旧版本。
3. `apps/api/service.py::prepare_experiment`：仅设置新预算时加入 metadata，旧配置不补 null、旧单次预算不改。
4. `packages/application/experiment.py`：新计划 1.1、完整产物 1.3；验证恢复 metadata；初始化矩阵账本；`reported_tokens` 对齐请求/响应/汇总；`run_arm` 准入；`record_tokens` 用完整累计替换该 ID 的安全点值。
5. `apps/api/main.py::_run_experiment_job`：明确区分预算达到和未知用量两个 failed error_code。
6. `packages/application/regression.py`、`scripts/run_regression.py`：新阈值进入回归预检查与比较指纹；没有新预算的旧基线仍按原指纹比较。
7. `apps/web/src/apiContracts.ts`、`App.tsx`：消费版本/字段校验、草稿预算、保存预算与超额说明、停止原因；失败 Job 结果面板明确“未形成完整成对结果”，不显示成功率；窄屏结果优先。
8. `tests/integration/test_global_token_budget.py`、`_checkpoint_worker.py`：边界、失败/未知、跨进程安全点、终态发布、损坏来源、旧配置、Job GET；前端 Node/E2E 增补预算兼容和只读刷新。

主链：网页显式 POST → 固定计划落盘 → 排队 Job → 同一 Experiment 串行执行侧别 → 保存 Episode → 替换账本对应值 → 下一 Episode 准入 → 完整实验或明确 failed。GET/刷新不进入模型执行链。

## 3. 状态与失败路径

- `EXPERIMENT_TOKEN_BUDGET_EXCEEDED`：达到阈值，保留完整 Episode/冻结计划，Job failed。提高限额须新建实验，不能恢复原 ID 清零。半对不补虚拟结果。
- `EXPERIMENT_TOKEN_USAGE_UNKNOWN`：存在未报告或不一致的用量，同样保留证据并停止，不继续 Provider。
- 完整 Artifact 来源/身份冲突、安全点被改写、坏 JSON 无有效安全点：在准入前拒绝；正确安全点可以重建损坏最终文件。
- 安全点恢复：执行前一次扫描原冻结矩阵；同 ID 完整结果优先，只计一次。当前侧恢复后的累计替换旧值，不将恢复前的用量再加一次。
- 终态安全点：next_node=end 不需要继续模型，可完成落盘；不会把保存结果的动作误当新的预算消费。
- 旧计划与配置保持原版本/字段；新预算进入计划与结果哈希，恢复不能换预算或任务条件。

安全点以外未持久化的在途请求无法证明是否消耗了上游额度，本方案不能保证供应商实际总量或请求恰好一次。算法只支持当前单进程固定计划，不引入数据库或分布式协调。

## 4. 实际 Fake 行为

固定成功订单每侧两次模型，模拟 Token 每侧 120：

| 全局预算 | 计划与实际行为 |
| --- | --- |
| 1 / 120，多 Pair | 第一侧完成并保存 120，下一侧停止；重启不新增调用 |
| 121 / 240，多 Pair | 两侧共 240，下一 Pair 停止 |
| 241，多 Pair | 三侧共 360，第四侧停止，保留半对 |
| 121，仅一 Pair | 两侧完成 240，形成完整报告并明确在途超额 |
| 180，120 完整侧 + 60 安全点 | 恢复前达到阈值，0 新模型调用 |
| 181，相同安全点 | 允许恢复一调用，该侧完整累计替换为 120；全场 240 后停止下一 Pair |
| 未报告响应/超时 | 当前 Artifact 留存、未知用量错误；重启 0 新调用 |
| 第一侧失败但报告 60，预算 60 | 失败用量也计入，不启动下一侧 |

这些是 Fake 工程证据，不是免费模型能力/计价/真实 Token 消耗结论。本轮没有新的真实预算实验；10 月 8 日此前四模型真实复测独立保留。

## 5. Windows 写入问题修复

完整门禁首次 312 passed/7 failed；七个失败用例短目录重跑全部通过。等长目录复现证实：原临时文件名包含目标 UUID 加随机 UUID，较长 Windows 工作区下触及路径长度限制，报 FileNotFoundError，导致 API 返回 500。

在共享 `trace.write_text_atomically` 将临时名缩为一个随机 UUID；Experiment 计划和 Episode 安全点改为复用该函数，保留同目录临时写、flush/fsync、原子 replace、失败清理与旧文件保护。不是只对 pytest 改目录掩盖问题，也不承诺任意长度的最终 Windows 路径可用。原门禁中的长目录用例修复后通过，已有替换失败测试仍保护旧产物。

首轮专项还有一条测试错误地引用真实模型预算而不是 Fake 原值，已按实际 Fixture 修正；首次 lint 导入排序、测试回调类型和根目录误运行 npm 的检查失败也修正。未把首次失败写成通过。
