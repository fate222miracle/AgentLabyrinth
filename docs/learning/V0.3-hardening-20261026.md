## 2. 源码阅读与数据流

1. `apps/web/src/historySummary.ts::savedUsage`：只读保存Episode与事件，核对完整性，返回complete/reportedTotal；不修改产物、不估算缺失Token。
2. `EpisodeSummary.tsx`与`PlanningPairReview.tsx`：复用该检查；有报告显示输入/输出，无报告显示未知。汇总页面缺少各Episode完整Trace，只改为保守的已报告标签，不发额外批量GET或捏造完整标志。
3. `App.tsx::loadMetadata`：首次优先Fake，普通原生任务只选一个；刷新保留存在于目录的选择。两个模型选择器为空时有明确占位选项，防止浏览器替用户显示第一项真实模型。`expGlobalTokenBudget`初值16000。
4. `ExperimentCharts.tsx`/`ExperimentDashboard.tsx`：数值仍来自原保存metrics，仅澄清报告范围。`tool_selection_accuracy`的计算仍在原Evaluator，Web只改解释。
5. `.github/copilot-instructions.md`：稳定协作入口替换过时任务/自动试跑指引；根AGENTS/current-state保留历史，不以旧记录作为当前授权。
6. `index.css`：已保存运行指标的说明与标签允许长词换行；处理实际390视口中NETWORK_CONNECTION_FAILED越卡的问题，不通过缩小字体或隐藏错误码规避。

## 4. 剩余硬伤与接续约束

当前修复不能证明网络已稳定、规划能提升成功率、Judge准确或Runtime独立调度边界已消除。仍需先分析网络失败与失败可观测性，再设计有区分度且预算明确的效果验证；任何新真实请求需单独授权，失败必须保留。

App的大组件与重复状态、JSON文件单进程持久化、文档历史冗长属于仍需评估的维护问题。本轮不为清理表象一次拆整个前端，也不引入数据库/队列或新Agent机制。后续修改必须针对复现的问题和明确验收，不能把测试数量作为研究收益。Reflection保持暂缓，A1边界保持。
