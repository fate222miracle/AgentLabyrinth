## 1. 使用方式与产品边界

打开对照实验页，在“待恢复的对照实验”或“可恢复的实验任务”中点击指定ID的“查看保存进度”；当前Job区也提供入口。默认不加载各计划的Trace，不自动批量读取；按钮只GET，没有模型/工具调用。重新读取仅刷新快照，关闭会取消读取；跳转“查看保存的运行”走原Episode只读页。

状态含义：

- 已保存结束记录：有通过来源核对的结束Episode，成功或失败另行显示。
- 仅保存安全点：没有可用结束文件，保留了来源匹配的安全点。
- 尚无保存记录：可能尚未开始或尚未落盘，不能当失败、零用量或“确定未执行”。
- 保存记录不可用：有文件但损坏/来源不符，明确提示，不从安全点冒充完成。

此快照不是完整Experiment，不计算通过率或费用，不把右侧未执行捏造成失败；原恢复和Job控制保持显式操作，查看不代表继续执行。冻结计划已被正常成功清理的完整实验不适用此接口，仍走原结果页。

## 2. 源码阅读顺序与调用链

1. `apps/api/schemas.py::ExperimentProgressResponse/ExperimentProgressArm`：响应1.0及四种保存状态，未完成侧的success/termination保持null。
2. `apps/api/main.py::get_experiment_progress`：GET `/api/v1/experiments/{id}/progress`，后台线程读取；缺计划404，损坏/外来计划409，消息固定且不回显输入。
3. `apps/api/service.py::experiment_progress`：读冻结计划并验ID/hash → 依原seed/repeat/task顺序与uuid5规则定位两臂 → 复用`read_completed_episode`/`CheckpointStore.load`，检查Agent/Task/Seed/环境/配置hash与已有安全点；重复事件ID也拒绝 → 输出轻量状态。结束文件坏时不降级为安全点；不读最新任务目录或新草稿，不重写旧文件。
4. `apps/web/src/apiContracts.ts`：Zod Mini校验响应版本/状态与结果一致性/重复归属；调用方另绑定所选实验ID。
5. `App.tsx` → `ExperimentProgressReader.tsx`：显式选择ID才加载；切换使用key重建并AbortController取消旧请求，失败可重读，只有completed提供Episode链接。
6. `traceSteps.ts::explainFailure`：从App原函数抽出共享，无新依赖。Episode原摘要、规划对照和进度快照复用；网络错误不判断每日额度耗尽，用量未知明确停止后续准入。未知错误保留原值，不吞错误或自动重试。

冻结计划没有独立Runtime版本字段时，不按当前SDK版本补造历史版本或声称完成了框架版本一致性验证；结束记录与安全点之间仍按保存RunConfig核对。接口归属检查不代表重新评判任务正确性。
