# V0.3 SQLite 单 Episode 持久化成品交接（2026-10-29）

## 交付范围

本轮完成 ADR-043 的首个成品切片，不是隔离样例：正常单次与实时 Episode 已使用 SQLite 保存安全点、完整 Trace、最终结果和 Fake 恢复来源；API 的历史读取、复核和失败重跑复用同一结果。Application 只依赖 `EpisodeStore` Port，Infrastructure 使用 SQLAlchemy 2.0，Alembic 管理 `0001_episode_records`。产品数据库延迟创建于被忽略的 `artifacts/agentlabyrinth.sqlite3`，无仓库内绝对路径。

同一 Episode 只有一个权威记录。每个安全点先验证来源、预算和 Trace，再在 `BEGIN IMMEDIATE` 短事务中插入或前缀扩展；完成时核对安全点身份、配置和事件前缀后原子转为不可覆盖的最终结果。模型和工具调用发生在事务外。数据库读取再次核对载荷 SHA-256、UUID、配置哈希、事件唯一性、父链和唯一结束事件。

旧 JSON Episode 不写入数据库、不删除、不重写；读取按 ID 兼容回退。数据库与文件若出现同 ID 冲突会停止并报错，不选择“看起来更新”的一边。Experiment、Job、成对运行和 Review 仍维持原 JSON 权威，后续必须按各自事务边界单独接入。

## 故障与恢复

- 新 Python 进程在首个工具安全点后直接退出，重启服务能从同一 SQLite 记录继续，保留 Episode ID、已执行工具和 Trace，并把该行转换为最终结果。
- 重复完成的相同载荷幂等；不同完成载荷拒绝覆盖，事务失败后原结果不变。
- 摘要篡改、来源/Trace冲突、未知现有数据库和数据库/旧文件同 ID 冲突均失败关闭。
- SQLite 使用 WAL、`synchronous=FULL`、外键和5秒busy timeout；仍只承诺本机单进程调度，不把SQLite描述成多机锁或外部写工具幂等方案。
- `python -m scripts.backup_sqlite <新备份路径>` 使用 SQLite 在线备份，拒绝覆盖既有文件并对备份运行 `integrity_check`。没有自动备份计划，也不会自动清理源数据库。
