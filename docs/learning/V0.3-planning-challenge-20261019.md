## 调用链与状态

**运行（右臂/声明计划）**：`service.execute_experiment` → `_task_tool_version` 先派生任务再返回 `v1.6.0` → 构建 `baseline_agent`（`planning=None`）与 `recovery_agent`（`PlanningConfig()`），两侧 `ContextPolicy(mode="full")` → Runtime `Session`：

- `observe` → `model`：`call_model` 先执行`project_context`，`full`不裁剪历史；若启用且已有计划，再追加保留封装`_agentlabyrinth_plan`，记录实际消息数量/字节与声明来源，最后调用`provider.generate(model_messages, self._available_tools(), ...)`。计划消息不写回完整持久对话；PLAN_UPDATED/成功工具反馈仍保留。
- `validate/execute`：`update_plan`经Registry/Validator校验；结构非法在TOOL_CALL_VALIDATED阶段拒绝，最多一次参数纠错，不伪造工具已开始/执行失败事件。真正执行出错才记TOOL_FAILED。成功回写self.plan并记PLAN_UPDATED；声明与成功反馈都保留。
- `submit_answer` 成功才 `done`；计划声明**不**触发环境 `done`。

**保存/恢复**：`checkpoint()`依plan/pending_calls选择SessionState版本（有plan→1.2）；restore不仅核对Agent启用状态，还核对图结构、此前合法提议/成功返回/对话与PLAN_UPDATED，删除/篡改计划也拒绝。规划轴的ExperimentCheckpoint版本为1.4，其中冻结Agent组件配置；具体运行计划由各Episode保存。

**指标**：`fixed_config()` 不含 `planning`（轴变量非公平字段）；`order_status.py` 对 `plan-update-v1` 任务把 `update_plan` 从 proposed/validated 剔除，使工具选择/参数有效性两侧可比。

## 失败路径

- 结构非法（未知/重复 id、跨计划依赖、成环、超长、超项、非法 status）→ 拒绝，不静默修正。
- 无规划臂调用update_plan：工具不可见且Runtime权限拒绝，任务失败，不能由Evaluator的组件指标排除掩盖；任务明确禁止的工具尝试仍计入禁止工具次数。用户预览/文档正文不会成为保留计划封装。
- 计划自称 `done` 但未真实提交 → 评测不通过（只以环境提交为准）。
- 恢复时计划/上下文/赛道不一致 → `restore`/artifact 校验拒绝。
- 计划声明多一轮模型调用与 Token 全部计入该臂预算，不另送免费调用。
