# 读懂桌面界面的连续过渡

2026-10-04；需求V0.6、UI规范1.3。[调研与决策](../research/desktop-motion-20261004.md)、[任务卡](../tasks/ui-motion-20261004.md)。负责人授权先调研再直接实施，人工手感/整版签收仍延期。

## 做了什么，为什么

桌面操作频繁，连贯感需要动作即时生效、速度平滑减速，新的动作可以接管未完成的动画。本次保留暖色设计、原生滚动和sticky导航，通过短距离位移、透明度和滑动选中标记呈现空间关系。不是对iOS惯性物理模型的精确复制。

两项顶部导航已有滑块，本轮统一减速曲线；原三项Replay仅切换背景，现在共用沿轨道滑动的选中标记。导航/Replay/故事步骤共享局部内容过渡；配置、历史与工具详情在浏览器支持时平滑伸缩；按钮有轻微按压，桌面指针悬停任务卡有小幅位移。

保持120/180/240ms三级时长，JS读取CSS Token。CSS过渡可自然重定向；JS动画被打断时采样当前画面位置/透明度，从该位置回到静止状态。不会等动画结束才修改页面、URL或开始GET，也不保持可点击的旧结果副本。

5. `apps/web/src/App.tsx`：main、Replay内容与故事步骤实际复用hook，保留原状态/URL/数据边界。新增DOM容器不复制Artifact，也不改变Trace。
6. `apps/web/e2e/motion.spec.ts`：真实Fake产物、RAF中间采样、快速反复切换、草稿/焦点、动态reduce、API故障降级与视频；旧`acceptance.spec.ts`继续验证四视口和回放无POST。

```text
点击/键盘 → 原App状态更新、原URL/GET规则
 → React提交新内容 → useContentMotion读取CSS Token
 → 减少动效/不支持：立即静态呈现
 → 正常：180ms局部减速 → 结束，未写入永久内联样式
 → 新操作：清理旧动画并采样呈现值 → 新内容、新过渡
 → 媒体偏好变为reduce：取消动画，静态选中/内容/焦点保留

details原生toggle → DOM仍保存原表单值
 → supports intrinsic-size：240ms伸缩；否则即时展开
```

## 生命周期与失败路径

- `previous`/`interrupted`只属于UI hook；不进入Artifact、Checkpoint、API或localStorage。
- 动画与媒体监听随下一次状态/卸载清理，不累积动画队列；结束不留下锁定的transform/opacity。
- 元素不存在、减少动效、animate缺失或抛错，都保留已提交内容，不让视觉增强阻断操作。
- 偏好动态变化会取消JS位移；CSS与SVG保护继续有效。播放/切帧仍是用户主动的只读操作。
- 不截获滚轮/触控，不新增推测模型思考阶段，不以动画结束事件控制网络或成功判定。
- intrinsic-size支持情况决定展开是否有动画，功能仍使用原生details；没有为兼容动效引入新依赖。
