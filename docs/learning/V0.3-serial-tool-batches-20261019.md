## 1. 使用与版本

新网页ToolLab默认“多工具：同轮只读调用，按顺序执行”，更多设置可切single。对照配置提供两侧共同的调用方式；历史显示保存模式，切草稿不会升级历史。BFCL单函数评分保持single，界面说明并锁定，API显式serial请求拒绝。

- ModelConfig1.1 + tool_call_mode=single/serial；旧1.0不带字段，序列化省略None，旧Agent哈希保持。ModelResponse1.1的tool_call_batch为2–8个调用；一个调用仍用原tool_call。
- 新Episode请求1.4/Experiment请求1.7要求明确模式；旧版本拒绝新字段，默认版本保持旧行为。现有Agent/结果/计划外层不升级，冻结独立版本ModelConfig，模型配置和任务协议进入比较指纹。
- 新serial运行派生Task版本`原版本+serial-v1`，保存source_task_version及tool_call_protocol=serial-read-batch-v1，替换单工具限制为批次规则。原18题JSON、私有目标和评分不改；恢复/重跑读原保存版本。
- 本次批次只接受只读工具，提交答案及其他写工具仍单独调用；按原顺序逐个执行，无工具并发或事务回滚承诺。

## 2. 源码阅读顺序与调用链

1. `packages/domain/models.py`：ModelConfig、ToolCallBatch、ModelResponse的版本验证；`ports.py`错误可携带已验证TokenUsage。
2. `packages/providers/aihubmix.py::generate`：serial发parallel_tool_calls=true（允许模型返回多个，不代表平台并发）；完整解析最多8项，不截断/补造Call ID。新配置解析失败时携带上游有效非负整数用量，旧配置失败行为保持；缺用量不补造。
3. `apps/api/schemas.py`请求版本；`service.py::_with_call_mode/_agent_with_call_mode`冻结执行变体与模型模式。BFCL入参在调用Provider前拒绝serial。
4. `packages/runtime/session.py::call_model`一次计模型与Step、完整响应计Token。`_validate_batch`全批提议/校验，任何权限/未知/重复/写工具或不足工具预算在执行前终止；每项独立Trace。参数错仅在原recovery策略下允许一次，整批零执行，逐Call ID给错误/取消反馈，要求新Call ID。
5. `execute`一项一项经过原Environment/Registry/Validator/Executor；每项计工具、保存真实返回和环境快照；中途失败/超时不运行后项。一个assistant工具列表对应多个tool反馈，不伪造额外模型轮次。
6. `SessionState1.1`在execute节点保存剩余队列；恢复核对同轮原调用、已返回反馈、Trace参数/计数/来源与未执行项权限。`handwritten/runtime.py`原调度可继续execute；`langgraph/adapter.py`增加execute自环，图递归边界覆盖真实工具预算。
7. `packages/runtime/context.py`原有整轮匹配逻辑直接复用：N=一次assistant响应+所有tool结果；整轮保留，记忆按每条成功返回准入。未完成轮次不再次请求模型。
8. `packages/application/experiment.py`仅为新配置在保存model中记录模式/子版本，保持旧config哈希；`scripts/run_regression.py`检查模式及派生任务协议，不跨单/多模式比较。
9. Web：`App.tsx`新建模式/CSV追加tool_call_mode/同轮所有调用概览，`flowFrames.ts`保留批次序号与Call ID独立节点，`McpFlowReplay.tsx`显示同轮次序/被拒响应，`EpisodeSummary.tsx`显示保存模式。概览批次使用整行两列卡片，窄屏单列，不把多条结果堆在单列旁留下空白。

## 3. 状态与失败边界

新批次：模型响应 → 全批提议/参数权限预检 → pending全部调用/assistant消息落盘 → 执行第一项 → 结果/快照/剩余队列落盘 → 下一项 → 完整轮次 → 下一模型请求。

- 预检失败整批没有TOOL_STARTED，不能将已提议当已执行。写工具即使参数也错，仍立即按批次不允许写拒绝，不进入参数纠错。
- 第二项执行失败时第一项已经完成，保留它的状态与计数，第三项不执行；无回滚承诺。时限在每项前后检查，已开始的工具先保存返回。
- 批次安全点恢复只执行剩余工具，无再次模型请求或重做已完成项。Call ID、参数、会话与Trace不匹配即拒绝。Session1.0/旧单工具恢复保持；进程在工具返回与落盘之间退出仍不属于通用外部写幂等保证。
- 新模式解析失败但有有效上游用量：MODEL_RESPONDED action_kind=rejected记录该用量和错误码，工具零执行；没有用量则保持未返回/未知，原全局预算检查继续拒绝未知记账。并未恢复上一轮失败请求丢失的用量。
