# 课程案例固化与 UI 失败状态学习指南

需求依据 V0.6；本轮只包装现有能力与修复展示，不新增核心 Schema/协议。任务与验收见 `docs/tasks/V0.2-demo-freeze-20261001.md`，命令和实际 ID 见 `docs/handoffs/V0.2-course-demo-20261001.md`。

## 为什么需要这次工作

旧演示链接依赖被忽略的本机产物；新电脑没有这些 UUID 文件。`scripts/course_demo.py` 用相同固定任务和正式入口重新生成案例，并让失败条件也参与验收。诊断索引只保存产物 ID 与链接，不能替代 Episode/Experiment 或独立评分。

历史 GET 失败后旧成功结果原来仍显示在屏幕上。本轮用真实 404 复现，修复时先清空对应产物、更新请求 URL，再等待响应；当前请求序号仍防止较早响应覆盖较晚选择。普通回放不会重新执行任务。

## 源码阅读顺序和调用链

1. `scripts/course_demo.py`：`generate` → `local_cases` / `resume_case` / `network_cases`，看固定输入、验收条件与输出目录；`preview` 只管理自己启动的 API/Web，`DemoService` 限制本轮预览为 Fake。
2. `apps/api/schemas.py` → `apps/api/service.py`：服务组合 Task/Agent/Provider/环境和 Runtime；`execute_experiment` 保持单变量对照。
3. `packages/application/episode.py` 与 `checkpoint.py`：正式 Runner、安全点原子保存和恢复来源校验；回到 `interrupted_child`，理解为什么先调用真实 save 后才退出进程。
4. `packages/runtime/session.py` → `packages/providers/fake.py`：共同计时/校验/调用与 Fake 的恢复 call_count；调度器没有订单业务。
5. `packages/environments/tool_lab/mcp.py` → `environment.py` → `packages/tools/executor.py`：官方 SDK Client 和独立 MCP Server 的真实 HTTP 调用；本地证据状态只在远程读取成功后更新。
6. `packages/evaluation/order_status.py`：只读评分，运行终止码与评测通过仍是不同事实。
7. `apps/web/src/App.tsx` 的 `loadEpisodeById` / `loadExperimentById` → `flowFrames.ts` → `McpFlowReplay.tsx`：GET 历史、映射事件、只读动画；`index.css` / `flowReplay.css` 用统一辅助色与字号。
8. `tests/integration/test_course_demo.py`：运行真实 CLI 和子进程，检查保存的评分、工具顺序、未知费用、拒绝覆盖与真实模型拦截。

## 对象生命周期与状态

生成器为新目录创建一个 EpisodeService，所有案例由它写入正式产物。普通 Episode：接收任务 → 模型提议 → 严格校验 → 工具执行/环境快照 → 安全点 → 后续动作 → 唯一终态 → 独立评分与落盘。子进程在首个查询工具安全点退出码 75，父进程用新服务按存档 ID 恢复：恢复事件 → 提交 → SUCCESS；查询工具不重复。

MCP 进程仅在网络案例期间存在。`ready` 用 SDK `tools/list` 核对两个只读工具，随后分别运行同一任务的本地与 HTTP 路径。平台本地提交没有 transport 字段；动画根据固定 ToolLab 环境和 submit_answer 识别本地边界，不修改已有事件。

Web 历史读取：请求序号递增 → 清空对应结果/更新 URL → GET → 若序号仍为当前则更新结果和加载状态。404 留明确错误与所请求 ID；较早返回的成功或错误不会覆盖当前请求。草稿配置保持独立。

## 失败路径与限制

- 参数错误：Baseline 终止失败；Recovery 获得一次结构化参数反馈后成功。固定对照 0/1 → 1/1，只证明受控 Fake 挽救。
- 总时限：人为 Fake 等待 250ms，总时限 40ms，模型等待终止；无响应用量保持未知，0 工具，不重试。同步工具的截止边界仍遵循 ADR-019。
- MCP 断线：固定不可达端点，记录 TOOL_FAILED，无答案，不继续远程读或本地提交。不是杀掉用户已有服务，也不是网络包级抓取。
- 子进程未到安全点/最终状态不符/本地远程状态不同：脚本非零退出，保留现场，不写完成索引。已存在目录拒绝覆盖；端口已占用不接管。
- 预览仅 Fake，阻止真实 Provider 创建；正常 API 与模型目录未改变。真实模型、跨公网、多 worker、外部写工具、全局 Token 和数据库均不由此验收。
- 依赖安装仍需网络；已安装依赖的核心课程包不需要 BFCL 下载。未在第二台机器实测，真实浏览器 200% 和 Windows 减少动画未验。

## 实验与检查问题

完整网络案例生成与一条命令预览都已实际跑通，详见交接报告。最终 Ruff/mypy 86 文件、pytest 225 项（1 条既有 Starlette/AnyIO 警告）、Web 195 modules、Node 11 项通过。四套 Fake 回归沿用同日上一收尾验证，未把本轮无变更的 Runtime 重复跑成新证据。

最小失败保护实验：

```powershell
uv --cache-dir .uv-cache run --locked pytest -q tests/integration/test_course_demo.py
```
