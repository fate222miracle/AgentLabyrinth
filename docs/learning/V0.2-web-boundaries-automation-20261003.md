# V0.2 Web 接口边界与自动验收阅读指南

需求唯一来源：`docs/product/requirements.md` V0.6。执行范围见同名任务卡，选择依据见 Accepted ADR-022。这轮解决“接口类型看起来正确，但实际 JSON 错误仍进入 UI”和“手动验证难以重复”的具体问题，不改变公开 API、Domain Schema、评分或模型选择。

## 源码阅读顺序

1. `apps/api/schemas.py`、`packages/domain/models.py`、`packages/application/experiment.py`：公开 DTO、Trace/Episode 和 Experiment 的权威代码契约。
2. `apps/web/src/apiContracts.ts`：页面实际消费字段的投影 Schema；先看 count/rate/UTC/Decimal，再看 meta、事件、结果、Job 和历史。`z.infer` 推导静态类型，不再另写一套接口。未消费字段保留用于导出，旧可选指标保留 undefined/null，不补零。投影不能替代后端的完整 Pydantic/来源哈希验证。
3. `apps/web/src/apiClient.ts`：HTTP 状态 → unknown JSON → Schema → 请求身份校验。错误只回显标准后端错误或中性提示；解析错误不暴露原始值和堆栈。
4. `apps/web/src/streamEpisode.ts`：分块 UTF-8/CRLF 与多行 data 合并；每条 Trace 先验证再通知 UI，拒绝重复/错属事件；complete 与已收到事件的 ID 和顺序必须一致。校验失败取消客户端读取，后端仍可能继续落盘。
5. `apps/web/src/App.tsx`、`requestGeneration.ts`、`historySummary.ts`：所有结果入口调用校验；页面请求归属判断继续保留，校验通过也不能由迟到响应抢回导航。恢复列表失败显示“可能不完整”，不静默冒充空列表。
6. `apps/web/e2e/acceptance.spec.ts`、`playwright.config.ts`、`scripts/web_test_server.py`：真实 API + 页面，独立目录、仅 Fake、拒绝复用服务；WebServer 管理自己的进程。测试服务器复用 DemoService 的真实模型拒绝入口，不读取 `.env`。
7. `scripts/check.py`、`scripts/check.ps1`、`.github/workflows/quality.yml`：同一条本地/CI 命令链，任一步失败即停止；官方 Action 固定 SHA，只上传新质量目录，不上传 `.env` 或整个 artifacts。

## 调用链和状态变化

```text
单次点击 → POST episodes/stream → API/EpisodeService → Runtime/工具/独立 Evaluator
  → trace JSON → Trace Schema → 当前请求归属 → liveRun/节点
  → complete JSON → Episode Schema/一致性 → 当前请求归属 → 保存结果与 URL
  → Replay（仅消费保存的事件，不重新执行）

历史/恢复/重跑 → HTTP JSON → Schema → 历史/恢复 ID 核对 → 请求归属 → 结果
Job 创建 → validated queued → 当前请求归属 → Job ID/轮询
轮询 → Job Schema/ID → completed → Experiment Schema/ID → 结果/URL
历史看板 → Dashboard Schema → 既有同配置组规则 → 历史打开
```

元数据未到达时运行按钮不可用；有效元数据进入配置态。历史读取先清空旧产物，再进入 loading；成功后显示该请求的产物，失败只显示错误与空态。运行流开始进入 liveRun；合法事件追加真实轨迹；合法 complete 才替换为最终结果。连接/校验失败时状态为中断/未知，不伪称 Agent 失败或执行取消。页面导航使旧请求失去归属，但后端 Job 可继续，随后可 GET 回读。

本轮对照：此前 HTTP/SSE 有 `as EpisodeArtifact` 等转换，字符串 `success`、非法状态或错 ID 可进入页面；现在同样数据在更新结果前拒绝。正确历史仍显示相同未知费用，未重新计算分数。前端单元检查由 13 增至 28；关键手动路径变成 6 条可运行浏览器回归。

## 失败路径与实际验证

- 数字/布尔类型错误、负数/非整数用量、非 UTC 时间、未知版本、数字费用、非 Decimal 字符串：明确字段校验失败，不回显错误值。
- 历史/Job ID 错配、事件归属错配、重复事件/成对复用同一 Episode、完成顺序不一致：拒绝更新结果。验证不承诺前端重新计算配置哈希。
- HTTP 非 JSON 错误：显示状态码；坏 JSON/无 complete：明确无法读取或连接中断。客户端取消 reader 不代表取消模型请求。
- 损坏恢复列表：可见的列表不完整提示；后端恢复规则保持原样。
- 新建 Job 受理响应被测试 gate 暂缓：期间在同一 SPA 打开看板历史，回复送达后仍保持历史 URL/结果，运行按钮可用。门禁不用“睡够几秒”猜测竞态，等待真实后端受理并控制回复释放。
- Chromium 首轮三个测试在浏览器启动前失败：本机事件日志为 WinError 14001，缺少对应 Chromium 153.0.8010.12 的并行程序集；没有进入业务页面。切换已有 Edge 后三条通过，补齐用例后完整六条通过。不修改系统运行库或安装策略。Zod Mini 转换期间一处语法错误被类型检查检出并修正，最终全量门禁通过。

## 最小实验与交接边界

首次 `uv sync --locked`、`npm.cmd --prefix apps/web ci`；有 Edge 的本机可先设置 `$env:AGENTLABYRINTH_E2E_CHANNEL='msedge'`，再执行统一入口。其他环境默认需要在 apps/web 中执行 `npx playwright install --no-shell chromium`，Linux 首次通常用 `--with-deps`。先停止自己占用的 8000/5173 服务，测试不会接管别人的进程。

学习实验：运行 `npm.cmd test` 找到旧指标测试，把费用改为数字或 success 改为字符串，观察错误；随后运行 `npm.cmd run test:e2e`，读迟到 Job 用例的 gate 和 RequestGeneration，说明“服务受理”与“页面仍属于这个请求”的区别。不要修改固定回归基线来绕过失败。

本轮没有新真实模型调用，没有验证 Linux/GitHub 的 Chromium 运行，也没有第二台电脑、真实 200% 与 Windows 系统减少动效检查；已配置的 CI 必须发布后看到远端结果才算实跑。全局 Token、最终免费模型和课程现场整版签收仍待负责人决定。没有 Docker、数据库或 V0.3；没有提交、推送、Tag 或发布。
