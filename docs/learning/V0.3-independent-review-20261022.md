## 1. 已交付

- `EpisodeReviewArtifact 1.0` 单独保存在 `artifacts/.../reviews/<review_id>.json`，引用源 Episode SHA-256 与冻结评审输入 SHA-256；同一 Episode 可追加多份，不能覆盖。
- 人工复核与 Judge 共用总判断、答案正确性、证据支持、过程安全、说明和 Trace 事件引用。非法引用默认拒绝。
- Fake Judge 只有一次无工具 Provider 调用，覆盖正常、非法 JSON、非法事件引用和 Provider 失败；不修复、不重试，不计入 Agent Token、费用或 Experiment 指标。
- 三个 API 分别负责显式创建、按 ID 回读和按 Episode 列表。GET 只读，不调用 Provider；源 Episode 缺失或哈希改变时拒绝回读。
- Episode 页面并列显示原规则评分和独立复核，支持人工追加、显式 Fake Judge、刷新回读及独立 CSV；Experiment 页面仅在用户展开时读取已有覆盖，不自动创建评审。
- 原 Episode/Experiment/Evaluator/Trace/旧 Experiment CSV 均未修改。

Fake Judge 的 `uncertain/unknown` 是链路演示固定值，不能用作模型质量、Judge 准确率或任务收益结论。真实 Judge 仍须单独授权并固定模型、提示、价格与样本范围。

## 3. 调用链与状态

### 人工

`POST /episode-reviews` → 读取并校验 Episode → 生成不含原 `evaluation` 的冻结输入 → 校验人工量表和事件归属 → 原子新增 Review 文件 → 返回独立产物。

### Fake Judge

显式按钮 → 同一冻结输入 → `provider.generate(messages, tools=[], config)` 一次 → 严格 JSON 解析 → 事件归属校验 → 保存 `completed` 或独立 `failed` 记录。失败不产生 verdict，不修改源 Episode。

### 历史与实验

URL 回读 Episode → GET Review 列表 → 页面展示。Experiment 折叠区展开后，按其保存的 Episode ID 逐一 GET；未评审不补成失败，原图表分母和成功率不变。

## 4. 失败路径

- 无最终提交：Judge拒绝创建；人工仅允许uncertain、答案/证据unknown，过程可按Trace记录，不能补造任务答案。
- 人工空说明/空标识、方法字段混用、外来事件 ID：400/422，不写文件。
- Judge 非 FinalAnswer、非法 JSON或字段：保存 `INVALID_JUDGE_OUTPUT`。
- Judge 引用外来事件：保存 `INVALID_EVENT_REFERENCE`。
- Provider 异常：保存 `JUDGE_PROVIDER_ERROR`；未报告 Token 保持空、费用保持未知。
- Review 文件 ID、源 Episode ID 或源哈希不一致：GET 409，不能展示为可信历史。
- 页面切换 Episode 会取消旧 GET；刷新只 GET，不重新 POST。
