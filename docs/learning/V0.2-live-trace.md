# 单次 Episode 实时 Trace：源码阅读与实验

依据需求 V0.6、Accepted ADR-014。此功能只增加传输和运行中展示，不改变 TraceEvent、Artifact、Evaluator 或历史 Replay 的语义。

## 阅读顺序

1. `packages/application/trace.py`：`JsonTraceRecorder.record` 脱敏、复制并追加事件后，将独立副本交给可选观察回调。
2. `packages/application/runner.py`：开始、Runtime、评分与唯一结束事件仍由原流程负责。
3. `packages/application/checkpoint.py` 与 `apps/api/service.py`：ToolLab 本地走原 Checkpoint；MCP/BFCL 走原 Runner。两条路径都可把同一个回调交给 Recorder。
4. `apps/api/main.py`：新增 `POST /api/v1/episodes/stream`，按顺序推送 `trace`，落盘成功后推送 `complete`；错误推送版本化 `error`。浏览器断开不会取消已启动的服务端任务。
5. `apps/web/src/streamEpisode.ts`：处理跨网络数据块拆开的 SSE 消息，缺少最终产物时拒绝宣称完成。
6. `apps/web/src/App.tsx` → `McpFlowReplay.tsx` → `flowFrames.ts`：运行中用已到达事件逐步添加节点；结束后改用 Artifact 只读回放。BFCL 仍标为函数调用提议。

## 状态与失败路径

点击运行 → `liveRun=running` → 第一条 `TraceEvent` 给出 Episode ID → `MODEL_REQUESTED` 等待上游 → 实际提议/工具事件加入图 → `EPISODE_FINISHED` → `complete` 返回完整 Artifact、显示评分和 Replay。实时画面没有虚构的百分比或阶段耗时，也不显示未记录的 token 流。

流式验证失败时发送 `error`，不会产生虚假的 `complete`。网络断线只说明浏览器失去连接，页面保留最后事件与 Episode ID；后端任务继续运行，稍后可用原 GET 查询已保存产物。若进程本身退出，ToolLab 本地按原 Checkpoint 规则恢复；BFCL/MCP 没有此保证。历史 GET 永远不启动新模型运行。

## 验证记录

- API Fake：流中每条 `trace` 与最终 Artifact.events 顺序和值一致；最后仅一个 `complete`，原 GET 回读相同产物。非法模型只有版本化 `error`，无 `complete`。
- 浏览器 Fake `order-status-001`：Episode `9bd6b972-596c-4572-8f28-381a31c64ba0`，最终 SUCCESS、17 事件；Fake 太快，未能肉眼观察中途逐帧。
- 浏览器真实模型 `coding-minimax-m2.7-free` / BFCL `simple_python_0`：运行中先看到实时模型和校验节点以及 Episode ID `99b2bc6f-5452-4e13-a17a-78d36fec4a50`；结束后显示函数提议 `calculate_triangle_area(base=10,height=5)`、SUCCESS、10 事件。此为一题真实小样本，非稳定性结论。
- 浏览器真实模型同款 / ToolLab `order-status-001`：Episode `7eb9bad7-7696-4263-a3e1-2c42988e6b86`，最终 SUCCESS、2 次模型/2 次工具、17 事件、约 15.6 秒。实际工具节点中途是否连续可见未单独截取；最终 Artifact 与 Replay 正常。
- `tests/unit/test_api.py`、`apps/web/tests/streamEpisode.test.mjs`、前端生产构建、Ruff、mypy 均通过。无需 MCP 服务即可复核上述本地样例。

## 边界

当前只支持单次 Episode 的同一 HTTP 连接。客户端刷新不会补发流；结束后用既有 GET 回读。对照实验与 Resume 暂不实时推送。SSE 事件是已记录 Trace，不是模型原始 token 流，也不能把回放动画当成真实执行。
