# 课堂演示 UI 优化与阅读交接

日期：2026-10-08。需求 V0.6、UI 规范 1.3；任务卡 `docs/tasks/ui-classroom-20261008.md`。基线 `4581ffb`，未提交/推送；保留10月7日复核文档。沿用 ADR-013/014/022/024，只调整现有 Web 呈现。

## 实现与阅读顺序

1. `apps/web/src/traceSteps.ts`：抽出既有工具反馈解析供两个视图复用，不改变字段来源和评分。
2. `apps/web/src/ReadableFields.tsx`：移动既有中文键值展示组件，复用在概览和当前帧摘要；错误码/参数合法/权限补中文标签。
3. `apps/web/src/flowFrames.ts`：按保存顺序投影观察、模型请求/响应、提议、拒绝、执行、返回、状态更新与终止。帧携带原事件下标、当次参数、已返回反馈及关键状态变化；`frameIndexAt` 对无独立帧的事件显示最近前置阶段。
4. `apps/web/src/App.tsx`：`replayIndex` 始终是完整事件数组下标；概览按其所属 Step 显示整步摘要，技术 Trace 按事件显示，流程按阶段显示。切换视图不改原锚点；用户操作步骤/筛选/播放时才选择对应保存事件。新 Episode 从起点开始。
5. `apps/web/src/McpFlowReplay.tsx` / `flowReplay.css`：图旁加入可聚焦、可滚动的当前阶段摘要；失败先显示错误，再显示参数。正常与专注布局均保留控制器，窄屏纵向排列。模型等待取自已收到的 MODEL_REQUESTED；不显示内部思考或推测进度。
6. App 的对照页：已保存结果先于下一次草稿，DOM 与视觉顺序一致；历史模型原值和对照变量常驻，成功率/恢复转化前置，用量/配置折叠。草稿使用本地 JSX 变量在新建/历史两处条件放置，避免 CSS 重排造成键盘顺序不一致；Job 控制和恢复入口没有折进草稿。

## 状态与失败边界

- 回放只读；播放/切换/折叠不发起模型请求或工具执行。历史与草稿保持独立，修改草稿不改已保存的对照标签或指标。
- 提议阶段只保存当次参数，执行开始没有结果；返回阶段才显示该 Call ID 已保存的反馈；环境更新只比较已收到的快照。不得从最终状态或期望答案回填当前帧结果。
- 概览是整步摘要，可能包含该 Step 内较晚事件；流程摘要是事件阶段，两者粒度不同。终点卡明确标注“最终输出 · 已保存”，不伪装为当前阶段已取得的答案。
- INVALID_ARGUMENTS 等拒绝显示“工具未执行”；TOOL_FAILED 保留错误；MCP 仅在已记录远程工具阶段显示网络状态。BFCL 保持“调用提议/记录”语义，不声称执行上游函数。
- 原始 JSON 继续在技术 Trace/“查看当前记录”中提供；缺字段、未知费用/时长不会补零。播放器速度用于阅读，不等于实际耗时；仅正数 duration_ms 作为已记录事件时长展示。
- 手动切换/定位暂停播放；定时器切换视图时清理。减少动效即时关闭运动粒子，保留状态变化与键盘操作。

## 课堂查看顺序与后续交接

1. 先打开已保存对照：看历史模型、两侧成功率、挽救转化；按需展开用量、配置和成对表格。
2. 从成对表格打开对应 Trace；拖动进度或方向键，讲清“模型请求 → 调用提议 → 校验 → 工具返回 → 状态变化”。参数错误处先讲错误码与未执行，再讲下一 Step 的纠正。
3. MCP 已保存示例 `603b2362-2006-42e7-997c-7bd2804d84dc`：选择搜索/读取返回帧，点“专注查看”；明确是历史工具链路回放，不是协议握手抓包。Esc 返回。
4. 切“过程概览/技术 Trace”核查同一步；回到流程位置不重置。需要新运行时再展开草稿；课堂现场模型调用另做临场权限/网络确认，保留清晰标注的 Fake 备用。

接手防错：不要混用事件/分组/筛选下标；不要通过最终状态或任务答案填帧；不要把 BFCL 记录画成真实函数执行；不要折掉 Job 控制；不要用 CSS order 替代历史结果的实际阅读顺序；折叠改动要更新正常用户步骤并保留原断言。继续沿用当前依赖和契约。

全局 Token 上限、模型入口最终收口、真实可用性与第二机器/课程签收仍按原需求单独推进，不能因 UI 验证通过补签 V0.2。
