# V0.2 MCP 网络工具实验

## 阅读顺序与调用链

`docs/adr/ADR-012-mcp-network-pilot.md` → `packages/environments/tool_lab/mcp.py` → `packages/environments/tool_lab/environment.py` → `packages/runtime/session.py` → `apps/api/service.py` → `apps/web/src/App.tsx`。

页面单次运行选择固定文档任务及 `tool_transport=mcp`；Service 构造 `MCPToolLabEnvironment`，RunConfig 记 `tool-lab-mcp-v1`。Agent 看到原有工具 Schema，Session 继续做预算、权限和参数检查；Executor 调用 Environment 绑定的 Handler。Handler 用官方 SDK Client 经 localhost Streamable HTTP 调用独立 MCP Server 的 `search_documents` / `read_document`。服务只从仓库固定 TaskSpec 的 `initial_state.documents` 读取数据；`submit_answer` 仍由本地环境处理。远程读取成功后客户端环境才更新 `acquired_evidence`，Evaluator 仍只认成功的 `TOOL_SUCCEEDED` 证据。

Session 把同步 Environment.step 放入工作线程，避免 MCP 网络调用阻塞异步 Runtime。连接失败和 SDK 错误由 Handler 转成 `TOOL_EXECUTION_ERROR`；Trace 为 `TOOL_STARTED → TOOL_FAILED → EPISODE_FINISHED`。MCP Episode 不走现有仅支持 `tool-lab-m0-v1` 的 Checkpoint/Resume，最终 Artifact 照常落盘。

## 实测与边界（2026-09-24）

使用官方 Python SDK `mcp==2.2.0`，两个进程实际通过 `POST /mcp` 完成 `tools/list`，返回 `search_documents` 和 `read_document`。Fake Provider、`order-status-007`、同一默认 Seed/预算：本地和 MCP 各 SUCCESS、Evaluator true、3 次工具调用，均为 120 prompt / 60 completion tokens；单次实测耗时约 32 ms / 200 ms，不作为统计性性能结论。RunConfig 分别为 `tool-lab-m0-v1` 与 `tool-lab-mcp-v1`，MCP 工具开始事件额外标注 `transport=mcp`。关闭服务后，MCP 为 FAILED `tool_failed: TOOL_EXECUTION_ERROR`，事件顺序完整；同一任务的本地执行仍 SUCCESS。实测样例 Artifact 位于忽略目录 `artifacts/mcp-smoke/`。此结果证明协议与控制链路，不代表公网连接或真实模型成绩。

复现：先运行 `uv run python -m packages.environments.tool_lab.mcp`；另一个终端启动 API/Web，单次运行选 Fake、`order-status-007`、MCP HTTP。比较时将传输切回本地再运行；断开服务后重新运行 MCP，查看失败 Trace。

限制：服务只绑定本机固定端口，未做外部 MCP 服务器发现、鉴权或外部写工具；MCP 路径尚无 Checkpoint/Resume。课程演示前需先启动第三个进程。

追加真实模型小样本（2026-09-24）：`coding-minimax-m2.7-free` 的 Key 级目录可见性经实时查询确认；在文档任务 007、MCP 传输、8000 总 Token 预算下，Episode `c302b854-5a35-4ec7-b1b5-749b417e59e0` SUCCESS、Evaluator true、3 模型调用、3 工具调用、3108 prompt / 280 completion tokens。搜索和读取工具的 Trace 标记 MCP，最终提交为本地工具。仅一题探索，不作长期服务保证或模型能力统计。浏览器点击仍待验收。
