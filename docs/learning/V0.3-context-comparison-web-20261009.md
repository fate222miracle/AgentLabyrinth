# V0.3 上下文网页对照：源码与接手说明

日期：2026-10-09。需求 V0.6，Accepted ADR-026。本轮新增上下文创建与对照入口，保留已有未提交 UI、模型和全局预算工作。最终测试数量、产物路径与预览地址见 current-state。

## 演示顺序

1. 网页“对照实验”选择“上下文：完整历史 vs 最近完整工具轮次”。选择 Fake 与正常场景，保留同一 Runtime、恢复策略、Seed 和预算。
2. 选择 order-status-001 和 order-status-007；右侧窗口设为 1。左侧固定完整历史。运行后看两组成功率与单题表格：订单均通过，文档仅完整历史通过。
3. 打开文档右侧 Trace，在流程视图选择后续“等待模型响应”帧，查看已保存历史/可见/剔除消息数及输入消息字节。完整 Trace 仍包含早期搜索与读取，输入投影只影响 Provider。
4. 返回结果，展开下次配置，将窗口改为 2；历史仍显示窗口 1。只有主动新建运行才产生新的窗口 2 结果；刷新和前进/后退只 GET。
5. 导出 CSV，context_mode / context_max_tool_rounds 对应每侧；纠错挽救字段为空。Fake Token 是模拟用量，消息字节不是 Token 或 HTTP 大小。Fake 遗忘失败不证明真实模型表现。本机演示实际模型调用：001两侧各2次；007完整历史3次、窗口1为6次并MAX_STEPS，说明截短可因循环增加累计调用。

## 阅读顺序与调用链

1. `docs/adr/ADR-026-context-comparison-web.md`：契约、版本和范围。
2. `packages/domain/models.py` 的 ContextPolicy / AgentSpec 与 `packages/runtime/context.py`：已有完整工具轮次投影，无新增实现。
3. `apps/api/schemas.py`：两个入口可选 context_policy；单 Episode 显式策略要求请求 1.3，Experiment 要求 1.5。上下文轴必须给出 recent_tool_rounds，严格整数 1–100。旧版本未设置时仍可读。
4. `apps/api/service.py` 的 execute_episode / prepare_experiment：配置在最后覆盖后进入 AgentSpec1.2；上下文对照从同一 Agent 复制两侧，只改变 context_policy 和身份。其他轴显式策略为两侧固定值。
5. `packages/application/experiment.py`：create_experiment_plan 检查共享模型/Prompt/工具/预算与同 Runtime/恢复策略，冻结新轴计划1.2；verify 再检查新轴策略与版本。正式 Runner/Checkpoint、确定性 Episode ID 和串行隔离复用，完整结果1.4。旧轴版本保持原语义，全局预算兼容新版本。
6. `packages/runtime/session.py` 的 call_model：从完整历史投影，MODEL_REQUESTED.context 保存可见输入诊断；两种 Runtime 共用。不读取私有目标。
7. `packages/application/regression.py` 的 fixed_config 与 `scripts/run_regression.py` 的 preflight：已有策略进入固定指纹，新预检核对每侧策略/窗口，错误配置在重跑前拒绝。
8. `apps/web/src/apiContracts.ts`：新轴/版本/每侧策略校验与挽救指标不可用约束；`App.tsx` 复用 Job 创建、只读导航、成对表格和导出。
9. `McpFlowReplay.tsx` / `ReadableFields.tsx`：当前请求帧只展示保存的 context 诊断，旧记录没有诊断时不补造。

## 状态与失败路径

- 新建 → 校验请求 → 固定计划落盘 → 两侧正式 Episode → 完整结果落盘。请求版错误、窗口非法、上下文轴缺策略或 full 作为右侧均拒绝；平台不默默退回完整历史。
- old recovery/runtime 对照不同上下文仍拒绝，新 context 对照不同 Runtime/纠错策略也拒绝。两侧任务、Seed、单次/整场预算相同。
- 窗口 1 的文档任务可能反复搜索/读取，最终 MAX_STEPS；保留失败评分和 Trace，不将其当作网络故障或自动重试成功。
- 原冻结计划恢复只使用原窗口与完整历史；已完成左侧复用且文件不改写。显式失败重跑保存新 ID、原策略，窗口 1 仍可能失败。
- 达到全局已报告 Token 阈值停止下一 Episode，保留半对和计划，不补造完整评分。未知用量按 ADR-025 停止。费用与预算的既有边界未扩大。
- 结果读取保留旧 baseline/recovery 字段表示左/右。上下文轴 retry_eligible、三个挽救聚合字段 null，recovered=false；网页无挽救率，CSV 空值。

没有新依赖、数据库、第二框架或长链任务；不自动扩大到真实 Seed×Repeat。下一步可单独安排一个可用真实模型的小样本和课程实机演示，继续把真实结果、供应商波动与Fake机制分开记录。V0.2整版现场签收、第二机器/系统辅助功能与远端CI仍待，不自动提交推送。
