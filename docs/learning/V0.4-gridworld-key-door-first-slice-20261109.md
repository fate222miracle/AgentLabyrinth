# V0.4 GridWorld 首片：Environment 与状态隔离

## 本切片解决的问题

ToolLab 验证工具交互，但不覆盖空间移动、局部可观测、钥匙/门状态变化和探索记忆。GridWorld 首片用固定钥匙门地图验证这些能力，同时避免服务端全图和真实资源状态通过模型输入、Trace 或最终 Episode 状态泄露。

本交付包含环境规则、Fake 单次 API/SSE/Web 实时地图、SQLite 跨进程恢复和历史只读回读。所有运行使用固定 Fake 行动序列；没有真实模型/Judge 请求，也不据此声称模型规划收益。

## 主调用链

```text
run_episode
  -> HandwrittenRuntime.run_resumable
    -> EpisodeSession.observe
      -> Environment.reset
      -> 私有 snapshot 保存到 Session.last_state
      -> public_state 写入初始 Observation / Trace
    -> model request 与预算记账
    -> Schema / 权限校验
    -> Environment.step -> ToolExecutor -> 确定性动作
    -> 私有 snapshot 更新 checkpoint
    -> public_state 更新 Observation / ENVIRONMENT_UPDATED
  -> Evaluator 读取 EpisodeResult 内的权威终态
  -> Runner 把最终 Episode.final_state 替换为 public_state
  -> EpisodeService 保存结束产物 / SSE complete
  -> Web 按已到达事件前缀显示地图；GET /episodes/{id} 只读回放
```

### 关键状态变化

- 服务端状态保存当前位置、钥匙可用/持有、门是否打开、动作数与终态。
- Agent 状态保存当前位置、库存、当前视野和曾发现格子的最后已知事实。四条正交射线每条最多两格；墙和关闭门会挡住更远单元。
- 任务固定为 7×5 地图，Seed 只记录、不改变布局。标准通关路线为 8 个环境动作。
- `snapshot()` 与 `public_state()` 彼此独立。Evaluator 在 Runner 内读取私有终态；Observation、Provider 输入、Trace 和最终公开 Episode state 不包含私有恢复字段。

## 失败与停止条件

- 规则内拒绝（例如撞墙、未拿钥匙拾取、目标不可用）会递增环境动作和非法动作计数，产生结构化 `TOOL_SUCCEEDED` 回执，不变成工具/服务器故障。
- Schema/权限错误不会成为游戏动作。真正的工具或环境错误使用既有 `StepResult.error` 语义停止。
- 恢复前先校验版本、任务/Seed、状态组合、当前位置、最后动作、当前视野和已知格。恢复仅使用保存的 Agent 知识，不从全图补齐探索记忆。
- 第 16 个动作仍可成功；第 16 个未成功动作后不发第 17 次 Provider 请求。
- 单次 completion=800 可执行当前合法动作；801 完整记账并拒绝动作。累计 Token 正好达 16,000 时完成当前合法动作（包含规则内拒绝）后停止请求；累计超限时完整记账并拒绝该动作。completion 累计 12,800 亦覆盖等值/超值。
- Evaluator 或 `public_state()` 失败时，Runner 仅保留安全公开状态或空状态，绝不使用私有快照作为公开回退。

## Fake 实时产品闭环

`POST /api/v1/episodes/stream` 是唯一开始运行的操作。GridWorld suite 在 API 校验层锁定 Fake、handwritten、固定任务、16 轮/模型/工具调用、800 completion tokens、16,000 累计 tokens 和 300 秒预算；客户端不能改成真实 Provider 或提高限额。SSE 每个 Trace 事件由 Runner 实际追加后发出，完成事件携带同一 Episode 的产物；历史详情使用 GET，不重跑模型或环境。

Web 的 `GridWorldMap` 只从 `OBSERVATION_CREATED.initial_state`、`TOOL_SUCCEEDED.observation.world` 和 `ENVIRONMENT_UPDATED.state` 读取投影，并按 Replay cursor 限定前缀。未知格保持空白。规则拒绝从 `TOOL_SUCCEEDED.observation.action_result` 读取，并显示为游戏反馈，不转换成工具/服务故障。最终评测与 Episode 产物独立于 Replay cursor。

## SQLite 跨进程恢复

测试通过独立子进程创建 SQLite checkpoint，再以 `os._exit(0)` 模拟进程突然退出。两个恢复点分别在 3 个动作后（已持钥匙、门未开）和 5 个动作后（门已开、钥匙已消耗）；重启后的 `EpisodeService` 使用原 Episode ID、已保存 Fake 场景和 `BudgetState.model_call_count` 重建运行。恢复后不重做已完成模型/工具调用，旧 Trace 是新 Trace 的完整前缀，最终 8 个工具动作通关，预算计数未重置。

Session 保存私有 `last_state`；Trace 保存可公开状态。恢复会先验证/重建私有 Environment，再计算 `public_state()` 并与事件流最后保存的公开投影逐项比较。合法但篡改后的私有探索时间若与 Trace 视图不同，恢复被拒绝。SQLite 完成产物只保存公开 `episode.final_state` 和 Agent 可见 Trace；普通 GET 不暴露 `has_key`、`door_open`、`visible_cells` 或 checkpoint。

uv --cache-dir .uv-cache run --locked python -m pytest tests/integration/test_gridworld_product.py tests/unit/test_gridworld_environment.py tests/contract -q

测试使用本地脚本化 Provider，不访问真实模型。环境规则覆盖固定路线、任意 Seed 下固定地图、遮挡与已知格、规则内拒绝、错误工具提案、任务元数据拒绝、快照篡改/恢复、Provider/Trace/产物隐私扫描、Evaluator/public projection 故障 fail-closed、800/801、累计 Token、16 轮、时间配置及估算费用边界。产品集成测试覆盖 SSE/GET、冻结预算、私有/公开状态一致性、SQLite 故障退出恢复及公开历史记录。最终完整质量门禁：`uv --cache-dir .uv-cache run --locked python -m scripts.check` 退出 0，804 Python passed（1 条既有警告）、132 文件 Ruff/Mypy、Regression 22 格/0 regressions、Node 53/53、系统 Edge 88/88、npm audit 0 vulnerabilities；质量产物为 `artifacts/quality/df5a1047-17eb-4806-b509-4f40e4848cd9/`，Edge 运行 `artifacts/playwright/b54dc936-e4fd-4768-becd-1c5c3cdcdc68/`。门禁运行时使用隔离端口 19800/19801、Edge 与 `NODE_OPTIONS=--max-old-space-size=512`；本机结果不是远端 CI。

## 当前不解决

- 不含 GridWorld Experiment 对照、历史迁移或观察者全局视图。
- 不支持 `communicate`、多个 Agent、随机地图、地图编辑器、资源合成、Planning/Reflection 或真实模型/Judge。
- 单张地图与脚本化 Provider 仅验证机制，不证明模型规划收益、记忆收益或泛化能力；GridWorld Experiment 和真实模型评估不在本首片。

## 阅读检查问题

1. 为什么 Session checkpoint 保存私有 `snapshot()`，而 Trace 和最终 Episode 使用 `public_state()`？
2. 恢复时如何使用最后一个公开 Trace 投影验证 Agent 知识投影没有与私有 checkpoint 分叉？
3. 累计 Token 正好到限与超过上限时，当前响应的动作分别如何处理？为什么之后不会再发模型请求？
4. 为什么已探索格子使用最后已知事实，而不是每次按权威全图刷新？
5. 如何验证规则内非法行动不是 `TOOL_FAILED`，又如何区分真正 Environment 执行故障？
6. Evaluator 为什么需要私有权威终态，而前端/Replay 不需要它？
