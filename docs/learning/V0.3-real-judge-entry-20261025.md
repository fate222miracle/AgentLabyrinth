# 真实 Judge 成品入口与能力证据收敛

日期：2026-10-25。SSOT V0.6、负责人明确确认的 ADR-040。负责人指出人工/模拟面板不能提供所需的大模型评审、看不到组件加入前后的效果。本轮撤下正常页面的人工填写和 Fake 生成，接入真实 Judge；保留旧 API 和历史，不删除未知改动、21题或已有产物，不提交 GitHub。

## 1. 产品现在提供什么

“大模型评审”选择当前真实模型后，用户显式点击才发起一次请求；无模型/无最终提交时说明原因，不回落 Fake，不自动重试。呈现判断、理由、三个维度和引用事件；与原规则评分显示一致/分歧/无法比较，不覆盖原评价。版本和独立用量仍按需展开。

旧人工/模拟记录仅归档提示和完整 CSV/API 可追溯，不再作为主区大模型判断；删除了人工表单、模拟操作和对应未使用样式。对照复核摘要只统计已保存的真实模型记录，不把人工/Fake当大模型评审，也不改变 Experiment 原成功率或图表分母。

**Judge 是辅助评估，不是执行能力优化。** 它提供解释和问题定位，并不提高同一运行的成功率。没有真实对照结果时，不能将组件存在或画面丰富解释为性能提升。

## 2. 源码顺序与调用链

1. `apps/api/schemas.py::CreateEpisodeReviewRequest`：1.1仅允许显式aihubmix/model的llm_judge，禁止human/judge_scenario；1.0保留原人工/Fake语义并拒绝新字段（包括null），不把旧请求悄悄变为真实请求。
2. `apps/api/service.py::create_episode_review`：读取源Episode → 检查最终提交 → 冻结输入≤65536 UTF-8字节 → 后端白名单/现有目录及例外 → 现有AIHubMix Provider（30秒/13秒起始间隔）→ `ModelConfig(max_tokens=800)` → 原 `create_judge_review` → 独立原子保存。字节上限不是Token预算或HTTP包大小，超限拒绝而非截证据。
3. `packages/application/review.py`：沿用episode-review-v2，不注入原evaluation，一次无工具调用；严格JSON/枚举/说明长度/事件归属均不放宽，Provider/格式/引用失败仍分别留档，无自动修复、剥离、二次请求或原始推理落盘。原ReviewArtifact1.0与旧v1记录保持。
4. `apps/web/src/App.tsx` → `EpisodeReviewPanel.tsx`：接现有模型目录，只显示真实模型；加载只GET，显式POST1.1且核对返回Episode/模型/provider。等待时按钮禁用，HTTP失败显示错误，不伪造成功；源运行和下一次草稿隔离。原CSV完整列/来源/未知费用/BOM/公式防护保留。
5. `ExperimentReviewSummary.tsx`只GET既有模型记录；`index.css`使用原生折叠、紧凑模型选择和已有配色，窄屏单列、可键盘操作；未增加依赖。
