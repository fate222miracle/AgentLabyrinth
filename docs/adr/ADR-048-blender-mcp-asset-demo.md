# ADR-048 Blender MCP 资产制作演示

2026-11-11，负责人确认 V0.4 收工，并要求制作 Blender + MCP 演示。

使用项目现有的 MCP SDK 建立本机 Streamable HTTP 服务，提供一个固定的 GridWorld 资产制作工具。服务通过 Blender 官方后台命令执行仓库中可审查的建模脚本。工具接受固定的钥匙门资产场景，产物放在独立运行目录。每次调用生成 Blender 源文件、GLB 资产和预览图。

独立演示页通过项目的 MCP 客户端完成连接、工具发现与工具调用，并显示实际请求、返回值和用时。Blender 的场景用于资产展示。游戏中的位置、开门、拾取和回放仍由 GridWorld 事件决定，后续三维舞台可加载这里生成的资产。

首版验收以本机实际 MCP 调用成功和可打开的资产为准。保留连接或 Blender 执行失败的诊断。此处范围为 V0.5 的首个演示，完整版本见需求 V0.6 的版本规划。

## Q 版尤诺角色与动作

负责人确认先制作可动的 Q 版尤诺，再将其接入 GridWorld 三维舞台。资产工具增加固定角色 `iuno-chibi`，使用 Blender 生成蒙皮骨骼、动作及预览。动画包括待机、原地走路、左右各转 90 度、拾取及开门。资产原点在脚底，角色在 glTF 坐标中朝 +Z。走路、拾取和开门片段不改变世界格坐标。

三维舞台接收现有 `GridWorldMap` 已校验的公开状态。一次被接受的新 `action_count` 只消费一次。位移和门、钥匙变化以公开状态为准，失败动作与跳转历史不得触发虚假位移或交互。三维视图使用相同的 Trace 前缀，未知格继续不可见。

2026-11-12，负责人确认将现有角色与场景迁入 GridWorld。前端按需加载 Three.js 的 WebGL 渲染器、GLB 加载器和骨骼动画播放器，复用 Blender 导出的角色和墙、地面、门、钥匙、目标原型。展示按公开坐标实例化原型，资产展示图中的原始摆位不参与游戏布局。二维地图保留用于手动切换与渲染失败回退。应用继续沿用现有 Trace、历史和评测规则。
