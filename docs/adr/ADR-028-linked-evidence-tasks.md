# ADR-028：跨文档依赖与完整证据场景

状态：Accepted，2026-10-12。负责人授权增加少量复杂场景，强调实验价值与可用成品；本轮不提交GitHub。

## 问题和假设

现有文档007–009只有搜索、单文档阅读和提交，无法覆盖多份关联证据。新增三个独立自建场景：退货资格、配送争议、退款批准。分别关联3/4/5份文件，包含旧版或其他案件的干扰项；有效结论来自最后的审批记录，提交必须引用整条依据链。它们验证引用跟踪、证据完整性和上下文裁剪风险，不代表一般商业推理或外部Benchmark成绩。

假设：裁掉较早阅读记录后，依赖当前可见阅读内容的受控Fake会漏交证据；full或足够窗口保留完整证据。该工程现象不是模型记忆能力结论。真实模型可以从现有工具返回的累计证据列表恢复ID，未必失败；如实记录，不人为隐藏它。

## 决策

- 原12题JSON不改，新增到固定任务目录的long_chain子目录，继续使用tool_lab_core公开Suite，类别evidence_chain、来源native_long_chain/development。API和固定MCP服务递归读取受控目录，输入只按名称或UUID查目录，不解释路径；重名/重复ID拒绝。
- 复用search_documents/read_document/submit_answer、现有环境快照和order_status_v1评分。最终状态值精确匹配，证据ID按字典序完整提交，必须由成功阅读事件实际获得。无需强制中间行动顺序或固定调用数；更短的合法路径允许通过。早交、漏证据、猜答案、错案证据保持失败。
- 文档正文以Next document: ID指向下一份依据；终端正文有Status: value。公开描述说明任务目标和证据要求，不暴露私有goal_conditions。工具参数Schema/版本与评分不变。
- 新公开task_kind=document_chain只在新任务使用。Fake从可见公开工具反馈跟随引用，终端解析状态，收集可见已读证据；不读取私有目标、不按任务ID或调用次数写答案。保留原document路径，旧Fake基线不变。
- 新任务上限10步、默认20000 Token。MiniMax真实三文档任务最后一轮报告9493总Token，旧8000不足；新Task版本1.1.0提高默认预算，旧产物保持8000与原版本。新API Agent预置模型/工具次数与步数为10，只对含evidence_chain任务的新请求应用；显式单次max_steps及Token仍优先。两侧相同，实际预算写入Agent哈希，旧恢复/冻结计划按保存Agent执行。原题和旧基线预算不变。
- Web复用任务卡、SSE实时节点、证据/输出呈现、对照和历史读取，新增中文类别与自建来源说明。不只交付隐藏的测试数据。
- 真实Flash首轮返回多工具提议，被原单行动契约拒绝。Provider带工具时显式发送OpenAI兼容参数parallel_tool_calls=false，匹配既有每轮单行动边界；如供应商忽略仍保留MULTIPLE_TOOL_CALLS拒绝，不丢弃其余调用、不自动重试、不扩并行执行。单独记录修复前失败与修复后小样本；未知用量不按零作结论。

## 验收

两Runtime全部新题、短窗口漏证据与足够窗口、原12题/四基线；提前提交、伪造/干扰证据、预算停止、独立Episode状态与恢复，API/SSE/GET、Web实跑/刷新零POST、MCP只读目录一致。完整质量门禁和一个可用真实模型一题的小样本，输出实际ID/结果；失败也保留，不调低评分。原任务文件哈希不变。

独立自编模拟数据，不称外部真实数据集。原BFCL保持来源和协议；数据库、写业务工具、自动Planning/Memory、LLM Judge与大规模数据接入留给有独立问题的后续ADR。
