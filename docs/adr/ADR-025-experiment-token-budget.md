# ADR-025：跨 Episode 的全局 Token 预算

状态：Accepted（2026-10-08）。负责人在版本复核后明确授权按建议继续开发；本项补齐 V0.6 FR-08，不启动其他 V0.3 能力。

## 决策

1. 增加可选 `max_total_tokens`，严格正整数，最大 1,000,000,000。累计同一 Experiment 全部侧别、任务、Seed、Repeat 的已报告输入加输出 Token。旧 `token_budget` 继续表示每 Episode 上限，未设置新字段的行为、配置与哈希保持不变；Fake 模拟 Token 单独标识，不能当真实用量。
2. 采用 **Episode 边界准入预算**，不是硬性 Token 上限：已报告累计达到阈值后，不启动或恢复下一未完成 Episode。在途 Episode 可超过阈值，不修改两侧单次预算、不截断工具事务、不自动补齐半对实验。若最后一个 Episode 完成时超额，允许形成完整报告，保留实际累计用量；不宣称未超额。
3. 复用原计划、确定性 Episode ID、完整产物和安全点作为用量账本，不另设数据库或可漂移计数器。执行前验证所有已存在矩阵产物/安全点的身份、来源及 Trace/用量一致性；完整产物优先于同 ID 安全点，单个 ID 只计一次。恢复安全点时，其已有用量计入总额；完成后以该 Episode 完整累计替换，不重复加总。失败 Episode 已报告用量也计入；新 ID 的显式单题重跑不属于原冻结矩阵。
4. 请求次数与已报告响应次数不一致，或 Trace 用量与结果/安全点不一致时停止后续执行，错误 `EXPERIMENT_TOKEN_USAGE_UNKNOWN`。不能把未报告请求（包括超时、解析错误、429）当零。进程退出后安全点以外的在途请求没有落盘记录，本预算无法证明实际供应商总消耗；不作恰好一次或实际账单保证。
5. 达到阈值为 `EXPERIMENT_TOKEN_BUDGET_EXCEEDED`。Job 标 failed，完整 Episode 与冻结计划保留；没有伪造完整 Pair/评分。原计划预算不可提高或通过恢复清零，用户提高预算须创建新实验。最后半对可按已保存 Episode ID 只读查看。
6. 请求 schema 1.4、启用新预算的计划 1.1 / 完整 Experiment 1.3；旧请求/计划/产物继续可读。新预算进入冻结计划哈希、最终配置哈希与回归比较指纹。网页新增预算置于原“种子与预算设置”，与单次 Token 和参考美元明确区分；历史仅展示保存值、不读取草稿。

已结束的安全点（next_node=end）可以零额外模型调用地发布最终产物，即使累计达到阈值；随后下一侧仍受准入限制。这不属于继续执行未完成模型循环。

## 验证与边界

检查严格参数、累计跨两侧/Seed/Repeat、达到与超过边界、失败已报告用量、未知响应、安全点恢复与重复计数、来源冲突、旧哈希/回归兼容、Job 错误与只读刷新。复用 Fake 服务自动测试，不扩大真实批量调用。算法重建一次矩阵账本，随后只更新当前 Episode；仅支持当前本地单进程计划，不支持跨 Job 共享账号预算或多 worker 原子准入。

回滚时关闭新预算的新建入口，保留新版本读取，不能将已保存预算删除或抬高后继续原计划。
