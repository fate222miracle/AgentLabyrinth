# ADR-040：移除演示型复核操作，接入真实模型 Judge

- 状态：**Accepted，负责人2026-10-25明确确认“按 ADR-040 实现真实 Judge”**
- 日期：2026-10-25
- 依据：需求 V0.6 §0.3/§19、ADR-039；负责人要求真正的大模型 Judge，删除不能体现价值的面板。

## 1. 实际问题与立即处理

现有公开 POST 只生成 Fake Judge；人工表单记录的是人的意见，不会分析 Agent。它们可以测试机制或留标注，但对负责人当前“让模型评审任务”的目标没有直接交付价值。改标题、折叠字段没有解决能力缺失。

立即移除正常产品页面的人工填写和模拟生成操作，以及无真实模型记录时的大块空白面板。已有人工/Fake/真实产物和旧 API 保留兼容，不删除文件或改历史评分；测试覆盖旧 API 即可，不必让课堂用户看到开发测试工具。

## 2. 真实 Judge 的价值与限制

Judge 只作运行后的辅助诊断：解释答案是否符合任务、实际证据是否支持结论、工具使用是否合规，引用保存 Trace 中的事件。它不让执行任务的 Agent 变聪明，不直接提高任务成功率。规则明确的题仍以原确定性评分为主，模型判断可能误判，和规则有分歧时并列显示，不覆盖原指标。

Memory/Planning 是否有效必须另用同任务、同模型、同预算的有/无组件对照。当前 Memory 有真实单对探索，Planning 尚无真实效果证据；不能用 Fake 对照或新增 Judge 的画面证明收益。本 ADR 不新增对照轴、不执行批量测试。

## 3. 提议一次确认的产品协议

1. `CreateEpisodeReviewRequest`新增 **1.1**，仍用原 POST。仅 `method=llm_judge`；显式必填 `judge_provider=aihubmix`、`judge_model=<白名单模型ID>`；禁止 `human` 和 `judge_scenario`。版本1.0保留原人工/Fake语义，拒绝新字段，不静默将旧调用改成收费/真实请求。
2. 后端只接现有 Key、已有白名单/目录例外校验和 `AIHubMixModelProvider`，不装 SDK、不添加依赖。先确认源 Episode 和最终提交存在，再做模型准入；不因用户输入任意地址或型号绕过限制。
3. 复用 `create_judge_review`、当前 `episode-review-v2` 和原 `JudgeOutput`，最多一次无工具请求，无自动重试/修复/剥离；原引用校验、失败留档不变。单次输出上限 **800 Token**，Provider超时 **30秒**，沿原13秒起始间隔。冻结评审输入超过 **65536 UTF-8字节**时在调用前拒绝，不裁剪证据；字节限制不是Token预算。
4. 原 `EpisodeReviewArtifact1.0`、已保存v1/v2与CSV列保持。评审Token/未知费用独立显示，不计入 Agent/Experiment预算，不存原始推理响应。
5. 正常页面为紧凑“模型评审”：选择现有真实模型 → 明确提示单次真实请求及独立用量 → 用户显式点击“评审本次结果”。无提交/无可选模型时禁用并解释原因；不自动运行、刷新不POST、不回落Fake。正常页面不再提供人工/Fake创建操作。
6. 历史真实评审展示结论、理由、引用的事件及“与规则一致/存在分歧/无法比较”，不是准确率；旧人工/Fake记录仅在有历史时折叠归档，完整导出保留来源。对照页仅在有真实评审时显示相应内容，空模块不占版面。
