# ADR-050 GridWorld 模型对比

2026-11-13，负责人要求开始实现模型对比。第一阶段在实验中心展示已保存的 GridWorld 运行，沿用 SQLite 及只读 Episode 接口。原策略实验可在同页切换，旧地址可继续读取。后续批次调度及双局 Judge 独立验收。

## 第一阶段契约

- `GET /api/v1/episodes/gridworld-comparison` 返回版本 1.0、最近 100 条已保存 GridWorld Episode 的摘要及跳过数。数据来源为 SQLite；摘要使用现有完整性校验，只包含公开结果和配置。目录读取、选组、选两局、切换页面和刷新只读。
- 比较组指纹由保存的任务、运行配置、评测器版本和 Agent 配置计算。排除 Agent 展示名和模型 ID，保留 Provider、模型请求参数及其他配置。来自不同设置的记录各自成组。按模型取组内最新一局，选择两行读取各自完整 Trace；无模型响应的用量显示未知。该口径表示保存配置一致，未记录的网关环境仍可能有差异。
- 双局展示通关、动作、规则拒绝、Token、耗时，以及从已保存公开 Trace 得出的路线与拾钥匙、开门步数。回放链接沿用 GridWorld 详情。

## 第二阶段 双局 Judge

状态：**Accepted，负责人明确同意按 ADR-050 第二阶段实施**。项目现有单局 Judge 依赖最终提交，GridWorld 评审以行动轨迹作为证据。

### 准入与请求

- `POST /api/v1/gridworld-comparison-reviews` 接收 `schema_version="1.0"`、`episode_ids=[UUID, UUID]`、`judge_model`。来源必须是两条通过现有完整性校验、已完成、同比较组的 GridWorld 真实模型运行，且两局模型不同。复用对比首页的指纹计算。评审模型复用单局 Judge 的白名单、目录准入与 AIHubMix Provider，必须与两局模型不同。未通关的已结束运行可以评审。两局均无环境动作时停在客观结果展示，创建评审前拒绝。
- 按 UUID 固定 A、B 顺序。评审请求只发送关卡目标、两局公开指标、起点、每次行动后的公开坐标、动作名、是否被规则接受、标准反馈码及终止原因。每条证据包含对应 Trace 的 UUID 和步号。组装时不包含模型名、运行 ID、原始 Prompt、推理文本、工具自由文本、私有快照或完整地图。用量只在报告完整时作为精确指标。缺少来源或投影不完整时拒绝，投影 UTF-8 超过 16,384 字节时拒绝。该阈值是序列化大小。
- 单次显式触发，无工具、无自动重试，4,096 输出 Token、双局 60 秒 Provider 超时、13 秒请求间隔与 MiniMax 推理字段分离设置。格式错误、引用错误、请求超时与其他 Provider 失败各自保存错误码及上游已报告用量。旧记录沿用原错误码。

### 评审结果与保存

- 提示版本 `gridworld-pair-review-v1`。输出严格 JSON 对象，包含 `assessment`（`a`、`b`、`tradeoff`、`insufficient`）、`rationale`（非空中文说明，最多 1,200 字符）、`citations`（最多 8 条，每条为 `side` 与 `event_id`）。必须解释路径行为或资源取舍。引用只能取对应一侧实际送给 Judge 的事件。两侧都有动作证据时，明确偏向一侧或说明取舍须各引用至少一条。上游错误或缺证据应保留不确定性，耗时与 Token 是各局观测结果。
- 独立新增 SQLite 表 `gridworld_comparison_reviews`，以评审 UUID 为主键、以规范化双局键建索引，保存版本化 JSON 与摘要校验值。Alembic 追加建表，旧表和历史记录保留。记录包含 A/B 源 Episode ID 与内容哈希、比较组指纹、评审输入哈希、评审模型、提示版本、时间、成功输出或失败码、已报告用量及费用。Agent 评分与用量继续由原记录展示。
- `GET /api/v1/gridworld-comparison-reviews?episode_a=UUID&episode_b=UUID` 返回这一对的最近 20 条评审及校验跳过数，交换参数顺序回读同一结果。读取检查记录和两局来源。页面在并排路线下提供折叠区，显示评审模型、结论、理由、带 A/B 与步号的引用、独立用量和失败原因。选局、刷新、展开与历史回读只发 GET，选择模型并点击评审才发 POST。

### 开发顺序与验收

1. 将比较组计算提取为列表和评审共用函数，实现公开事件投影及引用校验。
2. 接入现有模型准入、单次调用、独立保存与 GET，验证两局规则评分和来源保持一致。
3. 接入双局页面，覆盖跨组、自评、同模型、无动作、错误引用、输出截断、断线、SQLite 重启回读及页面切换。真实请求由用户在产品中显式触发，开发验证使用替身。

只读可行性验证已完成。两条回廊档案室历史（`8f547b35…` 与 `301ac295…`）的保存配置指纹一致。共 272 条 Trace 事件中有 38 条有效行动后状态，与各局规则动作计数相符。一次本地试算将公开行动、终止引用和运行摘要压至约 5.9 KB。该数字是样本投影大小。

本地已实施。最终投影使用相同两条历史为 6,053 字节。通过 74 项定向 Python、54 项 Web 单元、25 项 Edge 定向、Ruff、Mypy、前端类型检查和构建。评审结果由替身验证，真实历史在本地预览验证选局、候选模型及只读回查。开发期间未发真实 Judge 请求。

## 第三阶段 四模型批次

负责人要求完成同配置四模型批次和 Judge 分析改进。批次固定「回廊档案室」当前真实配置、Seed 1、24 步、330 秒、单次最多 2,048 输出 Token、160,000 累计输入 Token 的现有运行阈值，保留最近两轮工具上下文。四个固定候选为 MiniMax M2.7、MiniMax M3、GLM 5.3、GLM 5.3 Flash，按固定顺序各执行一局。合计配置的输入阈值为 640,000，输出上限合计 196,608；输入用量在响应后核对，阈值不构成供应商硬封顶。用户显式点击后才发起真实批次，本次开发用替身验证。

新增 `POST /api/v1/gridworld-batches` 受理及 `GET /api/v1/gridworld-batches` 查询。计划先以原子写入的本地清单持久化，包含冻结配置、每局模型及预分配 Episode ID。每个 Episode 仍使用现有 SQLite，批次清单随本机产物目录保留。任一时刻同一服务仅执行一批。单局未通关、网络异常、目录不可用、服务中断和未开始分别展示，不自动重试或在重启后续跑。已保存的结果可在实验中心限定为本批数据，再选两局评审。

## 双局 Judge 分析改进

新增 `gridworld-pair-review-v2`。仍使用原结果 JSON 和引用校验。要求用自然中文直接回答哪一个决策造成差异、该决策在当时的局部视野下是否合理，以及单次证据能支持到哪一步。优先引用分歧发生的动作，避免复述表格和完整路线，禁用未经验证的全局最优结论。增加动作前可见的相邻格类型、动作后的新发现格数和重复到达标记，使用观察到的轨迹推导，不发送完整地图或未见状态。历史 v1 按原投影回查。
