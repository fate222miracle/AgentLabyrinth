# ADR-033：有界多工具响应与顺序执行

状态：Accepted，2026-10-19。负责人明确要求完成多工具调用、兼容单工具并同步必要UI，授权替代此前只纠正为单工具的候选。依据需求V0.6§0.3/§6/§19；不提交GitHub。

## 事实与决定

ADR-032真实探索第三轮MULTIPLE_TOOL_CALLS，旧Provider/ModelResponse/Session按单行动拒绝，未证明记忆失效。新增显式、版本化的serial模式，保留single及无配置的旧行为。批次是同一模型响应，不代表并发；本次固定最多8个只读调用，按返回顺序执行，写工具/submit仍单独调用。新网页ToolLab默认serial，可切严格single；BFCL固定原single，避免改变单函数Benchmark评分。

ModelConfig1.1增加tool_call_mode（single/serial），旧1.0不带字段且序列化/哈希保持。ModelResponse1.1增加tool_call_batch，2–8个ToolCall，不截断、猜测参数或合并Call ID；单调用仍旧形状。Episode请求1.4、Experiment请求1.7显式要求模式，旧版本拒绝新字段并保留原默认。Agent/冻结计划/Artifact外层不升级，使用有独立版本的ModelConfig；同轴两侧模型配置完全相同。历史与失败重跑/恢复按保存模式，不按最新草稿升级。

任务JSON原文件不改；新serial ToolLab运行冻结一个+serial-v1执行变体，记录source_task_version/tool_call_protocol，替换原“每轮只一个调用”约束为本批规则，评分/私有目标/资料不变。全历史、工具和任务版本参与比较指纹；旧任务和BFCL不静默改协议。

## 校验、执行与预算

整个批次先提议/校验，未知/禁止/重复ID、非只读、超过剩余工具预算均在任何执行前终止。参数错误在原recovery策略下最多纠正一次，整批不执行，给每个调用匹配错误/取消反馈后回到模型；未知/禁止/重复及二次参数错不重试。每轮一次模型/Step计数，每个实际工具分别计数与Trace；不强制把并列调用当依赖规划，后一个依赖前一个返回时应另起模型轮次。

通过预检后按序逐个执行。工具错误/超时/预算终止后不执行剩余项，无事务回滚承诺。每项结果/环境快照保存后才推进待执行队列，安全点Session1.1可存execute节点及剩余队列，恢复核对历史未完成轮次、Call ID/参数/权限与Trace，不重做已完成项。原Session1.0仍可读、原单调用安全点不变。工具执行与落盘之间的进程死亡窗口仍不保证外部写幂等；本批只读。

近期窗口N依旧指一个assistant响应及其所有匹配tool反馈，整轮保留/丢弃；记忆按每个成功工具返回准入。既有project_context已支持多个tool_calls，无须新算法。不把未完成批次送回模型。

Provider解析失败若上游返回可信非负整数用量，在新ModelConfig1.1模式记录被拒响应和用量；缺失保持未知，预算准入不放宽，不保存密钥或原始回复。旧1.0失败路径保持。

## UI和验收

配置提供调用模式与短说明，历史显示保存模式；实时/回放每个Call ID独立节点，同Step明确“本轮多个工具/顺序执行”，概览不能只展示首工具；资料只在对应成功返回时已读。CSV和比较指纹可区分模式，记忆实验两侧同模式；历史刷新/导航仅GET。

验收：两Runtime、单/批兼容、全批预检零执行、Call ID/权限/参数/剩余工具预算、第二项失败/超时、逐工具安全点跨进程恢复与篡改拒绝、窗口整轮/成功记忆、MCP/local、BFCL/旧哈希/旧回归、网页实时/历史/四视口/reduce/CSV及完整门禁。再用一个免费模型一题两侧有界复测，保留所有结果，不重跑旧失败或静默改变它的模式。无新依赖、数据库、Planning或多Agent。
