# ADR-027：可信模型目录例外与通用提交工具说明

## 状态

Accepted（2026-10-11；负责人明确授权处理实测发现的两个共性问题）。依据需求 V0.6、ADR-006/010/019/024。不是新增模型对照轴或版本签收。

## 证据

GLM 5.3 Flash 两次目录 GET 均缺失，但 BFCL、订单和文档六次真实响应 HTTP200；Kimi K3 目录可见却无通道。M3 读取文档后误提订单查询；submit_answer 的描述仍要求 query_records 证据，与文档任务不一致，尚无因果消融证明。

## 决策

1. 继续默认使用目录预检。共享候选 JSON 可对显式实测型号设置内部布尔 `allow_catalog_missing: true`；本次仅 GLM Flash 开启。字段不进入公共 DTO，客户端不得提交。只有配置中的同一 AIHubMix ID、精确 true 才有效，不放行任意模型、付费字符串或目录外请求。元信息与所有执行/恢复/重跑入口复用同一例外读取。目录失败仍如实标记 unavailable，例外候选可见并提示目录未确认，不自动换模型或重试。
2. 将 M3 与 Flash 作为带日期的实验候选加入正式列表，默认型号保持 M2.7；Kimi 本次未通过，保留文档失败证据，不加入新候选。历史型号及原值不覆盖。
3. 新 API ToolLab 单次及对照使用工具集 `v1.1.0`：submit_answer 的 answer 从实际查询记录或读取文档复制，evidence 从 query_records/read_document 成功返回的 evidence_id 复制，不允许编造或以搜索摘要替代阅读。只改描述及 submit_answer 工具版本，不改字段、严格参数验证、权限、预算、执行和评分。
4. 默认环境/固定 CLI 回归保留旧 `v1.0.0`；新工具集显式传入本地或 MCP 环境。新 Agent 哈希记录实际工具集；Experiment 两侧固定同一版本。旧安全点、旧失败重跑、已冻结 Experiment 按保存 Agent.tool_set_version 重建原说明，新运行不会静默改旧产物。现有历史别名 v1/tool-lab-v1 映射原说明；未知版本拒绝。BFCL 工具协议不变。
5. 公共 API/Domain/Trace/Checkpoint Schema 不变。新旧工具集的比较指纹自然分开，不修改既有回归基线。真实复测仅少量文档任务，单次改进不能证明普遍能力或工具描述的因果效果。

## 验证与限制

覆盖目录缺失/网络失败、字符串伪 true、客户端注入、任意模型拒绝、例外真实 Provider 失败保留、两种 Runtime 的新文档说明、伪造证据失败、旧/新安全点与失败重跑、冻结对照版本及 MCP 相同参数校验。生产入口真实 Flash 文档与 M3 文档小样本分别记录，不扩大批量或自动恢复供应商请求。

例外来自带日期人工实测，仍可能以后失效，不是健康保证。减少例外需修改配置；回滚新运行工具集可退回 v1.0.0，保留 v1.1.0 的历史恢复实现。
