# ADR-019：Episode 总执行时限与历史兼容

## 状态

Accepted（2026-10-01）。依据需求 V0.6 §13.3；负责人授权推进产品复核中的总时限和 UI 收尾，明确暂缓全局 Token 预算与最终免费模型选择。

## 决策

1. Budget 增加可选 `max_execution_time_ms` 正整数，配置时使用 Budget schema 1.1；旧 schema 1.0 不配置时限。序列化省略未配置字段，保留旧 Agent/配置哈希和安全点来源。API 新增同名可选字段（Episode 请求 1.2、Experiment 请求 1.3），实验两侧使用相同时限。Web 新运行默认 300 秒，允许显式调整；历史读取和恢复始终使用保存的配置。旧客户端、CLI 与固定回归未配置时保持旧行为。
2. 两种 Runtime 由共同 EpisodeSession 使用单调时钟核算活动运行时间。观察、模型、校验、工具与活动期间的安全点开销均计入；进程停止/暂停等待不计入。恢复继承安全点的 `elapsed_ms`，不能归零；未落盘期间的耗时不能精确追溯，仍遵循 ADR-011 的安全点边界。
3. 开始模型/校验/工具前检查剩余时间。模型请求使用剩余时间作为本地异步等待上限；响应返回时先记录完整 usage，再检查时限。超限原因为 `TIME_BUDGET_EXCEEDED`，Runner 仍是唯一终态事件所有者。不自动重试；在途上游请求不保证取消，未收到响应的 Token/费用不填造为零，终止详情明确用量未知。
4. 已开始的同步工具线程不强制终止，不回滚或开启另一个工具。等待工具结果和快照安全保存后检查时限；即使提交已发生也以超限终止且评测不通过。局部网络超时继续约束远程读取。总时限是调度与模型等待约束，不承诺同步工具在截止毫秒立即返回，更不承诺外部写操作幂等。
5. 不重释现有 `token_budget`：它仍是单 Episode 输入加输出预算。UI 如实标注；FR-08 的全局 Token 预算继续为未完成项，待负责人确定演示免费模型后另走 ADR。数据库只记录为后续架构方向，不在本轮实现。

## 验收

两种 Runtime 覆盖模型慢响应、已完成响应超限、工具超限后保留状态且不继续、恢复沿用耗时、严格参数校验和唯一终态事件。旧配置序列化/哈希不变，旧 Episode/Experiment/Checkpoint 仍可读取；API 与 Web 配置可回读。Fake 用于确定性验收，本轮不新增真实调用或声明整版签收。
