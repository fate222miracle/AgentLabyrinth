# ADR-049 GridWorld 第二关：回廊档案室

2026-11-12，负责人要求增加一张更大的地图和一个适合课堂演示的复杂任务。沿 ADR-045 至 ADR-048 的公开投影、工具、评分和三维资产规则增加第二张固定地图。复用现有公开字段，地图以任务 ID 冻结，原关卡布局和保存结果保留。

## 关卡

任务 `key-door-002-v1`，展示名「回廊档案室」。先在门前区域找到钥匙，再回到主廊开门。门后隔墙挡住直线通路，Agent 可选择上下两侧绕行。空地、墙、钥匙、门和目标沿用现有含义。

```text
#########
#..K#...#
#.#.#.#.#
#S..D.#G#
#.#.#...#
#...#.#.#
#########
```

9 列 × 7 行。起点 (1,3)，钥匙 (3,1)，门 (4,3)，目标 (7,3)。以四向动作及钥匙、门状态为节点进行最短路验证。局部视野继续采用四向各两格，墙和闭门挡视线。地图源码仅由环境读取，任务公开元数据仅提供起点和地图版本，Web 复用公开 Trace 按已知格实例化 Blender 道具。

设计参照 [MiniGrid Key Corridor](https://minigrid.farama.org/environments/minigrid/KeyCorridorEnv/) 的钥匙与门分区，以及 [Valve 的 Portal 2 关卡编辑](https://store.steampowered.com/news/posts/?enddate=1336508339&feed=portal2_blog) 的独立房间构图。采用单一视觉锚点和两段路径判断，沿用自制素材与尤诺动画。

## 运行与验收

- 新关卡最多 20 个动作，Fake 累计 16,000 Token、单次输出 800，真实累计 160,000、单次输出 2,048，累计输出按动作数乘单次上限。单场仍为 300 秒。第一关继续最多 16 个动作。
- Fake 脚本覆盖最短路、撞墙后通关和动作上限。API 只接受两张冻结地图的已知任务标识及相应预算。旧局部观察、拒绝规则和 SQLite 回读继续验证。
- 前端 GridWorld 内选关，3D 和 2D 都从同一前缀显示已探索格。真实模型入口沿用已有目录与工具能力，交付验证先使用 Fake。

## 2026-11-12 真实第二关上下文裁剪

GLM 5.3 Flash 样本 `3bd40bae-b2ac-4f7e-b3a0-2f6835e1b54a` 在第 20 轮达到累计输入 163,264 Token。当前工具结果已携带尤诺的累计已知格、当前坐标、库存和可见目标。采用 [LangGraph 消息裁剪](https://docs.langchain.com/oss/python/langgraph/add-memory#trim-messages) 的完整消息对原则，结合 [Claude 旧工具结果清理](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context) 的做法，避免重复提交更早的地图快照。[Google ADK 摘要压缩](https://adk.dev/context/compaction/) 更适用于需要保留旧对话语义的场景。

新建真实第二关冻结 AgentSpec 1.2 和现有 `tool-round-window-v1`，保留任务指令、初始观察及最近两次完整工具调用和结果。原记录按保存配置回读，完整 Trace 和检查点照常保存。预算仍为 160,000 Token、20 轮、300 秒和单次输出 2,048。第一关和 Fake 配置沿用原策略。

按保存的 20 个请求离线重建网关消息序列化，完整历史为 495,661 字节，最近 1／2／4 轮为 82,206／132,486／221,249 字节。采用两轮保留近期动作对，兼顾折返线索与 73.3% 的累计消息体缩减。该测量只计消息 JSON 的字节，真实 Token、路线、成功率和耗时需独立模型运行验证。原轨迹至少需要 21 轮，裁剪并不改变这一点。

## 2026-11-12 真实复测及新运行边界

同一 GLM 5.3 Flash 第二关复跑 `3bd950f7-b8c5-4805-b02f-e48c10783dc5`。两局均有 20 次模型响应，累计输入从 163,264 降至 49,619（-69.6%），第 20 轮输入从 18,190 降至 3,370。两次走法不同。新样本拾钥匙并开门，第 20 个动作执行后以 MAX_STEPS 停在 (5,1)，沿地图最短还需 4 个动作。

新建第二关真实默认运行（请求省略两项预算覆盖或传 null）采用 `temporary-real-gallery-v3`，24 轮、330 秒，保持累计 160,000 和单次 2,048 输出 Token。累计输出随 24 轮为 49,152。保留最近两轮工具结果；新增行动提示，说明移动自动刷新、拾取要求同格，建议用已知可通行路径接近目标、探索时优先能揭示未知格的路线。提示只使用公开游戏规则。显式旧预算请求仍使用原配置，第一关、Fake 与历史读取保持原行为。

同日真实样本 `8c425323-a39b-4f48-9041-88b68bdcb197` 在新配置下第 1 次请求以 `provider_error: REQUEST_TIMEOUT` 结束。耗时 31.156 秒，后端日志记录 completion 请求超时，未收到模型响应，未执行环境动作。新建真实第二关的默认配置将 AIHubMix HTTP 连接/读取超时阈值从 30 秒提高到 60 秒。整体仍由 330 秒预算控制，同一次超时保留失败记录，由用户决定是否新建运行。旧预算请求及其他任务沿用原 HTTP 等待阈值。
