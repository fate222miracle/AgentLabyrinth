# ADR-034：文档ID精确查找与明确的字面检索

状态：Accepted，2026-10-19。负责人在上一轮明确提出下一项应优化检索交互后，授权开始下一步开发，并提出本周基本完成V0.3。依据需求V0.6§0.3/§6/§19；不自动提交GitHub。

## 已观察问题

ADR-033真实实验右侧已拿到INTAKE和正文引用，但多次搜索组合关键词为空；搜索INSPECTION时命中引用它的INTAKE/POLICY-B，却没有验收记录本身，因为旧搜索仅看标题/正文，不看document_id。此为工具交互可用性问题，不足以证明记忆机制失效。

## 决定

新ToolSet v1.5.0：搜索工具说明/参数文案1.1.0，参数仍query/top_k。新规则id-first-literal-v1：先对去除首尾空格的query作大小写不敏感document_id完全匹配；有命中仅返回对应文档的实际ID/标题。否则按原资料顺序，对标题/正文作大小写不敏感的整段字面子串匹配，top_k仍1–10。不引入分词/同义词/翻译/向量检索，不把任意英文组合词声称为语义搜索。

新返回除documents外附search_mode=exact_id/literal_text/none；空结果附固定提示，说明字面检索、已有正文引用ID可直接read_document、可使用任务公开document_query或较短字面片段。提示不读取goal，不返回正文/私有目标，不代替实际工具阅读、不额外注入记忆；搜索不取得证据。read/submit参数、评分、预算、恢复/单次参数纠错规则不变。v1.5延续v1.4的派生答案和正文引用说明，非目标任务也可提交直接读取的原值。

新Episode请求1.5/Experiment请求1.8启用该检索规则，仍须显式tool_call_mode；旧1.4/1.7及更早版本保持旧规则。新API/Web创建的ToolLab文档任务冻结+id-search-v1任务执行变体及document_search_protocol，源文件不改；与serial-v1组合时用同一版本后缀链，来源可追溯。只在新文档任务/含它的新矩阵选v1.5，两侧相同，BFCL保持原协议。旧产物/计划/安全点/失败重跑依保存ToolSet恢复，不用最新请求重解释。

MCP搜索服务增加可选search_protocol，默认literal-v1保持旧客户端行为；新客户端仅在v1.5内部附id-first-literal-v1，模型不能传或更改协议。服务器拒绝未知协议，与本地共用同一个检索函数；旧版本服务器不支持新参数时显式失败，不静默退回旧搜索。

Web继续复用实时节点/资料/ReadableFields，显示新查找方式和空结果建议，搜索结果不得标为已读。无新增配置选项或菜单；新建请求升级，保存结果按已有字段和工具版本说明来源。

## 验收与后续

ID和引用同现时精确ID优先、大小写/首尾空格/非ID子串/top_k/空返回/非法参数；旧v1.4及此前字面输出逐值保持；本地/MCP双路径、协议拒绝、空搜索零证据与独立预览零调用；新旧请求/任务变体/ToolSet/冻结计划/恢复/回归预检、Web搜索反馈和只读历史；完整门禁。然后只做一个免费模型一题正式记忆对照，固定两侧预算/版本，保留所有失败，不挑结果、不扩大批量。

本改动不保证模型会选择正确工具或题目通过，不新增Planning/Reflection/Judge或框架；这些按本周计划逐项形成具体方案。交付来源/调用链/状态/失败/实际验证见本轮学习交接。
