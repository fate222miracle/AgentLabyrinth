# ADR-016：Experiment 运行控制与固定套件回归

## 状态

Accepted（2026-09-29）。依据需求 V0.6 §10 FR-08、§12、§19；保留 ADR-010 的成对单变量口径和 ADR-015 的持久化恢复边界。

## 决策

1. 同一 Experiment 的矩阵仍按 Seed、Repeat、Task、Baseline、Recovery 顺序执行，避免两侧同时调用造成干扰。不同 Experiment 最多同时运行两个；AIHubMix 的现有全进程请求间隔继续生效。新的异步 Job API 返回稳定 Experiment ID，旧同步 API 保持兼容。
2. Job 状态单独持久化，包含 schema_version、ID、状态、请求控制动作和错误类别；原计划、Episode 和最终 Artifact 不改写。暂停/取消只在 Episode 边界生效，已经开始的模型或工具调用会完成；暂停保留计划与已完成侧并允许同 ID 恢复，取消保留已完成 Episode 作审计但不自动恢复。进程异常退出时，旧 `running` 状态按中断显示，仍走原计划恢复并校验来源。请求 ID 不得覆盖现有 Job 或产物。
3. 失败 Episode 单独重跑产生新 Episode ID，原产物保持不可变；只在能从原产物严格还原当前 Task/Agent/环境配置时接受。重跑来源关系保存为版本化旁路记录。模型请求可能再次计费；不存在隐式自动重试。
4. 自动回归采用固定请求 Manifest 与已保存的基线 Experiment Artifact。每次运行固定矩阵，比较前先核对 Suite/Task 版本、模型、Prompt/工具版本、预算、Seed/Repeat、对照轴和故障配置；Agent/Runtime 的实现版本允许变化。按相同 Task/Seed/Repeat/侧别比较成功与否，成功变失败为退化，Token/耗时/费用只作为观察指标，未知费用仍为未知。输出版本化 JSON 报告并以非零退出码标记退化或配置不兼容。CI 默认只跑 Fake 固定套件；真实模型回归需人工开启，不能把 Fake 结果当作真实能力成绩。

## 验收

- 两个 Job 可并行进入运行，但单 Job 的成对顺序不变；第三个排队。暂停/取消在安全边界停下，刷新或重启后能读回状态；暂停恢复复用已完成 Episode，取消不隐式恢复。
- 失败 Episode 重跑保留原文件，生成新 ID 和来源记录；成功 Episode、配置漂移、未知环境拒绝。
- 回归的同配置 Fake 基线通过；注入单个成功变失败能报出具体矩阵单元并失败退出；模型或任务版本变动在调用模型前拒绝比较。

## 边界

本地单进程 Job 调度和 JSON 原子写入满足课程演示；多 API 进程、外部分布式锁、外部写工具恰好一次和自动周期调度均不在此决策内。部署多 worker 时须先增加共享队列与锁。
