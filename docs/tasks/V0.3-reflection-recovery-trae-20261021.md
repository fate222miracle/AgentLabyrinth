## Reflection ADR必须回答

| 项目 | 要写清的内容 |
| --- | --- |
| 问题和必要性 | 哪个信息已可见但未调整的失败值得改；排除遗忘、网络、权限、预算原因；普通继续行动或一次参数纠错为何不足 |
| 触发/输入 | 活动Episode的哪些真实公开反馈可触发；触发依据及来源事件ID；不读私有目标/正确证据/最终私有评分 |
| 输出 | 可验证的简短行动修正结构、长度与次数上限；不要求隐藏思维链，不把声明当任务已完成 |
| 调用/预算 | 是否独立模型调用、总额外次数、用量/费用/时延与全局准入；无额外免费调用，未知用量不补零 |
| 停止/恢复 | 拒绝输出/Provider错/超时/预算/保存失败/中断的状态与来源；安全点前后只执行一次，不复活终态或撤回提交 |
| 公平性 | 两侧相同full、相同规划/恢复/工具/模型/Runtime/Seed/总预算，仅Reflection变化；原评分独立，不偏置基线 |
| 契约/兼容 | Agent/请求/事件/Session/实验/CSV/comparison_key等是否新增版本；旧缺字段默认、哈希、冻结/恢复/重跑保持 |
| 任务与验收 | 先复用现有题，若新题必要给具体协议/事实/评分待确认；反事实、无私有泄漏、错误恢复边界及真实探索范围 |
| 产品闭环 | 两Runtime、single/serial、本地/MCP、正常单次/正式对照/实时阶段/历史GET/CSV，源码学习包 |
