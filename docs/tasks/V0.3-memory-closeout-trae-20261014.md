## 目标与问题

## B. 本轮交付：Proposed同窗口对照方案

先检查下一个ADR编号，创建Proposed文档，不自行标Accepted。至少明确：

1. 研究问题、自变量、固定变量；左window N，无memory；右同window N，memory M。
2. 是否独立轴或版本化原轴的选项/结论；旧ADR-026仍强制左full，历史模式无静默变化。
3. 请求/计划/结果/策略版本，参数组合，非法N/M、混变量、旧版本误用、新配置降级的拒绝规则。
4. API service建Agent、Application固定计划/校验、保存读取、暂停/恢复、失败重跑与回归comparison_key影响。
5. 旧Agent哈希、旧Artifact及旧CSV列顺序/未知空值兼容；恢复使用冻结原策略。
6. 上下文实验不使用Recovery挽救率；派生阅读指标的成功返回/前缀/缺字段判定。
7. Web配置和结果信息草案：只展示必要选项，历史草稿隔离，两侧穿透来源/Trace，URL仅GET。
8. 拟改文件、实现顺序、测试矩阵、回滚/关闭新建入口方案、真实验证范围。

产物为可审核ADR与一份任务实施计划/界面信息设计；无需新前端依赖、空模块、原游戏服务或真实模型调用。完整可用入口是后续批准后的目标，不能将静态图或两次孤立POST伪装成已冻结/可恢复的正式Experiment。

## 复核结论与实际结果（Trae，2026-10-14）

接手基线：HEAD 998ff6e，存在大量 Codex 未提交/未跟踪交付，全部保留。逐项复核后**未复现需要改动已批准算法、旧序列化、评分或恢复语义的缺陷**，故未改算法、未动旧产物与旧哈希。

**检查清单证据**

- 策略/序列化：`ContextPolicy` 拒绝 1.1 算法缺预算、full+记忆、越界/非整数预算；旧 1.0 序列化形状与哈希不变；`project_context` 先校验全历史再投影。
- 记忆来源：`_tool_memory` 只取被窗口排除的成功 `result`（有 `result`、无 `error`），带实际 `call_id`/工具名；error/未返回/未匹配反馈与保留字段均失败关闭。
- 预算：紧凑 JSON 精确 UTF-8 字节；超预算整条跳过、256 字节不足仍失败；不退回 full、不增工具调用。
- 恢复：两 Runtime 共用投影；`EpisodeCheckpoint.validated_recorder` 与实验计划 `verify()` 对身份/来源/哈希失败关闭，旧结果不迁移。
- 证据/阅读：原生 007 与三跨文档任务评分保持；`flowFrames.documentEvidence`/`DocumentEvidence` 仅在实际成功返回且正文 ID 匹配时计读，空 `document:null`、失败、未返回、预览不累计，重复成功读同 ID 才计重复。
- 隔离/只读：单次草稿、高级设置、保存配置、模型失效历史与刷新/导航隔离；历史只 GET；CLI 逐侧保存回读、禁止覆盖、Provider 失败保存部分报告并停止。
- 旧轴：full 上下文对照与 Recovery/Runtime 轴、哈希/指纹/CSV 标签语义保持。
