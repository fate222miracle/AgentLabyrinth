# M0 任务卡

SSOT：`docs/product/requirements.md` V0.5。背景：从零建立可读、可运行的模拟订单闭环。目标：理解模型提议、Runtime 控制、工具执行、状态变更和独立评测。

## 当前协作拆分
1. Codex：初始 ADR、Domain 类型/Port、Application 编排、配置及 Trace 边界、契约与验收约束、学习与交接文档。
2. Antigravity：按 `M0-antigravity.md` 实现 FakeModelProvider、HandwrittenRuntime、Registry/Executor、ToolLab、Evaluator、CLI 和具体实现测试。
3. Codex：审查并复跑质量检查、对照实验。项目负责人最终阅读与验收并操作 Git。

## 本次范围
一个原生 development 订单任务；query_records 与 submit_answer 两个工具；严格参数校验；只用 Fake；手写控制循环；独立 Evaluator；JSON Trace；CLI；关键测试。

## 明确不做
完整 V0.1、其余 11 个任务、真实模型、超时重试、Recovery Agent、API/UI、数据库、Replay 产品、批量 Experiment、多 Agent、GridWorld、未来 Adapter。完整时间预算及超时相关测试留后续，不伪称已覆盖。

## M0 最终验收（当前框架交付不等于以下全部完成）
- 版本化输入严格校验并随 Trace 保存内容哈希；同 seed 重建同初始状态。
- Fake 至少两轮：根据公开任务查询订单，再使用工具返回的状态及证据提交；不读取 goal_conditions。
- 缺失/多余/错误类型/嵌套非法参数、未知或禁止工具、重复调用 ID 均拒绝且不改环境。
- 步骤、模型/工具次数、Token、Decimal 费用硬限制有明确停止原因；模型解析失败及执行异常可定位。
- Evaluator 区分合法提交与答案正确；错误答案、无提交、伪造/未取得证据都失败。
- 需求 26.3 全部事件字段，有因果关系、UTC/UUID、快照、配置、最终评测；JSON 可再次严格加载。
- pytest 覆盖预算、Executor、状态、Evaluator、Runtime 停止分支、所有具体 Port 实现、完整 CLI。
- Ruff 格式/Lint、mypy、pytest 通过；依赖审计记录真实结果。源码阅读指南、实验结果、current-state 完整。
