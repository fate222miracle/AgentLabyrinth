# V0.1 切片 F：补齐 ToolLab-Core 原生任务集（Copilot）

## Codex 已交付的框架

- `ToolLabEnvironment` 已实际注册需求规定的四个工具：`search_documents`、`read_document`、`query_records`、`submit_answer`。
- 文档状态支持严格 Pydantic 校验、大小写无关搜索、`top_k`、按 ID 读取、读取后证据获取、Snapshot/Restore，并兼容旧 Snapshot 缺少 `documents` 的情况。
- 已有一条环境级测试证明“搜索只返回摘要，读取后才获得证据”。这不是占位模块；Copilot 直接在现有实现上补任务闭环。

## Copilot 当前任务

1. 将现有 `order-status-004` 的类别改为 `parameter_generation`，保持前三条为 `tool_selection`；再新增 8 个 TaskSpec，使总数严格为 12，四类各 3 个：`tool_selection`、`parameter_generation`、`multi_step_planning`、`error_recovery`。
2. 文档类任务使用 `initial_state.documents`，每项字段固定为 `document_id/title/content/evidence_id`。多步任务必须实际走 `search_documents → read_document → submit_answer`，不能仅在文字中声称多步。
3. 最小扩展现有只读评测逻辑，使 `read_document` 成功返回的 `evidence_id` 可计入已获取证据；保留现有指标名称和旧订单任务结果。若确需改评分器名称、公共指标或 Schema，先写 ADR 并停止相关实现等待审查。
4. 扩展 `FakeModelProvider` 的确定性响应，使 12 个任务无需联网即可跑通成功路径；错误恢复任务用既有 `invalid_then_success` 契约。不要让 Fake 读取 `goal_conditions`，也不要按任务 ID 硬编码最终答案。
5. 增加一个 Suite 级测试，一次性校验：恰好 12 个 JSON、四类各 3 个、名称/UUID 唯一、四工具均被任务覆盖、每个 TaskSpec 可校验。更新 API 元数据测试，避免继续把“4 个任务”写死。
6. 为临时超时增加一个确定性环境测试和明确 Trace/终止结果；ADR-004 仍限定 Recovery 只重试一次 `INVALID_ARGUMENTS`，本切片不得静默扩大重试边界。
7. 用 Fake 跑完整 12 任务，并更新 README 与 `docs/handoffs/current-state.md`；记录成功数、失败原因、命令和产物位置。

## 验收门槛

- 12 个任务严格四类各 3 个，均有设计意图、预期工具轨迹、成功条件和失败条件。
- 固定 Seed 重置得到相同初始状态；旧 4 任务、旧 JSON 与旧 Replay 保持可读。
- 四工具均经过 Registry/Validator/Executor，不从 Runtime 绕过权限或参数校验。
- Fake 全套运行不联网；至少一条真实可用模型仅作为探索性证据，不作为自动化测试门槛。
- `scripts/check.ps1`、前端生产构建与 `git diff --check` 通过。不得声称完成批量 Seed × Repeat；该项留给下一切片。

## 明确不做

多 Agent、外部数据集扩容、并发、暂停/恢复、SQLite、登录鉴权、UI 重做、自动切换真实模型。完成本卡后交 Codex 复核，不自行开始下一切片。
