SSOT：需求V0.6；沿用Accepted ADR-030、ADR-026/028/029。负责人2026-10-14授权继续开发。仅一个现有模型、一个任务、两侧各一次探索；不提交GitHub，不扩大Seed×Repeat。

## 问题与交付

近期窗口加工具记忆是否减少丢失早期依据后的重复阅读，或使最终证据更完整？固定MiniMax M2.7、LangGraph、本地工具、退货审批Task1.3.0、Seed1、窗口1、10步/20000报告Token/300秒；仅右侧增加8192字节记忆。不能将单对结果当作成功率或稳定因果收益。

复用scripts/episodic_memory_ablation.py新增显式--model入口；默认仍为六格离线Fake。真实模式经EpisodeService→正式Checkpoint Runner→原Runtime/Executor/Evaluator，完整Episode存正常artifacts，可在网页按ID只读。每侧回读保存结果、核对Agent/Task/RunConfig哈希，比较时排除context_policy后其他配置须一致。报告使用原子写入，已有目录拒绝覆盖；第一侧Provider报错即保留部分报告并停止，不换模型重试。

报告记录实际评分/终止、提交、工具/模型调用、报告Token、耗时、请求记忆诊断及成功阅读文档列表。重复阅读定义为同一Episode中已成功读过的document_id再次成功读取；不把提议/拒绝/工具失败计为已读。重复为0也可能任务未完成，Token零也可能供应商未报告，必须连同失败原因解读。
