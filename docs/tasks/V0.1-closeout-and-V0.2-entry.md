# V0.1 发布验收与 V0.2 启动计划

SSOT：`docs/product/requirements.md` V0.6。本文只把既有版本路线转换为执行顺序，不新增产品范围。

## 为什么不再继续追加 V0.1 功能切片

M1 切片 A–E、V0.1 切片 F 和 Slice G 已完成演示闭环、原生任务集与 UI 收口。接下来应按版本验收，而不是继续用同级切片堆叠功能。

当前已知的 V0.1 验收缺口是需求 18.8 所要求的 `Agent × Task × Seed` 批量矩阵：现有 Experiment 支持多 Agent、多 Task，但一次实验只有一个 Seed，也没有 Repeat。其他 17 项需要做一次证据复核，不能仅依据旧任务卡宣称通过。

## Gate 1：V0.1 Release Candidate

目标：完成需求第 18 节的逐项验收并发布 V0.1，不引入 LangGraph、Checkpoint 或并发执行。

1. 为 Experiment 增加多个 Seed 与 Repeat 的串行执行能力；保留单 Seed 请求和旧 Experiment JSON 的读取兼容。
2. 每个 Episode 明确记录 `seed` 与 `repeat_index`，成对比较必须使用相同模型、任务、Seed、预算与重复序号。
3. 聚合结果按实际样本计算，不把缺失费用记为零；小样本不展示误导性的置信区间。
4. Web 高级配置允许输入 Seeds 与 Repeat，并在运行前显示真实 Episode 总数。
5. 使用 Fake Provider 完成固定矩阵回归；一个当前可用真实模型只跑受控小样本并明确标为探索性证据。
6. 按需求 18.1–18.18 建立验收表，记录代码、测试、实验产物与未满足项。
7. 同步 README、`current-state.md` 和学习文档，创建 `v0.1.0` 发布候选提交；Tag 与发布仍由项目负责人决定。

Experiment Artifact 和 API Schema 会变化，编码前必须新增 ADR，说明旧 JSON 迁移、成对键以及聚合口径。

### 2026-09-22 执行结果

- ADR-008 已落实：多 Seed × Repeat 串行矩阵、Pair 身份、Experiment 1.1 与旧 1.0 兼容均已实现。
- Experiment 已补充已知 Decimal 费用聚合；未知与历史缺失费用不补成零。
- 浏览器 Fake 实验完成 8 Episode / 4 Pair 并通过 URL 刷新回读；全量门禁 100 passed，Ruff、mypy 和前端构建通过。
- 第 18 节的 18 项验收已通过，证据见 `docs/handoffs/V0.1-acceptance-review-20260922.md`。
- 项目负责人已接受需求 V0.6 口径：全局美元费用上限进入 V0.2，并以可验证价格表为前提。V0.1 验收关闭，当前进入 Gate 2；不自动创建 Tag。

## Gate 2：V0.2 Milestone 1 — Runtime Interoperability

目标：把平台从单一参考执行器升级为可比较主流 Agent Runtime 的实验平台。

1. 将现有 `HandwrittenRuntime` 在产品文案中定位为 `Reference Runtime`，保留代码兼容名称。
2. 新增 `LangGraphRuntimeAdapter`，只放在 Infrastructure Adapter 边界，不让 LangGraph 类型进入 Domain、Environment、Evaluator 或统一 Trace。
3. Reference 与 LangGraph 复用同一 `ModelProvider`、Tool Registry、Validator、Executor、预算和任务集。
4. 将 LangGraph 节点事件映射为统一 Trace；框架原始元数据可以附加保存，但不作为评分事实来源。
5. 在 ToolLab-Core 上完成 `Reference × LangGraph` 对照，并分别运行 Baseline 与 Recovery 策略。
6. 先用 Fake Provider 做确定性 Contract Test，再用一个可用真实模型运行小样本。

编码前必须新增 Runtime Adapter ADR。ADR 需要决定如何把“Runtime 实现”和“恢复策略”拆成两个独立实验变量，并兼容现有 `runtime_strategy`。

## V0.2 后续里程碑

Runtime Interoperability 验收后，继续完成需求第 19 节已经确定的 V0.2 范围：

1. **Experiment Control**：并发 Experiment、暂停、取消与失败 Episode 重跑。
2. **Reliability**：Checkpoint / Resume、幂等性和中断恢复实验。
3. **Fault Lab**：扩展故障注入，并比较恢复成功率、额外调用和延迟。
4. **Benchmark Adapter**：以现有 BFCL 改编子集复核通用 Adapter 契约；只有出现新的研究问题时才接入第二个外部数据集。
5. **Regression**：固定 Suite 的自动回归评测。
6. **Observability**：Trace 与指标看板，展示跨 Runtime 和跨实验的可比较结果。

BFCL 已作为课程例外提前完成基础接入，因此 V0.2 的工作重点是验证并固化通用 Adapter 契约，而不是为了凑数量重复建设第二套数据接入。

上述里程碑覆盖 V0.2 路线图的全部九项能力。顺序是执行优先级，不改变需求范围；每一项开始前仍需说明要验证的失败现象和实验指标。

## 明确不做

- 不同时引入 CrewAI、AutoGen、PydanticAI 或 OpenAI Agents SDK。
- 不把 LangSmith 作为平台的评测事实来源。
- 不在 V0.1 Release Candidate 中提前实现并发、Checkpoint、数据库迁移或新的 UI 重构；这些能力按 V0.2 里程碑实施。
- 不用“引入了 LangGraph”代替跨 Runtime 对照实验结论。
