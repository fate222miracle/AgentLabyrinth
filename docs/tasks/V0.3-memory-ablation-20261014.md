# V0.3 同窗口记忆对照实施与界面信息设计

SSOT：需求 V0.6；依据 [ADR-031](../adr/ADR-031-same-window-memory-ablation.md)、Accepted ADR-023/026/030。状态：**已实施，Codex 技术复核，待负责人验收**（2026-10-15）；下文早期计划为历史，最新结果见文末和 current-state。不提交 GitHub。

## 目标

把“相同 N 轮近期窗口、仅切换单 Episode 工具记忆”从离线 CLI 探索提升为**正式、可冻结、可恢复、可只读回读**的 Experiment 入口，用于单独归因记忆的作用；不改默认 `full`，不改旧三轴与旧产物。

## 现状与不可动边界

- 现有 Web 上下文轴是 **full vs recent_tool_rounds（右侧可加 memory）**，比较整体策略，不能改名为“纯记忆轴”（[ADR-026](../adr/ADR-026-context-comparison-web.md)）。
- 旧 `ContextPolicy` 1.0 序列化/哈希、旧 `AgentSpec` 哈希、旧 Experiment ≤1.4 / 计划 ≤1.2 / CSV 列序保持不变。
- 记忆只改 Provider 输入，不裁剪持久历史；仅“窗口外成功 result 反馈”整条准入，256–32768 字节，超大整条跳过；error/未返回/私有目标/最终快照排除。
- 阅读计数只在实际成功返回且正文 ID 匹配时递增；空 `document:null`、失败、未返回、预览不计；重复成功读同 ID 才计重复。
- 不新增数据库/向量库/摘要模型/Planning/第二框架/多 Agent/新服务；不批量真实模型调用；不输出 Key。

## 版本与调用链

请求 1.6 → `CreateExperimentRequest` 新轴 `memory_ablation` → `EpisodeService.prepare_experiment` 派生左(同 N 无记忆)/右(同 N+M) → `create_experiment_plan`（计划 1.3，`_validate_memory_agents`）→ 写冻结计划 → `_resume_experiment_once` → `run_experiment` 逐臂 `run_checkpointed_episode` → 结果 1.5 → `ExperimentArtifact` 校验 → 保存。

完成现有功能复核后的 Part A 结论见 [current-state](../handoffs/current-state.md)：直接相关 77 项 Python、CLI 六格、Node 37、构建、Edge 相关 7 项通过；完整门禁用 `AGENTLABYRINTH_E2E_CHANNEL=msedge` 退出 0（默认 chromium 缺二进制是环境限制，非回归）。未复现需改算法的缺陷，故本轮不改动已批准算法。

## 界面信息设计

**配置区（对照）**

- 对照轴下拉新增：`工具记忆：相同近期窗口 vs 相同窗口+记忆`（与旧三轴并列，默认仍是恢复策略轴）。
- 选中后显示：
  - **相同窗口轮次 N**：整数 1–100，两侧共用；标注“左右窗口相同”。
  - **右侧记忆上限 M**：整数 256–32768 字节；标注“左无记忆、右有记忆，仅此一处不同”。
- 复用现有 `.context-settings`、数字输入与折叠帮助；不缩字体、不重置草稿、不改高级分组。
- 默认演示候选 N=1、M=8192；不改单次运行默认 `full`。

**结果区（只读历史）**

- 复用上下文对照只读块：显示左右臂策略与保存配置，提示“保存结果不随草稿改变”。
- 明确说明：① 左右窗口相同，仅记忆配置变化，真实输出仍有随机性，单对不是因果收益证明；② 字节不是Token，记忆可能增加输入量，不保证效果。
- 右侧穿透来源沿用 `McpFlowReplay` 当前请求诊断（记忆条数/实际字节/跳过数/源 call_id）；资料阅读沿用 `DocumentEvidence` 的成功阅读/重复计数。

**CSV 与导航**

- 列顺序、列集不变；新轴仅填充既有 `context_*` 列（左臂 `memory_max_bytes` 为空，右臂为 M）。
- 刷新/前进/后退只 GET；改草稿不改历史；导出用保存配置。

## 2026-10-15 实施结果（本地完成）

负责人确认“按修订 ADR-031 开始开发”，已按本卡顺序完成后端→网页→验收，协议实现见 [ADR-031 §12](../adr/ADR-031-same-window-memory-ablation.md)、详细状态见 [current-state](../handoffs/current-state.md)。要点：

- 版本落地：`ComparisonAxis` 加 `memory_ablation`；请求 1.6 / 计划 1.3 / 结果 1.5 仅该轴使用，旧默认请求 1.5、单次默认 `full`、旧三轴与旧哈希不变。
- 后端：`_validate_memory_agents` 严格单变量校验(创建/`verify()`/恢复)；`prepare_experiment` 服务端派生左同N无记忆、右同N+记忆，除 `context_policy` 记忆子版本外一致；臂标签左 `Recent Window` / 右 `Recent Window + Memory`；回归 `preflight` 适配新轴，`fixed_config` 未改。

- Fake 实际结果：原生 `order-status-007` N1/M8192 两 Runtime 左 `MAX_STEPS` 失败/右 `SUCCESS`；N5/M32768 两侧均通过；N1/M256 两侧均失败。属机制事实，其他任务/N/M 不套用。
