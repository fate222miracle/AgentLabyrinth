# V0.3：已保存记忆实验的执行差异解读

SSOT：requirements V0.6；沿用 ADR-030/031。状态：已实施并通过技术验证，Codex；不代替整版签收，本轮不提交 GitHub。

## 问题与范围

同窗口记忆轴已有正式 Experiment，但文档成功读取与重复读取只在单侧 Trace 中可见，用户需要来回切换才能判断差异。补充当前已实现能力的只读展示，不增加指标契约、评分或算法，不启动 Planning、数据库或多 Agent。

## 验收

- 仅在保存的工具记忆实验中提供任务/Seed/重复选择；显式点击后 GET 两侧 Episode，不自动遍历整个实验，也不发 POST。
- 复用 `readEpisode` 的 Schema/ID 校验及 `documentEvidence` 阅读规则；成功返回匹配正文 ID 才计读，失败/null/最终快照不补读。
- 两侧显示独立评测结果、工具调用、成功阅读/重复阅读以及文档明细；重复读取不自动判为无效调用。
- 无完整起止 Trace 时阅读统计显示未知；单侧读取失败仍保留另一侧，支持显式重试，不用旧数据或零补齐。
- 切换任务、实验或导航离开后取消/忽略旧请求；历史不改草稿、URL 和实验原产物。
- 单元覆盖计数/缺失；浏览器覆盖正常、部分失败/重试、ID 错配、快速切换、四视口、键盘和减少动效。只用 Fake，不新调用真实模型。

## 阅读与验证

`App.tsx`（保存实验入口）→ `MemoryPairReview.tsx`（显式读取及取消）→ `apiClient.readEpisode`（边界）→ `flowFrames.savedDocumentReads/documentEvidence`（只读派生）。结果不是新的后端评测分数，不纳入旧 CSV/比较指纹。
