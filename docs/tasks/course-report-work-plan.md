# AgentLabyrinth 计网实践报告分工

这份任务书供四位组员共用。交付物是一份《AgentLabyrinth 软件需求、设计与实现报告》，正文依次说明项目需求、系统设计、功能实现、测试结果与总结。

## 共同基线

- **报告主线**采用主分支的 ToolLab 文档任务 `order-status-007`。选择 Fake 模型和 MCP HTTP 传输，用一局运行贯穿需求、设计、实现和测试。先记录代码提交号、配置、Episode ID 和实际端口，再共享给全组。
- **业务链路**从选择任务、启动 Agent 开始，经过文档查询与读取、工具反馈、规则评分和结果保存，最终在网页回放。三维部分使用 GridWorld 展示 Blender 资产怎样进入浏览器并随任务事件更新。架构章节用这条链路解释浏览器与 API 的 HTTP／SSE 通信，以及 API 与 MCP 工具服务的 HTTP 通信。
- **取证口径**以同一局的截图、Trace、浏览器 Network 和服务日志为准。正文标出对应的回合或事件，截图和附件使用模拟数据并遮盖凭据与个人路径。

## 章节衔接示例

| 需求编号 | 需求与验收条件 | 对应设计或实现 | 测试证据 |

| FR-01 | 启动单个任务后，用户可在任务结束前看到执行进度。 | API 传送 SSE 事件，前端按事件更新视图。 | TC-01：记录任务进行中的视图和浏览器响应。 |

## Blender MCP 建模与三维场景上网页

这部分作为 GridWorld 的实现实例，与 ToolLab 的通信主线共用系统架构，另取一局 GridWorld 的三维画面和 Trace 作为证据。

| 阶段 | 组员需要讲清楚的实现 | 证据入口 |
| --- | --- | --- |
| **建模调用** | 建模客户端通过 MCP Streamable HTTP 发现工具并调用 `build_key_door_scene`。建模工具启动 Blender 后台脚本，生成可编辑的场景工程和供网页使用的资产。 | [建模服务](../../scripts/blender_mcp_demo.py)、[Blender 场景脚本](../../scripts/blender_key_door_scene.py) |
| **资产导出与部署** | Blender 工程保留为 `.blend`，选择网页需要的场景部件并导出为 `.glb`。网页资源目录分别提供迷宫场景部件和带动作的角色模型。 | [GLB 资源目录](../../apps/web/public/gridworld)、[建模与导出记录](../learning/blender-mcp-demo-20261111.md) |
| **网页加载与渲染** | 浏览器通过 HTTP 获取 GLB。Three.js 的 `GLTFLoader` 载入场景部件、角色和动画数据，在网页中组装并渲染。 | [三维场景加载代码](../../apps/web/src/gridWorldScene.ts) |
| **运行与回放** | 前端按已确认的公开 Trace 重建已知地图，把角色位置、钥匙拾取和门状态映射到场景与动画。 | [三维试跑与回放验收](../../apps/web/e2e/gridworld3d.spec.ts) |

**交稿证据。** 组员 2 画出「MCP 调用 → Blender 导出 → HTTP 加载 GLB → Three.js 渲染」的资产流。组员 3 用一个场景部件和一段角色动作解释导入与事件绑定。组员 4 核对浏览器 Network 的 GLB 请求与实际三维画面，在一次保存回放中对齐至少一个移动或交互事件。

## 交稿顺序

1. **全员联跑。** 按 [README](../../README.md) 启动 API 和网页，再从仓库根目录启动工具服务。

   ~~~bash
   uv run --locked python -m packages.environments.tool_lab.mcp
   ~~~

   服务默认使用 `http://127.0.0.1:8765/mcp`。网页选择 `order-status-007`、Fake 和 MCP HTTP，完成一次运行并记录共用基线。
2. **先定需求和设计。** 组员 1、2 把需求编号、架构图和时序图发给其余组员。组员 3、4 用这些编号组织实现说明与测试。
3. **收齐材料再组稿。** 四人分别提交章节正文、可编辑图表和证据索引。组员 4 检查需求与用例是否对应，再合成一份报告。
