## 1. 文档定位与实施边界

1.11补充（负责人确认ADR-040）：正常页面只提供真实大模型评审，选择模型后显式发起一次请求，先展示判断/理由/事件引用及与规则一致或分歧；无模型或无最终提交时明确禁用。人工表单和Fake生成按钮从产品撤下，旧记录只归档和完整导出，不呈现质量结论。不得用大块居中空白占位；未评审仅一行提示，版本/用量继续按需展开。不自动调用、重试或回落Fake，评审不能覆盖原运行成绩；后续算法效果用真实有/无组件对照证明。

1.10补充（ADR-039既有范围）：结果复核先说明用途——在规则评分之外记录对答案、依据和工具使用的检查意见。默认展示结论与理由，量表/提示版本、Token、费用及价格版本收进“技术详情”。人工入口用“记录我的检查”和完整中文问题。Fake Judge按钮及历史默认折叠到“模拟测试（开发用）”，明确不评分、不调用真实模型；模拟记录不能用一排“不确定/未知”冒充质量结论，不能计入主区人工/真实模型复核数量。对照摘要同样将模拟数单列。完整CSV继续保留全部原始记录及来源，未知值不补造；原生折叠控件须可键盘操作，展开/刷新仅GET，不自动POST。

1.9补充（ADR-033）：工具调用方式在更多设置中保持紧凑，明确多工具为同轮只读/顺序执行、写工具单独调用；BFCL锁定单函数协议并说明原因。保存结果显示实际模式，与下次草稿隔离。实时画布按Call ID创建每个调用节点，标记同轮序号，未执行不标成功；过程概览必须列出本轮所有调用的参数、校验和实际反馈。多工具概览使用整行区域、桌面两列卡片/窄屏单列，避免把所有结果堆在一列旁留下大片空白。取消/失败后未执行项保持明确，资料仍按实际成功返回逐项更新。CSV附加保存模式，历史刷新与回放只GET，继续遵守减少动效/键盘与四视口要求。

本规范把原稿的视觉方向落实到现有 AgentLabyrinth 实验平台。项目名称统一使用 **AgentLabyrinth**；“Agent Arena”保留为原稿名称，不据此重命名仓库、API 或领域对象。

本文规定 UI 如何呈现已授权的产品能力。产品需求与已批准 ADR 优先于本规范；本规范优先于页面临时样式。设计 Token 是视觉属性的统一来源，不替代产品需求的唯一事实来源。

V0.1 已验收，当前为 V0.2 收尾及 V0.3 受控切片。本文视觉与过渡规则指导已授权 Web 能力；文档更新不代表整版已经验收。

| 范围 | 本规范中的处理方式 |
| --- | --- |
| Baseline / Recovery 对照实验 | 主要设计对象，呈现固定变量与策略差异 |

## 2. 设计目标

视觉关键词：**温暖、安静、清晰、专业、透明、流畅**。

使用暖米白画布、浅色表面、深灰正文和少量陶土橙强调操作。通过留白、文字层级、分隔线和展开区域组织实验信息。页面的重点是任务、Agent 策略、运行结果和证据。

设计原则：

1. **内容优先**：不使用大面积渐变、霓虹、发光球、装饰图表和持续漂浮动画。
2. **逐步展开**：默认显示关键结论，完整配置、事件 JSON 和次要指标按需展开。
3. **状态可信**：状态和进度必须有接口或事件依据，不能用动画模拟未观测到的行为。
4. **边框优先于阴影**：优先通过背景、边框、间距和字体建立层级。
5. **颜色有含义**：品牌色表示主要操作或选中；语义色表示结果与异常。
6. **复用优先**：共享视觉规则与已实际复用的组件，不为了设计系统完整性创建空模块。

信息优先级随使用阶段变化：运行前突出任务与配置，运行中突出等待与执行说明，完成后突出结果和 Trace。不要强制所有页面沿用同一种顺序。

### 2.1 视觉方向与参考

采用暖色研究工作台的配色，借鉴 [Linear 近期界面更新](https://linear.app/now/behind-the-latest-design-refresh) 对信息层级、柔和分隔和主内容优先的处理；借鉴 [Apple 动效指南](https://developer.apple.com/design/human-interface-guidelines/motion) 的连续、简短且可打断的状态过渡。这里借鉴的是设计原则，不复制其他产品的页面或品牌。

界面的“灵动”来自操作前后的空间关系：选中的标记移动到新位置、已点击的卡片展开为相关详情、Replay 游标与证据面板同步更新。静态画面仍需清晰；动效不能承载唯一的结果或错误信息。保持现有暖米白、陶土橙与克制的阴影，不引入大面积毛玻璃、持续背景动画或无关的 3D 效果。

### 2.2 顶部导航例外（2026-09-27）

项目负责人明确要求导航随页面下滑保持可见，并采用透明毛玻璃。仅顶部导航允许暖白半透明背景与 backdrop blur；保持正文、焦点和选中态清晰，不将毛玻璃扩散到内容面板。不支持 backdrop-filter 的浏览器使用接近不透明背景。祖先容器不得建立干扰 sticky 的滚动容器，键盘自动滚动保留导航顶部空间。

## 3. 色彩与基础 Token

2026-10-12 品牌标志按负责人选择更新为“寻径之狐”。以正式fox-mark.svg为唯一轮廓，导航初次加载采用1330ms有限显形/路径展开，结束静止；点击品牌在新页查看和重播，不改变当前历史或运行草稿。favicon保持静态。减少动效即时显示完整标志，无动效样式或动画资源失败时静态兜底；不得以品牌动画阻塞工作区、表达模型/网络/Trace状态或伪造执行进度。原Wayfinder为历史资源。理念、源文件与验证见[狐狸品牌规范](../design/fox-v1/README.md)。

### 3.1 深色主题预留

未来启用时覆盖相同语义变量，不让组件判断两套变量名称：画布 `#1E1D1A`、表面 `#262521`、次表面 `#302E29`、主文字 `#F1EEE8`、次文字 `#AAA69E`、边框 `#3A3833`、品牌色 `#D97A59`。

这些仅为候选基础色；状态色、按钮和焦点必须一起验证。不要简单反转颜色，不以纯黑作为大面积背景。首版不需要主题切换按钮。

## 4. 字体、间距与图标

| 用途 | 字体建议 | 规则 |
| --- | --- | --- |
| 导航、正文、表单 | Geist 或系统无衬线 | 中文补充 PingFang SC、Microsoft YaHei、Noto Sans CJK SC 回退 |
| 特殊研究标题 | Source Serif 4 或中文衬线回退 | 可选，仅用于少量标题，不强制下载新字体 |
| JSON、工具参数、模型 ID | JetBrains Mono、Consolas、等宽回退 | 长 ID 可换行或省略并提供完整值 |
| 普通数字指标 | UI 字体与 tabular-nums | 不强制所有指标使用等宽字体 |

字号使用 `12 / 14 / 16 / 18 / 20 / 24 / 32 / 40 / 48` 的统一档位，建议转换为 rem Token。正文默认 16px、行高 1.6；紧凑表格和辅助文字 14px、行高 1.5；12px 仅用于非核心辅助信息。字体粗细以 400、500、600 为主。

过程概览、任务类别、步骤编号及可点击入口属于必须读懂的信息：暖色强调文字至少 14px，优先用深陶土色；链接常态保留下划线，不能只靠悬停辨认。等宽字体只用于 ID、代码和工具名等数据，不用于中文说明标签。

间距使用 4px 基础网格和上文 Token；边框 1px、图标描边、响应式宽度等不受间距网格限制。确需新增档位时统一调整 Token，避免逐页添加魔法数字。

按钮和输入框圆角 8px，面板 12px，对话框 16px；胶囊圆角仅用于短标签。输入框默认高 40px，触屏关键操作建议至少 44px。

图标统一为线性风格，尺寸使用 16、18、20、24px，描边 1.5–2px。正式功能图标不使用 Emoji。若现有依赖没有图标库，少量统一 SVG 即可；需要较多图标时再考虑 Lucide，保留许可说明，不混用多套图标。

字体加载失败不能影响布局和功能；课程演示不依赖外部字体 CDN。

## 5. 信息架构与布局

当前主导航只保留可用的“对照实验”和“单次运行”。近期历史可放在当前页面的历史区，无须为了导航完整性新增列表 API。任务详情和策略说明可以就地展开。

Agents、Datasets、Evaluations、Settings 等独立入口，只有在存在完整可用流程后再增加。禁止出现点击无反应的菜单、假数据集数量或仅写“即将上线”的整页。

对照实验桌面采用“配置区 + 结果工作区”，Trace 可在详情页、展开区域或右侧 Inspector 中展示，按实现成本选择一种。单次运行采用下方单独的宽工作区规则，不再把整套运行配置塞进窄侧栏。不要同时常驻导航栏、宽配置栏、结果区和 Inspector，挤压表格。

| 视口 | 对照实验布局规则 |
| --- | --- |
| 小于 640px | 单列；配置可折叠；保留结果、失败原因与 Trace 查看 |
| 640–1023px | 主内容优先；配置折叠或置于顶部；Inspector 不常驻 |
| 1024–1439px | 配置栏约 280–320px；结果自适应；需要时打开详情 |
| 至少 1440px | 可使用约 320px 的右侧 Inspector，但保留足够表格宽度 |

普通内容页最大宽度约 1200px，阅读说明约 760px；实验表格按可用空间展开。JSON、表格可在各自容器内横向滚动，页面整体不得因此横向溢出。

### 5.1 单次运行工作区

单次运行使用“选择任务 → 配置执行 → 运行 → 查看结果”的宽工作区，而非 280–320px 长配置侧栏。任务目录必须来自 API；ToolLab/BFCL 为紧凑套件筛选，可搜索任务卡并呈现任务目标、来源、步数上限和工具能力。切换套件时清除旧搜索并选择该套件的首个任务，避免当前选项被筛选隐藏。

默认执行区突出模型、Runtime 和主运行操作；纠错策略、MCP 传输、步数与 Token 预算集中在原生折叠的“更多设置”。MCP 控件只在 API 声明支持的任务显示；切换到不支持任务应使用本地传输。运行前摘要准确反映任务、模型、Runtime、传输及真实/模拟请求性质，不重复展示大块任务预览。

2026-10-14：右侧保持紧凑模型/Runtime/启动操作台；高级配置作为两栏下方独立整行，分工具与容错、上下文与记忆、运行预算三个组，不让展开内容拉长任务列表所在行。控件优先紧凑并排与条件显示，长说明原生details按需展开；摘要展示草稿实际限制。高级details的样式只作用直接summary，避免污染嵌套帮助。单任务工具记忆按ADR-030已提供，不把它称为跨任务知识库；其他未实现能力仍不建空入口。参考与实际测试见[配置收口](../tasks/compact-run-settings-20261014.md)。

运行结果存在时，配置区明确标为“下次运行配置”并折叠；最近历史显示来自 GET 产物的任务、模型、时间和结果，UUID 仅作为可复制详情。历史产物配置只读展示，不覆盖下次运行草稿。已有 Episode URL 的刷新和浏览器前进/后退必须回读同一产物，不得因恢复导航重复 POST。

小于 640px 单列；640–900px 以主内容优先，执行设置移至任务区下方；宽屏任务选择与执行配置并排。所有视口保持页面无整体横向溢出，支持键盘选择、可见焦点和系统减少动效偏好。

## 6. 对照实验页面

2026-10-12 课堂演示入口：三张中文场景卡复用已有跨文档任务，可选择实时单次或上下文对照。按钮仅填运行草稿，不自动POST；沿用当前工作区模型，明确重置推荐预算、LangGraph/无纠错/本地工具。对照只选同一任务，Seed1/Repeat1，共2个Episode。配置后折叠场景、打开并聚焦原配置；历史结果默认收起入口，保存模型/窗口/评分不受新草稿影响。缺场景或运行中禁用按钮，键盘与窄屏可用。保存结果说明Fake与真实小样本边界，不预设窗口优胜；CSV模型/Provider来源从保存配置读取，旧来源缺失留空。源码与实际结果见[成品交接](../learning/V0.3-classroom-product-20261012.md)。

2026-10-13 对照界面收口：配置采用全宽双列（执行设置/任务选择），长模型说明与高级预算折叠，主操作集中显示本次执行规模；已保存结果在前，下一次草稿收起在后。结果卡用每侧独立的通过/未通过环、Token总量与平均毫秒耗时条形图，详细费用/工具指标仍按需展开。历史看板概览仅单场，折线必须同comparison_key且至少2个非空样本；横轴明确等间距运行序号，最多30次，各单位分图。灰色非通过、零/全通过、无样本中性，标签和真实数字同时提供，不用百分率反推历史次数。未知费用不画成零，点/筛选/刷新只GET，SVG图和键盘原始表保留。原生SVG/CSS复用暖调语义色与焦点，无新增图表依赖。参考与验证见[看板任务卡](../tasks/experiment-dashboard-20261013.md)。

### 6.1 配置与操作

页头展示标题、运行/历史状态和一个主要操作。实验 UUID 次要展示，可复制；完整技术版本放入详情。

配置区按以下顺序组织：

1. **Agent 策略**：明确显示 Baseline 与 Recovery 两组；说明 Recovery 仅增加一次受控参数纠错。当前固定配对，无须虚构任意 Agent 创建功能。
2. **模型**：显示准确 ID、来源、真实 API / 离线模拟标识；元数据未加载完成前禁止提交。
3. **任务**：展示真实任务名称、简短说明、所选数量；可展开约束。原生任务与将来的外部数据集分开展示。
4. **高级配置**：Seed、实际预算和版本信息。当前 API 不支持修改的参数只读，不提供无效输入框。
5. **运行操作**：明确即将执行的 Episode 数量，例如“运行对照实验 · 8 次执行”；校验无任务、无模型等情况。

允许用户选择模型不代表 UI 能确认价格或实时可用性。历史验证应附验证时间或记录来源；模型名称含 `free` 不作为价格证据。模型接入规则由后端负责。

### 6.2 结果摘要

默认使用 3–5 个紧凑指标区域，至少覆盖两种策略的成功次数/总数、恢复结果、Token 代价、步骤和时延。可以把两组值放在同一区域以减少卡片数量。

示例内容结构（下面数字仅用于说明排版，不能进入生产默认数据）：

```text
任务成功       基线 0/4        恢复 4/4
恢复结果       已确认挽救 4    可恢复样本 4
Token          基线 240       恢复 720      差值 +480
平均步骤       基线 1         恢复 3
平均耗时       基线 … ms      恢复 … ms
```

结果区必须独立显示本次产物的模型、任务集、Seed、运行时间以及真实/模拟来源，不能让左侧“下次运行配置”冒充历史配置。

完整指标展开区展示工具选择准确率、参数合法率、模型/工具调用、费用已知状态与评测版本。数据尚未由后端交付时显示“未提供”，不能由前端猜测或以 0 补齐。

评分口径以经审查的后端契约为准。UI 不自行修正挽救率；已知口径存在问题的旧产物应标为旧口径结果，不宣传为经确认的恢复提升。

### 6.3 成对结果表

每行代表同一任务和 Seed 的一组实验。列包含任务、Baseline 评测结果、Recovery 评测结果、比较结论、步骤/Token、两侧 Trace 入口。

同时保留以下区别：

- 两者成功；两者失败；基线失败恢复成功；基线成功恢复失败。
- “恢复组成功”与“已确认发生参数纠错挽救”是不同事实，标签依据后端判定。
- Runtime 正常提交与 Evaluator 判定通过分别展示；不能仅凭 HTTP 201 或 `termination_reason=SUCCESS` 宣布任务通过。

表格使用文字和图标辅助状态；不要整行铺红绿背景。入口可写“基线 Trace”“恢复 Trace”，其可访问名称包含任务名，方便键盘与读屏区分。

### 6.4 数字和图表规则

- 百分比通常保留一位小数，并展示分子/分母；0 分母显示“不适用”，缺失显示“未提供”。
- Token 为整数；差值正确显示正负号，不出现 `+-120`。
- 延迟明确 ms 或 s；费用未知显示“未知 / 未核验”，不能显示为已确认的 0 元。
- Fake 的 Token 与费用标为模拟值；一次真实运行只能展示为探索性结果。
- 原生与外部基准不能合成一个无解释总分。
- 当前 4 条任务优先用表格。新增图表必须回答具体比较问题，且有表格或文字替代；不为装饰增加图表库。

## 7. 运行状态与 Trace

### 7.1 当前接口能够表达的状态

单次 Episode 已按 ADR-014 使用 `POST /api/v1/episodes/stream` 接收真实 TraceEvent 与最终产物；前端只根据已收到的事件显示步骤和工具状态。原同步结果接口仍可用。对照实验的进度来自 Job 状态与已保存的 Episode 边界，不推测正在进行的模型内部行为或工具执行细节。

请求进行中显示加载指示、已用等待时间和明确说明。单次运行在事件到达前只显示等待，事件到达后才绘制对应节点；对照实验可以展示预计 Episode 总数和当前 Job 状态，不显示接口未提供的逐题完成数。断线时标明状态未知与 Episode/Job ID，最终结果仍以保存的 Artifact 为准。

不得使用计时器轮流播放 Planning、Reasoning、Tool Calling 等未观测阶段。已实现的单次 Episode SSE 仅传现有、版本化的公开事件，不包含模型隐藏思维链；流程动画的计时器仅用于**历史回放**，不得冒充实时执行进度。新增实时传输或跨进程订阅仍须独立契约。

### 7.2 历史事件映射

| 实际 Trace 事件 | 面向用户的标签 |
| --- | --- |
| EPISODE_STARTED | 运行开始 |
| OBSERVATION_CREATED | 初始观察 |
| MODEL_REQUESTED | 请求模型 |
| MODEL_RESPONDED | 模型返回 |
| TOOL_CALL_PROPOSED | 提议工具调用 |
| TOOL_CALL_VALIDATED | 校验调用，显示通过或错误码 |
| TOOL_STARTED | 开始执行工具 |
| TOOL_SUCCEEDED / TOOL_FAILED | 工具执行成功 / 失败 |
| ENVIRONMENT_UPDATED | 环境状态更新 |
| EPISODE_FINISHED | 运行结束，显示实际终止原因 |

最终评分来自 Evaluation 产物，作为独立结果区呈现，不伪造一个不存在的 TraceEvent。

Trace 默认按事件顺序显示摘要，通过细竖线、缩进、图标和标签建立层级。展开内容展示工具名、公开参数、实际返回、校验错误、call ID、可用的用量信息与原始 JSON。事件缺少耗时则不展示推算值。

参数错误后的下一次模型请求可解释为重试，但必须依据真实事件链。不要新增虚构的“思考过程”“计划”“反思”节点，不展示或索取模型隐藏思维链。

### 7.3 Agent 身份

当前身份显示名称、策略、准确模型 ID 和运行结果。Baseline 与 Recovery 可使用固定的小图标或细标记区别，并始终保留文字名称。Agent 标识色不得与成功/失败语义混淆，也不得铺满卡片。

未来多 Agent 可视化再呈现“谁、何时、做了什么、与谁交互、结果如何”。当前不实现 AgentGraph、角色编队或协作拓扑。

### 7.4 逐次执行路径（2026-10-10 授权）

2026-10-14：资料侧栏显示当前前缀的成功阅读次数/重复次数；同document_id实际返回正文才累计，再次成功读取计重复。正在读、失败、空文档、未返回及网页预览不增加次数，环境最终快照不补历史。单卡重复时显示已成功读N次；不推断重复必为遗忘或无用，不把少调用当作评分通过，历史/实时使用同一投影。真实同窗口样本和验证见[记忆实测交接](../tasks/V0.3-memory-real-pair-20261014.md)。

2026-10-12 实时资料侧栏：ToolLab初始环境文档以卡片目录和正文预览放在执行画布旁，包含干扰项，不按私有答案筛选。工具开始读取时自动选择对应文档，节点展示实际文档ID；成功读取才计入已读，成功提交才显示实际引用，引用是否有效仍由Evaluator决定。拒绝、超时、空文档和断线不能显示取得证据。目录只在自身范围跟随，不抢焦点；观察者预览零POST、不注入模型，历史严格按当前前缀。窄屏堆叠、44px以上点击目标、独立正文滚动、减少动效保持即时状态。源码/失败与验证见[资料工作台交接](../tasks/realtime-evidence-20261012.md)。

单 Agent 的公开执行轨迹采用展开视图：每次模型请求、每次工具调用各自形成节点，同一工具的多次调用不合并。调用提议出现后才创建节点，校验/执行/返回更新对应调用；错误恢复保留失败调用并追加新调用。此处是实际执行路径，不是多 Agent 拓扑或可编辑工作流。

默认只呈现当前回放事件之前的路径，实时模式只用已到达事件。节点以中文行动名称、步骤、工具 ID、文字状态建立层次；陶土色用于当前节点，成功/失败使用现有语义 Token。连接只表示记录顺序，不推断未记录依赖或网络报文。长路径保持节点文字可读，视口跟随当前区域，提供逐次调用的键盘入口。

右侧事件卡呈现当前调用参数、已记录反馈、证据与状态变化；原始 JSON 按需展开。模型等待保持准确说明，BFCL 提议不写成函数实执行。节点进入/视口过渡短暂且可打断，减少动效时即时呈现；不得循环动画模拟进度。历史最终输出独立明确标识为保存产物。

任务交付是通用要求，不能只展示输入和结束状态。输入/输出卡明确交付要求，订单与文档任务展示实际答案和引用证据，BFCL展示已接收的函数调用与参数，并说明没有执行函数或生成计算结果。期望交付依据公开任务说明和当前评测协议，不把隐藏标准答案、初始数据或前端自行计算的值当成模型实际输出。结束节点与当前详情只取游标之前的环境快照；独立保存结果卡可以展示完整产物，但标明“已保存”。评测通过与运行终止分别显示，SUCCESS不自动等于答案正确。失败、缺字段、缺快照和断线均保留未知/未提交，不补造答案。

新发起单次任务默认展示实时执行过程：启动时仅一次转到执行区域，后续事件不反复滚动页面；节点/状态随已接收Trace即时更新，不能用定时播放伪装实时执行。收到完整产物后保持原流程与终点，显示实际输出，不重置到起点或自动播放保存轨迹。仅用户点击“查看保存详情与回放”进入历史工具；历史URL仍只GET。短暂连线动效表示事件到达，不延迟处理、不模拟推理时间，断线/完成/减少动效时停止。历史回读、Resume与Experiment尚无本切片新的实时订阅能力。

## 8. 历史回读与状态恢复

- 保留 `?experiment_id=...` 和 `?episode_id=...`；刷新、复制链接和返回操作读取原产物，不重新 POST。
- 页面明确区分“当前查看的历史结果”和“下一次运行的草稿配置”。选择恢复历史配置时，模型、任务、场景、Seed 必须一致，且元数据异步返回不得覆盖它们。
- 不依赖 localStorage 才能打开链接；近期历史只是快捷入口，JSON 产物是结果依据。
- 历史模型已不在目录时仍可展示原结果；重新运行前说明模型不可选，不静默换成默认模型。
- 缺失历史字段显示“旧产物未记录”；不把当前默认值当作历史事实。
- URL 与页面内容必须一致；浏览器前进/后退应同步当前产物，不重复添加相同历史记录。
- 读取失败时保留明确错误与 ID，不继续把旧结果显示成新请求的结果。

## 9. 组件与交互规范

| 组件 | 要求 |
| --- | --- |
| Primary Button | 每个操作区一个主操作，文本说明动作；提交期间防止重复提交 |
| Secondary / Ghost | 次要操作、返回、展开与关闭；可用状态明确 |
| Danger Button | 仅限真实破坏性行为；后端不支持终止时不显示“终止运行” |
| Input / Select | 持续可见的 Label、错误文本和必要帮助，不只用 Placeholder |
| Panel / Card | 只用于真实信息分组，优先用分隔与留白减少嵌套 |
| StatusBadge | 文字加图标或颜色；不只靠颜色 |
| Metric | 数值、单位、范围和缺失状态一致 |
| Trace 展开 | 原生 details/summary 或带 aria-expanded 的 button，可用键盘操作 |
| Inspector / Dialog | 只在需要时增加；可关闭，管理焦点，Esc 返回，关闭后恢复触发点焦点 |
| Copy | 成功后显示短反馈，失败给出手动复制路径 |

所有交互组件覆盖默认、Hover、Focus、Disabled、Loading、Error 状态。禁用按钮需要让用户知道原因，例如“请先选择任务”。

空状态给出上下文和下一步：“尚未运行实验。选择模型和任务后开始对照。”数据加载失败与没有数据不能共用同一空状态。

请求超时或连接中断只代表前端没有拿到结果，不代表后端已停止。提示用户先检查可用历史记录，避免自动重发 POST 造成额外调用；不要把“关闭页面”描述为“取消运行”。

错误信息说明已知发生了什么、哪个请求或任务受影响、可采取的下一步。只显示后端提供的安全信息；若只收到 `provider_error`，写“模型请求失败，未获得更具体原因”，不得编造 429、退役原因或重试倒计时。

## 10. 可访问性与动效

- 保留语义化标题、表格表头、表单 Label、按钮名称；图标按钮有可访问名称，装饰图标对读屏隐藏。
- Tab 顺序符合视觉顺序；所有操作可用键盘完成；展开内容不会困住焦点。
- 使用清晰的 `:focus-visible` 轮廓，例如 2px 实线加 2px offset。不要直接移除浏览器焦点；高对比模式下保留系统可见性。
- 重要错误使用合适的提示区域，运行状态可用 `aria-live="polite"`，避免整条 Trace 持续播报。
- 在 200% 缩放下保留主要内容和操作；必要长表格可局部滚动。
- 动画主要使用 120/180/240ms 的颜色、透明度和展开过渡，通常不超过 300ms。
- 尊重 `prefers-reduced-motion`，减少非必要位移、脉冲和闪烁。
- 状态动画必须表达已知状态，不模拟执行进度。禁止持续渐变、随机闪光和装饰性弹跳。

### 10.1 连续过渡规则

| 交互 | 过渡方式 | 保持可核查的内容 |
| --- | --- | --- |
| 对照实验 / 单次运行、过程故事 / 技术 Trace 切换 | 选中标记沿同一轨道移动；内容淡入并轻移，不让整页跳动 | 当前模式和可用操作始终有文字标识；切换技术 Trace 不丢失已保存事件。 |
| 任务、模型与 Runtime 选择 | 已选卡片的边框、背景及摘要在 120–180ms 内响应；选择指示位置连续变化 | 名称、来源、模型 ID、不可用原因仍可直接阅读；选中态不只靠颜色。 |
| 高级设置与任务详情展开 | 面板高度随内容平滑变化，周围内容顺势移动；关闭后焦点回到触发控件 | 表单值不因展开/关闭而重置；键盘与读屏状态同步。 |
| 配置 → 等待 → 结果 | 运行前摘要保留上下文，已记录的 Trace 节点随事件出现；完成后在同一工作区切到可回放产物 | 事件到达前只显示等待，不伪造阶段或完成比例；断线提示状态未知，历史结果明确区别于下次运行草稿。 |
| Replay 步骤与 Inspector | 当前步骤标记沿步骤轨道移动，详情同步更新；失败步骤可直接定位 | Replay 只读；状态、工具结果和评分来自已保存事件及 Evaluation，不凭动画补造证据。 |

动效分三级：Hover/按压 120ms；选择和内容切换 180ms；面板展开及共享元素过渡 240ms，通常不超过 300ms。位移以 4–8px 的短距离为起点；不要让整个页面滑走。用户快速连续操作时，过渡应被新操作接管，不等待上一段动画结束。新内容出现后保持稳定，不循环漂浮或脉冲。上述数值是设计起点，最终以浏览器实测的响应速度、可读性和性能调整。

`prefers-reduced-motion: reduce` 时取消非必要的位置和缩放过渡，可保留简短的颜色/透明度反馈；错误、成功、选中与焦点必须有非动效的可见表达。遵循 [W3C 对交互动效的指导](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)。

实施先复用现有 CSS Token、`transition` 和语义 HTML。只有“卡片展开到详情”“选中标记跨组件移动”等实际需要共享布局时，才评估 [Motion 的 layout/layoutId](https://motion.dev/docs/react-layout-animations)；新增依赖前用一个真实页面原型验证手感与包体影响。原生 View Transitions 可用于简单视图更换，但不能把截图式过渡当作高频 Replay 的默认方案。动画层不修改 URL 回读、表单状态、Trace 或 API 契约。

继续使用现有 React、TypeScript、Vite。默认通过 CSS Token、原生表单、语义 HTML 和少量实际复用的 React 组件完成；不因本文引入全套组件框架、图表框架或多层组件继承。

建议按需要提取 Button、StatusBadge、Metric、ExperimentSummary、PairTable、TraceViewer。只有复用或明显可读性收益时拆分文件；不预建 PromptComposer、ReasoningNode、AgentGraph。

组件负责呈现与交互。策略判定、预算、评分、免费模型准入都由后端决定；前端不得通过硬编码生成通过率或偷偷放宽限制。API Key 不进入浏览器、截图、示例 JSON 或前端构建。

后续视觉更新按以下顺序推进；V0.1 已验收的基础主题与功能无需重做：

1. 先以现有单次运行与 Replay 做可交互原型，验证第 10.1 节的选择、展开和步骤联动。
2. 在不改变 API 与评分契约的前提下，调整配置的信息层级和 Replay 阅读方式；保留技术 Trace。
3. 将通过原型验证的过渡扩展到对照实验、历史回读和错误/空/加载状态。
4. 检查响应式、键盘操作、减少动效、URL 回读和现有功能回归。

每一步均交付可运行的完整页面，避免留下只有视觉壳而按钮无效的中间结果。

## 14. 相对原稿的调整记录

| 原稿内容 | 本版调整及原因 |
| --- | --- |
| 产品名 Agent Arena | 统一为现有 AgentLabyrinth，避免品牌和工程实体分裂 |
| 所有能力均为 Active | 区分现有页面、后续可选能力和本次文档交付范围 |
| 固定三栏、多项独立导航 | 首版采用配置与结果工作区；仅提供真实可用入口 |
| Planning / Reasoning 等状态及 Trace | 单次 Episode 按 ADR-014 的已到达事件展示，未到达前只显示等待；禁止虚构思考过程 |
| Agent 执行禁止只用 Spinner | 允许加载指示配准确说明与等待时间；单次事件流到达后呈现真实 Trace |
| 至少实现一整套专用组件 | 按实际复用拆分，不创建未来功能空组件 |
| 陶土橙按钮与浅辅助文字 | 保留主色，增加更深的按钮和状态文字色，补充对比度验证 |
| 禁止默认蓝色焦点 | 品牌焦点可替换，但必须保留可见焦点和系统高对比支持 |
| 默认 Dark Mode、外部字体与图标库 | 深色模式后置，字体有本地回退，图标按实际需求选择 |
| 绝对视觉优先级与严格像素禁令 | 按用户阶段调整信息顺序，允许必要的布局与可访问性例外 |
| 通用 Result 与 Metric 展示 | 增加配对实验、评分口径、历史配置、来源及未知值规则 |

设计取舍顺序：先判断信息是否必要，再复用现有组件，然后尝试留白、字体、边框和少量语义色；装饰排在最后。

## 15. V0.2 兼容历史看板补充（2026-09-30）

2026-10-01 课程固化复验：历史导航发起时清空对应旧结果并更新 URL，读取失败不残留旧通过率/动画；保留迟到响应防护。辅助色统一加深为 `#625F59`，任务类别/说明/限制至少 14px，流程工具 ID 与保留的开源署名至少 12px。实际页面前景/背景扫描覆盖单次、对照、失败与技术视图，最低抽样 4.69:1；不称为全量 WCAG 认证。真实浏览器 200%、Windows 系统减少动画仍未在本机通过；交接和截图见 `docs/handoffs/V0.2-course-demo-20261001.md`。

2026-10-01 接续优化：历史看板默认折叠；配置组附 Seed/重复/短键以减少近似名称混淆。历史读取与实际执行使用不同按钮文案。总时限配置显示为每次运行秒数，结果展示保存值，历史未配置不填默认值。流程回放提供浏览器全屏专注查看，桌面并排保留输入/最终输出，画布按实际容器适配；窄屏顺序堆叠并允许纵向滚动。技术记录可选展开，动画不新增未记录的网络事实。代表性实测及未完成的 UI 全矩阵见 current-state 顶部。

按 ADR-018，原生下拉选择兼容配置组；没有完整来源的历史记录照常打开，不加入趋势。趋势仅展示最近两次的成功率百分点、Token与耗时差值，明确非显著性结论。实际网关费用和原厂参考成本分开，缺失字段用“未记录”，无适用样本时不用0/0制造转化率。
