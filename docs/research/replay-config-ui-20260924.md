# AgentLabyrinth Replay 与运行配置界面调研

日期：2026-09-24。性质：设计调研与实施建议，尚未改动产品 UI。依据需求 V0.6、现有 [UI 规范](../product/ui-design-guidelines.md) 与两张用户截图；实施前以需求和 ADR 为准。

## 看到的问题

- 当前 BFCL 单步运行有 10 个事件，页面逐条铺成同样大的卡片。用户要在「模型请求、模型返回、提议、校验、执行、成功、状态更新」之间自行拼出一次行动。多步 ToolLab 可达 24 个事件，阅读成本继续上升。
- 单次运行配置是 6–7 个纵向表单控件。模型、任务、Runtime 和传输方式在视觉上同等重要，任务内容与运行后会发生什么不突出。真正重要的「这次会测什么、会调用哪个模型和工具」没有一处完整预览。
- 截图中 Token 预算控件明显比其他输入框扁。源码里的 `#single-token-budget` 缺少其余表单输入采用的 `form-input` class；这是具体样式缺口，下一轮可直接修正。
- 当前 Trace 的事件级 `duration_ms` 基本为 0，只有最终事件带 Episode 总耗时。现有数据不能画准确的模型/工具耗时瀑布图；事件时间戳可作为顺序依据，不应被包装成精确阶段耗时。

## 推荐方案：双层 Replay

### 默认「过程故事」

页头先给出任务与结论：任务名、模型、Runtime/传输、Evaluator 通过与否、工具调用数、Token。下面是紧凑的可点击步骤轨道，不按原始事件数铺卡片：

```text
任务：读取退货政策并提交状态                         评测通过
观察任务  →  ① 搜索文档 ✓  →  ② 读取 DOC-007 ✓  →  ③ 提交答案 ✓
                          ↑ 当前选中
模型决定：调用 read_document(document_id="DOC-007")
工具反馈：返回文档内容，获得证据 document:DOC-007
状态变化：证据集合 [] → [document:DOC-007]
```

每张步骤卡只展示 **模型选择的工具、参数摘要、校验/执行结果、获得的证据或状态变化**。点击步骤时，同步更新右侧/下方 Inspector：输入、工具参数与结果、状态前后、错误代码。成功/失败由真实事件和 Evaluation 决定；不推测隐藏思维链。回放播放键默认按步骤前进；键盘左右方向与按钮都可操作。旧 Trace 缺少中间快照时标注「此步骤无状态快照」，不凭最终状态倒推。

### 次级「技术 Trace」

保留现有逐事件列表、过滤器、原始 JSON 与导出，放在一个显式的「技术 Trace」页签。事件必须仍可按 `call_id` 穿透；参数错误恢复、未知/禁止工具、MCP 断线等失败路径默认定位到失败步骤，并展示前因和终止事件。Replay 只读，不再次调用模型或工具。

**不先做真实时间瀑布图。** 当前只有 Episode 总耗时和事件时间戳，阶段耗时没有可靠区间。需要瀑布图时，先为模型调用、工具调用记录真正的 start/end 或 span duration，再做比例时间轴。短 Episode 的第一版使用等宽步骤轨道，表示顺序，不暗示耗时。

## 配置区推荐：实验发射台

保留现有暖色研究风格，改变信息组织与交互，不靠大面积装饰。顶端用「这次实验」摘要和一个主操作；主体只需三块：

1. **选任务**：数据集分段选择；下面用任务卡展示任务目标、类别、预期工具、步数边界和来源。BFCL 清楚标「改编子集，非官方分数」。选择任务后再决定是否展示 MCP 传输。
2. **选 Agent 执行**：模型用可选卡片展示名称、Fake/真实、最近目录状态；Runtime 用二选一分段控件，恢复策略用带一句解释的开关/二选一。MCP 只在支持的文档任务显示，并提示「独立本地服务」。
3. **运行前核对**：一句可读摘要，例如「用 MiniMax M2.7 + LangGraph，经 MCP 在文档任务 007 运行 1 次，最多 6 步」。旁边显示 API 可见性、预计调用性质和配置缺失项。运行按钮始终明确任务范围。

`max_steps`、Token 预算、版本/Seed 等收进「高级设置」折叠区。默认值应准确显示且可展开修改。历史结果页的左侧配置标题写「下次运行」，已保存产物配置用结果区只读展示；切换历史 Episode 不覆盖用户草稿。

```text
┌ 这次实验 ────────────────────────────── [运行一次评测] ┐
│ 任务：BFCL / ToolLab          模型：MiniMax / Fake    │
│ 任务卡：目标 + 来源 + 预期工具                         │
│ 执行：Reference | LangGraph     传输：本地 | MCP       │
│ 高级设置 ▸ 步数、Token、Seed、恢复策略                │
│ 运行前核对：……                                        │
└───────────────────────────────────────────────────────┘
```

这不是拖拽 Agent Builder。平台当前只提供固定任务、两个 Runtime 和少量策略；自由连线会暗示用户能编辑工作流，也容易让 UI 成为虚假的 Agent 编排器。卡片和摘要让配置有选择感，同时保持真实契约。

## 落地顺序与验收

1. 先做前端纯派生的 `groupTraceByStep`，以 `step_index`、事件顺序与 `call_id` 组织步骤。先覆盖单步 BFCL、多步文档任务、参数错误恢复、MCP 断线、历史缺少快照。不要改 Trace Schema/评测口径。
2. 在现有结果区加入「过程故事 / 技术 Trace」切换和联动 Inspector。默认过程故事；旧事件列表完整保留。课程演示在 30 秒内应能指出：模型选了什么工具、参数是否有效、工具返回了什么、状态如何变化、最终为何通过/失败。
3. 重排单次运行配置。先沿用现有 HTML 控件和 CSS Token，不为卡片效果增加图表库。检查小屏、键盘焦点、读屏标签、任务切换时 MCP 是否禁用、真实模型目录不可用时 Fake 是否仍可运行。
4. 用已保存 Artifact 的只读 URL 回归：BFCL `4716ca38-5f67-4f6d-8239-a5488541826b`、MCP `c302b854-5a35-4ec7-b1b5-749b417e59e0`，再用一条失败/恢复样本。刷新、前后播放和导出不得发起 POST。

本建议属于 UI 表达层。若后来要画真正的时延瀑布、跨 Agent DAG 或实时进度，先补相应的可验证运行数据与需求决定。

### 当前页面的具体问题

- 数据集下拉、任务下拉、任务预览卡连续重复同一选择；窄栏内英文任务说明折行，挤走真正的运行操作。
- `01/02/03` 看起来像三步向导，但三个区域始终全部展开；数字增加了分隔感，没有减少同时出现的选择。
- 模型、Runtime、纠错策略、预算具有相同的表单权重；首次演示用户还未理解任务，就被要求理解 Runtime 内部机制。
- 「运行前核对」完整重复已选任务、模型和 Runtime；最近历史用五个裸 UUID 继续拉长侧栏。截图中运行按钮在很深的位置。
- 运行完成后，下一次运行草稿仍占据纵向主视线，与历史结果争夺注意力。

### 建议采用的单次运行工作区

**运行前：宽工作区而非长侧栏。** 主区用可搜索的任务列表/卡片选择任务，`ToolLab / BFCL` 作为紧凑筛选；右侧或上方小配置区只保留「模型」「Runtime」和一个清楚的运行按钮。选中任务后显示一行目标摘要与来源，详细描述按需展开。不要再同时展示数据集下拉、任务下拉和完整预览卡。

**次级设置：一层折叠。** 纠错策略、MCP 传输、步数和 Token 预算集中在「更多设置」，折叠标题直接提示已偏离默认值的数量/关键值。具体选项仅在任务支持时出现；折叠时仍保存用户选择。运行前仅用一行摘要核对，例如「BFCL 任务 1 · MiniMax · LangGraph · 本地工具」，不要再造一张重复的大卡。

**运行后：结果占满工作区。** 顶部保留一条可展开的「下次运行」摘要，结果、评分和 Replay 获得页面宽度。最近历史移到独立的历史区域，显示任务名、模型、时间和结果，UUID 作为可复制详情；历史产物配置与下次运行草稿继续分离。

```text
运行前：  [ToolLab | BFCL]  搜索任务        模型 [选择]  Runtime [选择]
         ┌ 任务列表/任务说明（宽区） ┐     更多设置 ▸
         └ 选中的任务与来源 ─────────┘     [运行一次评测]

运行后：  [下次运行：任务 · 模型 · Runtime] [修改配置]
         ┌ 评分结果与关键指标 ────────────────────────────────┐
         └ Replay / 技术 Trace ───────────────────────────────┘
```

该建议已于 2026-09-28 落地为单次运行工作区，不新增 API、自由 Agent Builder 或假任务。工具/API 返回的真实任务用于可搜索卡片和 ToolLab/BFCL 筛选；模型、Runtime 与运行操作集中呈现，纠错/MCP/预算按需折叠；MCP 控件按任务能力显隐。历史存在时将配置作为“下次运行配置”折叠，历史条目显示读取到的任务、模型、时间和评测结果，草稿不被历史产物覆盖。代码与样式见 `apps/web/src/App.tsx`、`apps/web/src/index.css`，规范已同步至 `docs/product/ui-design-guidelines.md`。

### 实施验收（2026-09-28）

- 真实本机 API + Web 的 Fake `order-status-007` 成功：Episode `fa71b63d-83ce-42cc-8183-07be14285771`，刷新 GET 回读相同产物与 24 个事件。Fake `order-status-001` 配置 `invalid-then-success` + `handwritten_recovery` 成功：Episode `659eecb4-b712-4aa1-a42a-9b627990e667`，GET 回读 3 次模型调用、2 次工具调用与 21 个事件。
- 浏览器验证 MCP 只对支持的 ToolLab 任务出现；选择 MCP 后摘要反映 HTTP 传输，切换到不支持任务后控件消失、配置回本地。切换 BFCL 清空先前搜索，键盘 Space 可切换套件并选中 `bfcl-simple_python_0`，卡片显示 development、最多 1 步和本地工具。
- 390、768、1280、1440 CSS px 下没有整体横向溢出（`scrollWidth` 分别等于 `clientWidth`：375、753、1265、1425）；200% 等效 195px 视口没有横向溢出；`prefers-reduced-motion: reduce` 生效。截图：`artifacts/ui-check/single-workspace-{390,768,1280,1440}.png`。
- 带 Episode URL 的刷新、前进与后退回到同一产物；已执行的 Fake 浏览器刷新走 GET，无重复 POST。生产构建通过，Replay 4/4、流程帧 3/3、项目质量门禁通过（169 passed，1 条既有依赖弃用警告）。本轮未发起真实模型请求。

仍需 Codex 做交互/视觉复核，重点是小视口首屏滚动、历史摘要加载/失败呈现、键盘焦点路径和历史草稿隔离；以上浏览器验收不等于 V0.2 整版验收。
