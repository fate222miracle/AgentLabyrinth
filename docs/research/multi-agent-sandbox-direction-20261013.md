## 独立Agent模型与真实可视化

- 每个Agent独立id、role/capability、局部观察、权限工具、目标/收益、会话历史、记忆、预算、策略状态。可共享同一个底层LLM但会话隔离；角色提示本身不等于独立神经网络训练或可信权限隔离。
- 小人是上述对象的可视化映射。位置、任务、资源和状态来自环境已执行动作；气泡显示已生成的公开消息/行动摘要，不显示隐藏思维链。计划与实际动作区分。
- LLM选择高层任务、通信与协商；路径细步/移动插值/动画由确定性环境执行，不每帧调用模型。模拟世界tick与真实HTTP时延分开，不能靠播放速度制造优化组更快。
- 两世界独立实例，但同初始世界/任务/角色/模型/可见信息/资源/总预算；仅候选策略不同。结果可能持平或退化，画面不得硬编码获胜。

## 建议首场景：信息不对称的协同配送

示例3角色：侦察员掌握部分道路/障碍，搬运员有不同载重与拾取权限，配送员掌握交付时限和签收需求。有限搬运/路线/物资资源，各角色必须通过合法通信与Handoff结合信息。共同目标是按规则完成配送。

任务包括角色互补、路径资源争用、已领取任务防重复、信息改变后的协调；不能把已知答案发给协调器或为基线故意设置笨动作。全知规则规划器如使用，只作明确标注的上界；单Agent对照需要定义等价观测与工具范围。

第一阶段共同目标下争用资源是协作调度冲突，并不自动构成利益冲突博弈。后续同类世界可定义主体独立收益、私有成本、资源交换/出价/接受拒绝等规则，加入竞争与混合动机。各方收益和协议是否执行由环境状态计算，不以聊天宣称/模型裁判替代；公平和社会福利须定义具体量，不能把所有多方交易概括为单一正确率/Elo或宣称纳什均衡。

若后续希望更贴计算机网络，可另评估带宽/算力资源协商场景，复用同类角色观察、资源约束、通信与收益定义；不把仿真网络状态说成真实网络控制。

## 第一候选问题：通信预算约束下的协作调度

问题：在局部信息和有限通信/推理预算下，事件触发、定向通信能否相较固定轮询/全员广播，减少无关消息与Token，并保持或提升完成任务的能力？

候选机制分别为：根据公开任务/工具事件触发需要响应的Agent；依据角色能力与当前公开子目标定向传递信息。相关性/收益判定只能用允许观察和实际反馈，不能偷看其他Agent私有状态、评分标准或全知最优解。初步规则/启发式是可验证基线，是否有新颖方法贡献需进一步对照论文，不把接入路由器/增加角色当创新。

| 消融条件 | 调度 | 通信 |
| --- | --- | --- |
| A | 固定轮询 | 全员广播 |
| B | 固定轮询 | 定向消息 |
| C | 事件触发 | 全员广播 |
| D | 事件触发 | 定向消息 |

未来开题演示可以展示A/D，正式评估用A/B/C/D拆开两个因素；两侧相同Agent集合、基础模型、环境规则和团队总预算，不给多Agent每人一份基线总预算后宣称公平。统计全部调用（含协调器/路由/反思）、消息数量/Token、模拟完成时间、真实耗时、重复工作、协议冲突与失败。多Agent未必提高成功率，也可能主要节约通信；两种结果均如实记录。

## 技术深度与平台工作

| 技术问题 | 必须形成的实现与可验证边界 |
| --- | --- |
| 共享环境一致性 | 世界状态机、合法动作、角色权限、资源所有权、统一动作提交；失败动作不改状态 |
| 调度 | Agent readiness、回合/事件推进、停止与死循环检测、团队与个体预算、API限流 |
| 通信 | 发信身份、收件人/频道权限、消息ID/关联、投递顺序/重复去重、因果Trace，非单纯共享所有对话 |
| 联合恢复 | 保存全部Agent会话/共享世界/消息队列/资源与预算的一致安全点；在途模型请求重发与模拟写操作幂等区分 |
| 评测与展示 | 合作任务完成与成本、竞争个体收益/总体福利/公平、消息链和资源轨迹；各Agent视角与观察者视角明确分开 |

这些才是简历深度。当前单进程实现不称分布式系统；数据库/队列/容器等是否引入由实际一致性、隔离和索引需要决定，不为技术名词创建空底座。现有Runtime/Tool Executor/Trace/预算/恢复可复用，但单AgentCheckpoint不能直接称支持多Agent联合恢复。

## 论文与阅读顺序

1. [Why Do Multi-Agent LLM Systems Fail?／MAST，2025](https://arxiv.org/abs/2503.13657v3)：系统设计、Agent间失配、任务验证三类失败；先用它建立实际失败观察清单，不把自动标签当已证明原因。
2. [NegotiationArena，2024](https://arxiv.org/abs/2402.05863)：多轮资源分配/交易/价格谈判，学习场景、角色私有信息和收益定义。
3. [GovSim／Cooperate or Collapse，2024](https://arxiv.org/abs/2404.16698)：共享资源利用与可持续合作，学习通信消融与合作-个体利益关系。
4. [Multi-Agent Collaboration via Evolving Orchestration，2025](https://arxiv.org/abs/2505.19591v2)：随任务状态动态安排Agent，而非固定组织结构。原方法训练RL协调器，当前规则/启发式候选不是论文完整复现，不能借用其收益数字。

先理解场景/失败/指标，再对照调度方法；可以与实现和源码阅读并行，不要求负责人先读完全部论文。使用外部代码/数据时锁版本、核对许可并走Adapter/manifest，不复制受限任务或宣称官方协议成绩。

## 交付顺序建议

1. 定义一个3-Agent短场景、独立观察与合法动作、团队预算和确定性评分，先验证真实协作需求。
2. 完成可运行的固定协作基线、实时小人/消息/资源展示与联合Trace；展示前区分Fake与真实模型。
3. 从实际失败或冗余通信提出候选策略，完成A/B/C/D实验、失败测试与实际结果解释，再做双世界对照展示。
4. 框架验证后做真正成品入口和持久化/恢复，不止交测试脚本；再评估私有收益的竞争/谈判模式及独立测试场景。

未来研究演示先控制Agent数、世界长度和决策次数，真实免费网关调用可能慢，不以模型并行等同模拟世界并行；明确实时与保存回放。求职侧描述已实现调度/通信/状态机制和明确基线的收益；开题侧再检验方法新颖性、跨场景/模型泛化与机制消融。

暂定研究题目可为《通信预算约束下多Agent协作调度与合作竞争行为评测》。这是候选方向，不是已经证实创新点或通过开题。

判断：少量Agent的二维实时仿真技术上可行，已有原型和评测环境证明路线不是空想；但是“多个小人+角色提示+对照界面”已有先例，不能据此宣称研究创新。需要从实际失败提出通信预算、局部信息、异构伙伴适应或合作竞争机制中的一个具体问题，再对照相关方法与公平预算验证。已有Trace/SSE、Runtime Port和工具校验可复用；世界模型、多个独立观察、联合调度/恢复和行为指标仍是新工作，当前代码并不已支持。

### 首选候选：通信预算下的任务依赖感知协调与恢复

具体问题：局部观察、延迟或过期消息条件下，有限团队预算应花在通知、确认、重新获取事实还是重规划上？怎样避免关键Handoff遗漏，同时减少无关广播和全队重规划？

候选机制可围绕公开可观察的任务依赖与已完成承诺，给消息/恢复行动估计优先级；分别选择发送对象、必要确认、替代信息路径与局部重规划。先定义优化目标、可观察输入和正确基线，再考虑规则或小策略模型；普通时间戳/重发/去重/字段校验是工程基线，二维小人是呈现，均不自动算方法创新。新方法必须对照MASBench/RCR/SyncPlan/通信保护等相关工作，明确其额外处理条件和实验差异，不能只加不同场景皮肤。

最小可执行场景建议仍为3角色协同配送：侦察员有局部道路信息、搬运员有载重资源、配送员有签收要求。角色有独立观察/会话/权限，任务因信息和能力互补确实需要协作；世界事件可引入道路关闭、订单变化和可控通信延迟。环境统一裁决合法行动，小人只显示真正提交的行动；不让协调器读取评分私有目标、其他Agent不允许的观察或全知最优解。

共同目标下的资源争用是协作，不直接宣称利益博弈。先完成协作研究，再单独引入私有收益/交易和公平等明确规则，避免开题同时覆盖协作/竞争/均衡/人机伙伴。

实验至少对照：合理固定协调/广播、消息选择基线、固定保护/重规划、候选自适应机制；独立消融消息选择、证据校验、恢复选择，不能只比较“什么都没有”和复杂候选。相同团队总预算计入协调/路由/记忆整理/验证所有模型用量，分别报告通信消息/字节、总推理Token、模拟完成时间与真实API耗时。保留成功/任务进展、资源冲突/等待、重复工作、错误信息接受、故障恢复的权衡。先无故障和多种可控故障，再任务/地图/伙伴/模型留出验证；规模由费用和功效分析决定，不默认批量免费网关真实运行。

这是有参考文献和落地路线的候选，不是已证实新颖的问题。若相关工作已覆盖同机制，需要收窄到明确的新约束、提出更有区别的方法，或承认是工程复现；先复现/测失败，再与导师选择最终研究问题。

### 两条备选与现有平台关系

- 长序列共享计划与承诺一致：收到“已经完成”消息后如何验证实际依赖，变化时如何仅修受影响子计划？参考CooperBench/SyncPlan；比直接训练大模型可行，但显式承诺和局部修复本身已有相关工作。
- 伙伴适应：面对不同速度/能力/策略或不完全可靠伙伴，如何在线调整分工与通信？可进一步读[CollabBench，2026-06](https://arxiv.org/abs/2606.05793)，其重点含现实人类伙伴与协作游戏，不等同纯LLM多Agent场景。变量更多，优先级低于前述窄问题。

已实现Trace/SSE/预算/工具校验、单Episode工具记忆和安全点是可复用底座，不等于已有多Agent共享记忆、联合安全点或团队调度。未来增加共享世界、合法角色动作、独立观察、消息队列和任务依赖追踪属于实质新工作，须按需求阶段/ADR授权；当前继续V0.3范围，本轮不修改产品代码、协议或GitHub。

推荐下一阅读顺序：MASBench（机制/消融）→SyncPlan（同步/计划失效）→When Messages Go Wrong（故障与已有保护）→AgentWorld（长链任务/过程指标）；Evolving Orchestration作为可训练调度参考，MAST用于失败分类。

## 2026-10-14 负责人进一步选择AgentWorld作为候选研究载体

最新意图：优先借鉴AgentWorld的世界、角色与任务，在该环境中研究改进策略，结合其他论文提出idea。前文自建配送场景降为备选，不继续把它当负责人已选载体；仍是未来开题规划，非当前提前实现多Agent的授权。

已进一步核对[AgentWorld作者仓库](https://github.com/openagents-org/agentworld)、[自定义Agent指南](https://github.com/openagents-org/agentworld/blob/develop/docs/benchmark/custom-agents.md)、[评分说明](https://github.com/openagents-org/agentworld/blob/develop/docs/benchmark/scoring.md)和[服务说明](https://github.com/openagents-org/agentworld/blob/develop/docs/benchmark/server.md)。现有TypeScript世界/浏览器客户端与Python参考Runner独立运行，支持OpenAI兼容模型和自定义Python Agent；可以先接外部环境与策略，避免重复写游戏引擎。未下载、安装或启动，不能宣称已兼容本机模型或已复现。

建议分两条明确结果来源的路径：研究优先保留AgentWorld固定任务/角色/工具/世界/评分，替换可披露的Agent策略；产品可以将动作/观察/消息转换到本平台Trace和实时展示，但需后续ADR定义多Agent事件/预算/恢复，不能冒充已有支持。若另做借鉴式本地任务或修改世界/预算/工具，应作为独立改编实验，不标官方完整成绩。

论文基线是固定round-robin，每个Agent每次一行动、等待动作完成才轮到下一个；游戏实时并不等于评测Agent并发。黑箱禁止取得其他Agent私有观察、内部状态和行动历史，只能通过环境消息协作。研究前固定该协议，不把异步并发、全局协调器或自动绕过chat的共享记忆混入新方法造成信息/预算优势；若研究协议本身则单列实验条件。

首个方法候选收窄为“长序列协作中的证据约束团队记忆与依赖触发协调”：仅从本角色合法观察/工具返回及实际收到的伙伴消息维护任务承诺和依赖，区分伙伴声称完成、本人观察确认、信息过期/受阻；根据受影响依赖选择必要通知/确认和局部计划修正。Source/call引用说明来源，不自动证明消息内容真实；不得为核验读取隐藏世界真值或Evaluator私有目标。候选强调怎样选择、更新、失效、验证与预算权衡，常规状态字段或组合Memory/Router/Planner本身不算新颖性。

参考MASBench的机制消融、RCR的角色/预算信息选择、SyncPlan的同步与过期计划修复，各选适用机制；训练方法不等于无需训练的推理期实现。先原基线→单项改进→联合候选，兼顾较强结构消息/固定保护基线，逐项去除记忆证据、依赖触发/局部纠错做消融，保留相同观察权限/角色/模型/轮数与团队预算。原任务作为主评测；额外延迟/失效扰动标为独立压力实验，不混入原协议得分。

可先以原3角色制作链核对交接与重复行为（论文Task01的采集/木工/法师），之后冻结跨采集、制作、运输或协同战斗的开发/留出任务清单，不能只在单题上调提示。需要检查实际Task verifier是否覆盖文字目标；作者评分说明明确当前verifier不能单凭可执行就认为完全等价论文。CCE是LLM Judge事后关系判断，不能从完整轨迹生成在线决策图；固定Judge/提示、保留抽样核验，主要报告任务完成与成本，PSR当前上游未有可验证的可移植实现。仓库任务数量与论文报告有差异，正式比较需锁commit和manifest。

这是可落地的候选路线，尚未确认独立新颖性。下一研究动作：对照相关方法定义信息边界，复现小任务基线并分类真实失败，选择一个方法差异与导师讨论；新模块、外部服务与真实批量执行另走授权/ADR，不提交GitHub。
